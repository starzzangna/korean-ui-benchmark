# 모바일 탐색과 배경 경계 보완

[B와 비교](../polish/index.html) · [직전 개선본](../flow/index.html) · [검사 기록](../reports/polish-7/README.md)

이전 결과와 SaaS를 보존한 후속 개선이다. 스킬만 달리한 독립 생성 실험과 구분한다.

| 개선 대상 | 적용 |
|---|---|
| 행사 중간 색 띠 | 자식 margin이 바깥으로 합쳐져 body색이 드러나던 경계를 부모 padding으로 관리. 구간의 실제 계산된 배경/좌표와 위·아래 간격을 검사 |
| 움직이는 신청 색면 | 배경 section 대신 내부 설명/폼 묶음을 진입 대상으로 선택. 외부 구간과 신청 배경의 이동은 없음 |
| 브랜드 모바일 길이 | 같은 값을 가진 히어로 분류 버튼 제거. 네이티브 필터·검색·초기화 유지. 중복 상세 버튼을 줄이고 이미지 버튼으로 상세·관심 행동을 구분 |
| 로컬 카드 높이 | 모바일 그림/제목/설명을 병치하고 가격/선택을 한 행 중심으로 구성. 작은 폭/확대에서는 자연스럽게 줄바꿈 |
| 포트폴리오 소개 | 대표 작업 선정 이유를 이미지 캡션으로 옮겨 작품을 앞당김. 큰 작품·전체/세부·확대·분야 선택 유지 |
| 행사 모바일 GNB | 행사에 맞는 작은 마스트헤드를 명시해 공통 로고 크기 규칙의 덮어쓰기를 해소. 모든 폭에서 한 줄을 강제하지 않음 |
| 전문 서비스 | 예시 탐색과 제공 범위 확인의 제목 구분. 기존 결과 예시 강조 유지 |
| 진입 시점 | 관측 면의 아래 여백을4%에서1%로 조정해 늦은 도착을 줄임. 거리16px/시간780ms는 유지 |

SaaS·식당 사진·기존 긍정적인 구성은 유지한다. 사진과 작품을 교체하지 않았으며 가상 데이터·로컬 데모 범위도 동일하다. 폼은 실제로 전송하지 않는다.

## 다음 판단 기준

1. 첫 CTA가 빨라지는 것과 신청/목록 전체 길이가 줄어드는 것을 별도 측정한다. 설명은 실제 선택 근거만 남긴다.
2. 배색은 새 색을 더하기 전에 경계의 부모/자식 배경과 여백을 확인한다. 둥근 모서리 바깥과 모션 중 드러나는 면도 검토한다.
3. 움직임은 읽는 묶음으로 선택하되 큰 구간의 색면과 입력 초점은 안정적으로 둔다. 반복 효과의 수를 품질로 삼지 않는다.
4. 대표 사진/작품의 매력과 실제 방문·구매·의뢰 판단 자료는 구분한다. 데모 자산을 실제 성과처럼 표현하지 않는다.

## 실행과 검증

`node scripts/build-polish.mjs` → `node scripts/serve.mjs --port=4331` → `/polish/index.html`.

`QA_VARIANT=polish`로 `scripts/qa.mjs`, `scripts/branches.mjs`를 실행한다. 추가 검사는 `scripts/polish-checks.mjs`, `scripts/polish-motion-checks.mjs`, `scripts/polish-boundary-checks.mjs`다. PowerShell에서는 `$env:QA_VARIANT='polish'`를 사용한다. 서버 주소는 `BASE_URL`, 설치 Chrome은 `CHROME_PATH`로 지정한다.

B/새 개선본·직전/새 개선본·3종 비교를 제공한다. 함께 이동은 해당 구간, 동시 스크롤은 문서 상대 진행률을 맞춘다. 모달/확대 이미지 내부는 독립 조작이다. 이번 결과는 로컬이며 원격 업로드/배포는 하지 않았다.
