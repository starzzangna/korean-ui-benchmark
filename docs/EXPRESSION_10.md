# 내용별 결과 표현·작품 감상·참여 관심

[B와 비교](../expression/index.html) · [직전 비교](../relevance/index.html) · [검사 기록](../reports/expression-10/README.md)

전문 서비스·포트폴리오·행사3개만 수정했다. SaaS·브랜드·로컬·식당4개는 직전 HTML과 실행 자원이 동일하며 이전 비교본은 해시로 보존한다. 같은 작성자의 후속 편집이므로 최초 생성 성능의 통제 실험과 구분한다.

## 표현의 선택

| 대상 | 선택한 표현 | 보존한 내용/행동 |
|---|---|---|
| 브랜드 진단 | 큰 메시지 문장 | 가상 예시 표시·제공 범위·문의 동기화 |
| 웹 서비스 기획 | 번호가 있는4단계 화면 흐름 | 서비스 고르기→준비 자료→연락처→문의 확인의 순서 |
| 콘텐츠 정리 | 먼저/이어서/마지막의 읽기 구조 | 소개→범위→문의라는 설명용 구조. 제공 결과물 목록은 별도 유지 |
| 작품 대표 | 이미지 프레임에만 라운드, 이미지 밖 짧은 매체/작업명 | 실제 원본·안전 크롭·전체/세부/확대·초점 복귀 |
| 행사 관심 | 방문자의 관심 문구를 먼저, 실제 프로그램명을 근거로 연결 | e1/e5의 실제 날짜·세션 열림·키보드 초점 |

자료가 문장/순서/구조인 차이를 같은 인용문 카드로 압축하지 않았다. 서비스별 결과는 모두 설명용 가상 예시이며 실제 고객 성과나 납품 결과가 아니다. 프로그램의 참여 효과/혜택을 새로 약속하지 않았다.

## 모션의 선택

메시지 변경은240ms 페이드, 흐름은320ms의 작은 가로 이동, 구조는300ms의 작은 정착을 선택했다. 값·문의 선택은 즉시 바뀐다. 선택 중 남은 부모 진입은 정리하고 빠른 재선택/감소 설정을 유지한다.

대표 작품은12px/880ms·높은 시작 불투명도, 작업 항목은10px/700ms, 서비스 선택은6px/420ms, 서비스 결과 진입은8px/520ms, 행사 대표는14px/800ms, 프로그램은6px/560ms, 문의는8px/560ms를 사용한다. 이번 자료의 감상/선택/목록 역할로 정한 값이며 업종별 정답이나 품질 점수가 아니다. 배경은 유지하고 읽는 묶음만 도착한다.

## 에셋과 사실성

새 사진/외부 라이브러리를 추가하지 않았다. NEST/RAY/FIELD의 제공 SVG와 이전 재료 그래픽을 사용한다. 대표의 설명은 다음 작업 항목에서 읽을 수 있다. 서비스 전후 예시·읽기 구조는 제공 범위를 설명하는 데모다. 행사 관심 문구는 e1의 재료 이력 탐색과 e5의 종이를 접고 엮는 설명에서 편집했다.

## 실행과 검증

`node scripts/build-expression.mjs` → `node scripts/serve.mjs --port=4331` → `/expression/index.html`.

`QA_VARIANT=expression`으로 `scripts/qa.mjs`, `scripts/branches.mjs`를 실행한다. PowerShell에서는 `$env:QA_VARIANT='expression'`을 사용한다. 추가 검사는 `scripts/expression-checks.mjs`, `scripts/expression-motion-checks.mjs`, `scripts/expression-flow-checks.mjs`, `scripts/expression-evidence-checks.mjs`, `scripts/expression-role-checks.mjs`다. 서버는 `BASE_URL`, Chrome은 `CHROME_PATH`로 지정한다.

결과3종 각각의 실제 DOM/값·200% 확대, 짧은 캡션/이미지 행동, 관심 문구→정확한 양일 세션, 역할별 진입과 상태 전환·감소 설정을 확인한다. 함께 이동/동시 스크롤과 모달 내부 독립 조작을 유지한다. 실제 전송/예약 없는 로컬 데모이며 GitHub Pages에는 배포하지 않았다.
