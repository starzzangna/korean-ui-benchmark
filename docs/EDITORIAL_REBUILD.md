# 공통 기능과 별도 레이아웃으로 다시 제작한 28개 시안

## 제작 범위

SaaS·브랜드·로컬 서비스·식당·포트폴리오·전문 서비스·행사의 no skill / A / B / 자체 스킬을 다시 구성했다. 한 작성자가 전체를 제작했다. 기존 완성 히어로·페이지 본문·조건별 CSS를 새 시안의 기본 템플릿으로 호출하지 않는다. 이전 결과는 [직전 비교본](../archive/before-editorial-rebuild/index.html)에서 확인한다.

공통 입력은 [요구 기능](COMMON_BRIEF.md)과 `shared/data.json`의 사실·항목·가격·일정·선택값이다. 사진·개념 작품·Pretendard·아이콘 자원도 같은 풀을 제공했다. 자료 부족을 가짜 후기·성과·주소·개별 메뉴 사진으로 채우지 않았다. 에셋을 추가 제작해 성능을 비교하는 과제가 아니라 같은 자료로 지침에 따라 편집하는 과제다.

## 공통 코드의 경계

- `src/app.js`: 필터·관심 목록·업무 상태·선택/금액·오류/확인·모달·작품 탐색의 상태 처리.
- `src/saas-ui.js`: 탐색 메뉴/상태 선택 연결·모바일 메뉴·Escape.
- `src/editions/parts.mjs`: 입력/선택·버튼·이미지·탐색·동적 결과의 기능 계약. 폼은 공통 필수값을 가지며 연락처 순서와 외부 배치는 조건별로 선택한다.
- `src/editions/functional.css`: 컨트롤과 대화상자·키보드/접근성·동적 내용의 기본 표시. 페이지의 히어로/구간 격자를 정의하지 않는다.
- `src/editions/none.mjs`·`a.mjs`·`b.mjs`·`own.mjs`: 각 7개 카테고리의 별도 페이지 구조. 같은 폴더의 네 CSS 파일에서 각 구조의 구도·조판·밀도·반응형을 정의한다.

새 렌더러는 이전 `category-scenes.mjs`·`saas-layout.mjs`를 호출하지 않는다. 네 군의 main DOM에서 텍스트·색·클래스를 제외한 트리도 대조한다. 구조가 다르다는 검사는 편집 선택의 분리를 확인할 뿐 디자인 우위를 의미하지 않는다.

## 조건과 적용 범위

| 군 | 적용 |
|---|---|
| no skill | 같은 기능 요구를 일반적인 탐색·사진 소개·목록·신청 구조로 완결. 일부러 결함이나 부족한 기능을 넣지 않음 |
| A | 고정 리비전의 대상/자료 우선·명료한 조판·사진 또는 타이포 장면과 원본 모션 자원. 업무 앱에는 앱 과업이 우선 |
| B | 고정 리비전의 한국어 조판·면/위계·사진 장면·깊이·부드러운 등장/조작 반응. CSS/기능을 인라인한 HTML과 허용된 CDN 사용 |
| 자체 | 보강한 스킬의 과업/정체성 브리프·자료 적합성·실제 판단 순서·한국어 편집·대표/다음 구간 연결·정렬/확대/상황별 모션 |

원본 출처와 고정 리비전은 [출처](SOURCES.md), 실제 입력 파일의 해시는 [입력 기록](input-provenance.json)에 있다. A의 모든 moment/finish gate, B의 모든 장식·가상 신뢰 요소를 무수정 적용한 인증이 아니다. 제공 사실·공통 자원·무료 로컬 데모 요구가 우선한다. 원본 지침이 권하는 별도 서체 대신 사용자 요청에 따라 전체에 Pretendard를 쓴다.

## 실제 구성 선택

| 카테고리 | no skill | A | B | 자체 |
|---|---|---|---|---|
| SaaS | 제목→3개 상태 카드→목록 | 상태를 왼쪽 세로 축에 둔 작업 콘솔 | 목록/상태 사이드 패널을 나눈 대시보드 | 흰 탐색·보라 강조, 상태 안내/3카드와 검색을 통합한 업무 면 |
| 브랜드 | 사진/소개 병치→3개 상품 카드 | 큰 상품 이미지와 쓰임/가격이 이어지는 상품 편집 | 사진 프레임/소개→둥근 3열 상품 | 대표 장면 옆 품목 색인→상품 전체/설명/가격을 비교하는 행 |
| 로컬 | 넓은 과정 사진→수업 카드 | 사진 다음 제목/설명→수업 색인 | 아치 사진/소개→독립 신청 카드 | 과정 사진/소개→명확히 구분한 기법·결과물·가격 행→일정 확인 |
| 식당 | 사진 소개→2열 메뉴 | 넓은 음식 크롭 아래 소개→메뉴 인덱스 | 사진 위 소개/행동→메뉴→예약 카드 | 식사 소개·메뉴 예고와 참고 상차림→의미 아이콘/가격 축→따뜻한 예약 구간 |
| 포트폴리오 | 짧은 소개→3열 작업 카드 | 큰 대표 작품→연속하는 큰 작업 | 어두운 소개와 주/보조 작품→프레임형 작업 | 대표 작품과 분야 색인→크기를 맞춘 작품/설명 행→문의 |
| 전문 서비스 | 소개→서비스 선택/패널 | 타이포 선언→서비스 범위/결과 | 소개와 편집 문서→서비스/문의 | 의뢰 상황별 서비스 색인→선택한 범위/산출물→문의 내용 정리 |
| 행사 | 소개/날짜 안내→전체 폭 일정 | 타이포 포스터/큰 날짜→프로그램 | 어두운 포스터 장면→옆 날짜 탐색 | 행사 식별/일시→조밀한 일정 축→패스 비교/신청 |

이 선택을 다음 사이트의 업종 기본값으로 재사용하지 않는다. 자체 SaaS의 흰 메뉴·보라색 선호는 이 프로젝트에만 적용되는 기존 사용자 조건이며 모든 SaaS의 기본색이 아니다.

## 자체 군의 제작 브리프와 자료 한계

- 브랜드: 기록 도구를 고르는 사람이 사용 분위기에서 노트·달력·연필의 쓰임과 가격으로 이동한다. 책상 사진은 참고이며 상품 그림은 개념 자료다.
- 로컬: 처음 배우는 사람이 기법과 만들 물건을 비교하고 일정/금액을 확인한다. 과정 사진 한 장을 서로 다른 수업의 실제 기록처럼 주장하지 않는다.
- 식당: 아침 식사를 고르는 사람이 분위기를 보고 메뉴 설명/가격을 비교한다. 참고 상차림을 개별 메뉴 실물로 연결하지 않는다. 음식별 차이를 사진으로 비교하려면 실제 메뉴 원본이 더 필요하다.
- 포트폴리오: 의뢰인이 대표 작업을 보고 매체별 해석과 전체/세부를 탐색한다. 작품은 가상 콘셉트이며 실적/고객 정보를 추가하지 않는다.
- 전문 서비스: 의뢰인이 메시지·사용자 과업·읽는 순서 중 정리할 일을 골라 범위를 판단한다. 산출물은 제공 범위의 개념 안내이며 실제 납품 사례가 아니다.
- 행사: 참여자가 행사 성격·일시를 확인하고 날짜별 내용을 펼쳐 패스를 고른다. 장소/발표자/현장 사진을 만들지 않는다.
- SaaS: 팀원이 업무명·상태·담당·기한으로 비교하고 상태를 바꾼다. 진행 요약·다가오는 업무·감성 히어로는 추가하지 않는다.

## 검사와 해석

[최신 검증](../reports/editorial-2/README.md)은 기본 기능/오류 복구·모든 필수 선택값·5개 폭·두 방식의 200% 글자 확대·카드/아이콘/컨트롤 정렬·회전 아이콘·transform 상태/복귀·모션 감소·직전 비교본 실행을 구분해 기록한다. 정지 화면과 라이브 조작을 함께 본다.

한 작성자의 이전 대화 맥락은 남아 있다. 구성 분리·기능 통과·변형 관찰을 독립 생성이나 스킬의 인과 효과·미적 우위로 바꾸어 설명하지 않는다. 실제 사용자 선호는 동일한 PC/모바일 조건에서 별도로 비교해야 한다.
