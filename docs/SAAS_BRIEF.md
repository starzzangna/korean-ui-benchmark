# SaaS 4종 비교: 공통 기능과 자유로운 표현

## 네 군에 같은 요구

태스크링이라는 한국어 팀 업무 앱을 만든다. `shared/data.json`의 업무 4개·담당자·상태·기한과 제공된 문구를 동일하게 사용한다. 업무명/담당 검색과 상태 필터, 상세 상태 수정, 필수값 검증 후 새 업무 추가, 빈 결과/복구, 모달 닫기/초점 복귀를 제공한다. 실제 팀·계정·서버로 전송하지 않는다.

PC에는 좌측 워크스페이스 탐색과 대기·진행·완료별 건수를 확인하고 선택할 수 있는 영역이 필요하다. 상태 영역의 위치·카드 여부·크기·배색은 지정하지 않는다. 상태 숫자는 전체 업무 기준이며 수정·추가 시 갱신한다. 검색 결과와 현재 필터를 구분한다. 진행 요약 문장·다가오는 업무·가상 실적·홍보 히어로는 추가하지 않는다.

Pretendard·같은 데이터·공통 SVG 아이콘·동일 기능 엔진을 사용한다. 모바일에서는 탐색을 접거나 재배치하고 상태 영역·긴 업무명·날짜를 읽을 수 있게 만든다. 320/390/768/1024/1440px, 글자·행간 200%, 키보드·모션 감소를 같은 기준으로 검사한다.

## 각 군에 추가하는 조건

| 군 | 입력 | 공통으로 고정하지 않는 것 |
|---|---|---|
| no skill | 위 업무 브리프와 공통 자원만. 별도 디자인 스킬을 지정하지 않음 | 배색·배치·간격·조판·모서리·모션 |
| A | 같은 브리프와 고정한 외부 스킬 A 지침/원본 모션 자원 | 스킬이 선택한 표현을 다른 군의 정답으로 강제하지 않음 |
| B | 같은 브리프와 고정한 외부 스킬 B 지침. 앱 목적에 맞게 적용 | 랜딩페이지의 장식·후기·가상 수치를 업무 앱에 강제하지 않음 |
| 자체 스킬 | 같은 브리프와 자체 SKILL/카테고리 MD. 흰 메뉴·보라색·상단 카드형을 선호한다는 사용자 피드백 반영 | 해당 선호를 no skill/A/B의 공통 제약으로 전파하지 않음 |

입력 명세: [no skill](saas-inputs/none.md) · [A](saas-inputs/a.md) · [B](saas-inputs/b.md) · [자체](saas-inputs/own.md). 원본 입력의 출처·리비전은 [출처](SOURCES.md)와 `input-provenance.json`에 기록했다.

## 이번 구현과 해석 범위

네 군의 업무 레이아웃도 [최신 재제작](EDITORIAL_REBUILD.md)에 포함했다. `src/editions/none.mjs`·`a.mjs`·`b.mjs`·`own.mjs`에서 각각 작성하며 기존 공통 SaaS 구성 함수를 호출하지 않는다. 상태/필터/추가/오류/모달은 같은 기능 엔진을 사용한다.

상태 카드와 메뉴 연결·편집/추가 뒤 집계·모바일 키보드·확대 검사는 `npm run test:saas`, 전체 기능 검사는 `npm test`로 실행한다. 최신 결과는 [검증 기록](../reports/editorial-2/README.md)에 있다. 같은 작성자의 지침 적용 사례이며 독립 생성·미적 우위의 증명이 아니다.

[직전 28개 비교본](../archive/before-editorial-rebuild/index.html)은 원본 실행 자원과 보존했다.
