# 목적별 상단·색면 개선본

[B와 비교](../purpose/index.html) · [직전 비교](../atmosphere/index.html)

SaaS는 HTML과 실행 자원을 그대로 유지했다. 나머지6개는 같은 작성자의 후속 개선이며 독립 생성 실험이 아니다. 비교군 B와 모든 이전 결과는 보존 기준의 SHA-256으로 대조한다.

| 카테고리 | 선택한 관계 | 현재 자료에서의 이유 |
|---|---|---|
| 브랜드 | 상품 탐색형2행 GNB, 대표와 본문 같은 종이 바탕 | 상품 사용 사진과 카탈로그가 하나의 가게로 읽히도록 연결. 색 띠 대신 간격·제목·경계로 구분 |
| 로컬 | 중앙 매장명/수업 탐색, 소재 면에서 밝은 비교 면 | 매장 분위기와 수업 선택의 역할 구분. 예약은 새로운 녹색 면 대신 비교 면에 이어짐 |
| 식당 | 사진과 연결된 어두운 GNB, 전면 사진 | 안전 영역이 부족한 사진에 메뉴를 겹치지 않음. 모바일은 밝은 사진 감상 구간과 읽기 구간을 분리 |
| 포트폴리오 | 작은 마스트헤드, 같은 중립 바탕 | 작품과 의뢰 탐색을 유지하면서 반복된 부제로 감상 높이를 쓰지 않음 |
| 전문 서비스 | 독립된 진한 탐색 띠, 결과 예시가 주인공 | 반복 탐색의 안정성과 가상 문장/흐름 전후 예시의 초점 구분 |
| 행사 | 작은 영문 행사 표기와 포스터형 대표 | 행사명 연속 중복을 줄이고 날짜/참가 행동과 대표 그래픽을 함께 편집 |

레이아웃을 다르게 만드는 것이 목표가 아니다. 메뉴 행동은 공유하되 헤더 구조·줄 수·바탕 흐름까지 모든 업종에 고정하는 구현을 이번 개선본에서 분리했다. 모든 사이트에 다른 색 띠를 추가하지 않았다.

입장 모션은 각 사이트의 대표 자료 묶음 하나로 좁히고, 기존 필터·가격·작품 탐색·날짜·서비스 결과의 즉시 피드백과 모션 감소를 유지했다. 서비스 문장과 그림은 설명용 가상 자료이며 실제 성과나 납품 사례가 아니다. 사진은 기존 출처의 분위기 참고 자료다.

## 실행과 확인

`node scripts/build-purpose.mjs` 후 `node scripts/serve.mjs --port=4331`로 열고 `/purpose/index.html`에서 비교한다. B/새 개선본, 직전/새 개선본,3종 보기를 제공한다. 함께 이동은 각 화면의 해당 구간으로, 동시 스크롤은 전체 문서의 상대 진행률로 이동한다. 다른 레이아웃의 동일한 문장을 맞추는 기능은 아니다. 대화상자와 이미지 확대 내부는 독립 조작이다.

검사: `QA_VARIANT=purpose`로 `scripts/qa.mjs`와 `scripts/branches.mjs`, 추가 검사는 `scripts/purpose-checks.mjs`. Windows PowerShell에서는 `$env:QA_VARIANT='purpose'`를 설정한다. Chrome 경로는 `CHROME_PATH`, 실행 서버는 `BASE_URL`로 지정한다. 검사 기록과 실제 제한은 [검사 보고서](../reports/purpose-5/README.md)를 본다.

기존4종/직전 비교본과 스킬 스냅샷을 수정하지 않았다. 이번 결과는 로컬이며 원격 업로드·배포는 수행하지 않았다.
