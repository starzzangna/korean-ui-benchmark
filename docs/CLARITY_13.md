# 근거·모바일 대표 작품·중복 소개 개선

[비교 화면](../clarity/index.html) · [검사 기록](../reports/clarity-13/README.md)

## 변경 범위

Compact12를 보존한 별도 후속 개선이다. 전문 서비스·포트폴리오·행사만 변경하며 SaaS·브랜드·로컬·식당은 직전 HTML과 바이트 동일하다. 공통 사실/데이터와 필수 선택값·양식·모달 동작을 유지한다. B는 기존 비교 원본을 그대로 사용한다.

## 전문 서비스

축소한 PC 구성과 소개/선택의 같은 배경을 유지한다. 제목을 모르는 방문자가 관심 주제부터 책을 고르는 서점이라는 가정을 기본 화면에 명시한다. 펼침에는 서비스별 설계 판단을 연결한다. 브랜드는 소개 문장, 기획은 주제→비교→저장→재탐색 순서, 콘텐츠는 화면별 정보 역할을 설명한다. 실제 조사/납품/성과를 주장하지 않는다.

서비스를 바꾸면 결과·가정·판단 이유·실제 제공 결과물·문의 값이 함께 바뀐다. 열린 맥락과 키보드 초점을 유지하고 판단 이유도 상태별 공간 측정에 포함한다. 기본 패널은477px로 유지되어1440×768과1280×800에서 전체가 첫 화면에 들어온다. 확대나 맥락 펼침 상태까지 한 화면에 압축하는 기준은 적용하지 않는다.

## 포트폴리오

모바일 첫 대표를 단독 배치하고 RAY는 짧은 보조 항목으로 편집했다. NEST는 같은1600×1040 원본에서 주제 탐색의 핵심 부분을 크롭했다. 새 viewBox는380/210/1140/710이며 제목 전체와 네 도서를 포함한다.390px에서 대표 표시 폭은350px로, 원본46px 제목이 약14px로 표시된다. 이는 핵심 제목의 식별 기준이고 모든 작은 본문이 읽힌다는 의미는 아니다.

모달의 전체/세부는 기존 동일 버전 원본을 사용한다. 확대·이동·이전/다음·오류 재시도·Escape/초점 복귀를 유지한다. 보조 작품의 선택도 남겼다. 모바일 문서 길이는3508→3646px로138px 늘었다. 단독 대표의 식별을 우선한 선택이며, 다음 개선에서는 RAY/FIELD의 자료 완성도와 중단 작업 단위의 응집력을 검토할 수 있다.

크롭은 `src/clarity/assets/manifest.json`에 출처·원본 SHA-256·범위·용도·허구 여부를 기록했다. 가상 서점/도서 콘셉트이며 실제 고객 작업이 아니다.

## 행사

소개에는 만드는 사람과 쓰는 사람이라는 참여 맥락을 남기고, 반복 프로그램명 대신 '재료의 이력 읽기'/'종이 접고 엮기' 활동 버튼을 사용한다. 실제 프로그램명은 전체 일정과 버튼의 접근 가능한 이름에 남는다. 각 활동은 정확한 날짜 선택→세션 열림→summary 초점으로 이어진다. 장소/연사/성과 등 제공되지 않은 사실을 추가하지 않는다.

소개와 일정의 역할을 나누고 활동 버튼의 높이/간격을 줄여390px 모바일은2732→2635px로97px 짧아졌다. B2546px보다는89px 길며 기능과 정보 관계를 포함해 판단해야 한다. 날짜 버튼·신청 면을 무조건 더 압축하지 않았다.

## 스킬과 카테고리 MD

스킬 본문에 가정/판단/사실의 구분, 최소 예약 공간을 정하기 전 긴 변형의 조판 검토, PC 실제 높이 확인을 반영했다. 전문 서비스 MD에는 조건→선택→결과와 열린 판단 근거 동기화를, 포트폴리오 MD에는 실제 모바일 표시 크기·단독 대표/보조 관계·같은 버전 크롭과 확대를, 행사 MD에는 소개/일정의 정보 역할과 실제 날짜/세션 행동 보존을 추가했다. 에셋 요청서와 DESIGN 템플릿에도 대조 항목을 연결했다. 특정 구도·색상·수치를 모든 프로젝트에 강제하지 않는다.

## 모션과 검증

콘텐츠 묶음 진입은 기존 역할별 모션을 유지한다. 서비스 변경은 즉시 값을 갱신하고 메시지 opacity240ms/흐름 x6px320ms/구조 y4px300ms로 구분한다. 빠른 재선택·초점 진입에서 이전 효과를 취소하며 모션 감소 설정에서 효과를 생략한다. 활동 버튼의 포인터 화살표는220ms·3px로 짧게 이동하고 돌아온다. 모달과 비교 프레임 이동은 독립적으로 유지한다.

기능101·정렬/확대/비교 이동80·전환 안정성/모달 자료11·표현/선택/모션12·묶음 진입12·근거/크롭/행사/첫 화면8: 총224건을 확인한다. 기본320/390/768/1024/1440px, 글자만200%와 글자/행간200%, 열린 맥락·키보드·오류 복구·모션 감소를 포함한다. 실기기/브라우저 메뉴 확대와 종합 접근성 인증은 별도다.

## 실행

```sh
node scripts/serve.mjs --port=4331
node scripts/build-clarity.mjs
node scripts/check.mjs
```

브라우저 검사에는 `BASE_URL=http://127.0.0.1:4331`, `QA_VARIANT=clarity`, 로컬 Chrome의 `CHROME_PATH`를 설정한다. PowerShell 예시는 `$env:QA_VARIANT='clarity'`다.

```sh
node scripts/qa.mjs
node scripts/clarity-checks.mjs
node scripts/clarity-stability-checks.mjs
node scripts/clarity-role-checks.mjs
node scripts/clarity-motion-checks.mjs
node scripts/clarity-content-checks.mjs
```

기능 실행 직후 `artifacts/qa.json`을 `reports/clarity-13/browser-checks.json`으로 복사한다. 현재 단계의 결과를 확인한 후 `node scripts/report-clarity.mjs`로 보존/자료 동일성과 보고서를 생성한다.

같은 작성자의 후속 개선이며 독립 최초 생성 실험이나 스킬만의 효과를 증명하지 않는다. 작품 자료와 편집도 함께 변경했다. 실제 전송/예약/계정 연동이 없는 로컬 데모이며 GitHub Pages에는 배포하지 않았다.
