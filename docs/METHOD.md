# 비교 방법과 해석 범위

## 공통 조건

7개 카테고리의 사실·기능 요구·콘텐츠·사진/가상 상품/작품 자료를 동일하게 제공했다. [공통 과제](COMMON_BRIEF.md)와 `shared/data.json`이 요구 계약이다. 과거 비교 결과와 코드를 가져오지 않고 새 브랜드·데이터·상품/작품 자료·구성을 작성했다. 글꼴은 공통으로 제공하되 원본 지침의 추가 실행 의존성도 허용했다.

요청에 따라 한 작성자가 전체를 구현했다. 공통 기능 엔진으로 입력 검증·상태 변경·모달·확대·초점/복구 계약을 고정하고, 각 군의 DOM 배치·색·조판·프레임·모션을 분리했다. 단순한 색상 변경만으로 군을 나누지 않았다. 조건별 빌드는 `src/render.mjs`와 네 스타일 파일에서 확인할 수 있다.

## 입력과 실제 적용

SaaS 후속 재비교에서는 사용자가 선택한 흰 좌측 메뉴·보라색 강조·상단 상태 카드 3개의 구조를 네 군 모두에 적용했다. 같은 의미 구조와 기능 엔진을 공유하고 각 군의 간격·조판·경계·표면·조작 반응을 다시 작성했다. [SaaS 조건](SAAS_BRIEF.md)이 우선하며, 이 사례는 자유 구성의 최초 생성 실험이나 원본 전체 실행 인증이 아니다. [이전 SaaS](../archive/saas-before-status-cards/index.html)는 당시 스타일·기능 파일과 함께 보존했다.

| 조건 | 실제 적용 | 이 비교에서 인증하지 않는 것 |
|---|---|---|
| no skill | 기본 탐색/폼/목록 구성, 일반적인 hover | 스킬을 전혀 모르는 독립 작성자의 순수 기준선 |
| A | 새로 고정한 원본 지침의 구체적 제목·자료 우선·명료한 위계, 원본 모션 CSS/JS와 hero 진입 규약 | 전체 패키지의 자동 배정/모든 장면·moment·finish gate 및 전체 규칙 통과 |
| B | 한국어 타이포·채움 CTA·비대칭 사진/작품·구간 등장, 단일 HTML에 CSS/공통 기능 인라인, 원본이 쓰는 CDN | 원본의 모든 섹션 규칙을 그대로 복제하거나 모든 실행 도구 통과 |
| 자체 | 최신 자체 스킬의 카테고리·자료/행동 관계·첫 화면·간격·그룹/컨트롤 정렬·조건별 모션 | 모든 작성자/과제에서의 일반적 우위 |

외부 두 스킬의 자료와 도구를 사용할 수 있게 했지만, 모든 도구를 실행한 원본 패키지 전체 인증 비교는 아니다. 동일 기능 과제에 맞춰 적용한 시안 비교다. 전체 원본 무수정 실행 효과를 평가하려면 별도 실험이 필요하다.

## 출처 고정

A/B 원본 입력은 공개 리비전과 읽기/사용 파일의 SHA-256을 `input-provenance.json`에 기록했다. 원본 지침을 공개 저장소에 전부 재배포하지 않는다. A의 실제 사용 모션 모듈은 원문/라이선스를 보존했다. 자체 스킬은 이 저장소에 포함한 스냅샷이 입력이다.

B는 Tailwind·Motion·추가 글꼴의 외부 로드를 허용한다. 다른 군은 공통 로컬 자료를 주로 사용한다. 외부 네트워크와 패키지 자체의 환경 차이를 결과의 일부로 보되, 이 비교는 네트워크 속도를 디자인 점수로 삼지 않는다. 외부 CDN이 변경되거나 차단되는 경우 실행 조건이 달라질 수 있다.

## 검증

동일한 Playwright 검사로 주요 흐름·빈 결과·오류 복구·선택지·실제 상태 변경·모달 초점/닫기·작품 확대·전송 없음 등을 검사한다. 기본 화면은320/390/768/1024/1440px, 글자만200%와 글자/행간200%는390/768px에서 확인한다. 확대 검사는 대표 상세/확인 상태를 연 뒤 수행한다. 포인터 반응·모션 감소·터치를 별도로 관찰한다. 동일한 요구 계약을 모든 군에 적용하며 실패 수정은 군의 종류에 따라 차별하지 않는다.

자동 계측과 기능 성공은 광학적 정렬·읽는 호흡·개별 취향·실기기 접근성 인증과 다르다. 정지 화면 캡처는 모션 감소 조건을 사용하고, 실제 브라우저 비교는 기기 설정에 따른 정상 모션을 보여준다.

## 한계

동일 작성자, 공통 엔진, 공유 템플릿/자료, 조건을 차례로 읽은 맥락, 편집 선택의 영향을 분리하지 못한다. 반복 표본·무작위 순서·독립 평가자·블라인드 선호 조사를 수행하지 않았다. 시간/토큰/검사 수를 생성 조건별 동일하게 통제하지 않았다. A/B 표기는 브랜드 이름의 선입견을 줄이는 표시일 뿐, 소스 문서가 공개된 상태이므로 완전한 눈가림이 아니다.

따라서 “스킬만으로 더 좋아졌다”, “항상 우세하다”는 인과/일반화 결론을 내리지 않는다. 이 결과는 같은 사실과 동작을 가진 네 접근을 실제 화면에서 비교하는 한 사례다.
