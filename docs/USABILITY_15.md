# 식당 구성 복원과 SaaS 도구/목록 간격

[공개 비교](../index.html) · [검사 기록](../reports/usability-15/README.md)

## 변경

자체 식당은 업로드 직전 Clarity13에서 유지하던 사진 위 GNB/소개·메뉴별 선형 아이콘·따뜻한 메뉴/예약 면을 복원했다. 기존 생성기의 단순한 전면 사진과 공통 메뉴 행으로 대체하면서 승인된 관계가 사라졌던 부분을 바로잡았다. `build-renewal.mjs`가 보존된 `results/clarity/restaurant/index.html`을 사용해 복원하고, 중첩 경로의 자원과 공통 기능 엔진 경로만 맞춘다. 다음 빌드에서도 복원 상태가 유지된다. 새4종의 자체 식당은 완전히 새 구도라는 의미가 아니라 승인안 복원이다.

SaaS는 기본 상태에서 결과 개수/초기화 줄을 숨기지만 도구 자체의 아래 간격이 없어 표 헤더/업무 행과 붙었다. 새4종 모두 툴바가 직접20px의 아래 간격을 소유하게 했다. 결과 줄이 보일 때는 줄의 내부 정렬과 다음 목록과의16px 간격을 따로 둔다. 기본/필터/빈 결과/초기화에서 경계가 유지되며 검색·상태·집계 동작은 바꾸지 않는다.

## 처음 제작할 때의 방지 기준

스킬과 SaaS/식당 MD, 컨트롤 정렬 가이드에 보조 줄의 표시와 무관한 구간 간격과 승인된 구도 관계를 기록했다. 간격 검사는 CSS 선언 존재가 아닌 마지막 컨트롤/툴바 bottom과 첫 가시 표 헤더·업무 행·빈 결과 top의 차이로 확인한다. 모바일에서 표 헤더가 사라지는 경우도 포함한다.

`npm run test:usability`는4종×5개 기본 폭과390/768px 글자·행간200%에서 기본→필터→빈 결과→초기화의4상태를 확인한다. 복원한 식당의 GNB/사진·4개 메뉴 아이콘·필터와 예약 요소도 검사한다. CI에도 같은 명령을 추가해 후속 수정에서 간격이 다시 사라지면 실패하도록 한다. `test:renewal`의 기본 화면 대조에도 SaaS 경계 검사를 넣었다.

## 보존

수정 전4종 SaaS와 자체 식당은 같은 깊이의 `results/renewal-before-fixes/`에 복사했고 변경 전 스타일을 별도 동결했다. [수정 전 자체 식당](../results/renewal-before-fixes/own/restaurant/index.html) · [수정 전 자체 SaaS](../results/renewal-before-fixes/own/saas/index.html). 과거 다른 결과와 사진·데이터는 바꾸지 않는다. 현재 페이지와 기록된 이전 검사 결과는 시점이 다르며 이번 수정 검사는 별도 보고서에 둔다.

## 실행

```sh
npm run build
npm run check
npm run test:usability
```

추가 의존성이나 외부 전송은 없다. CSS 글자 확대·데스크톱 브라우저 에뮬레이션으로 검증하며 실제 기기/브라우저 메뉴 확대는 별도다. 이번 수정도 GitHub Pages에 반영한다.
