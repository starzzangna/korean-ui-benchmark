# 결과 위계·작품의 새 정보·행사 참여 근거

[B와 비교](../relevance/index.html) · [직전 비교](../editorial/index.html) · [검사 기록](../reports/relevance-9/README.md)

전문 서비스·포트폴리오·행사3개를 편집했다. SaaS·브랜드·로컬·식당4개는 직전 HTML/실행 자원과 동일하다. 기존 비교본은 실행 파일/자료 해시로 보존한다. 같은 작성자의 후속 개선으로, 스킬의 최초 생성 효과와 구분한다.

| 판단 | 채택한 관계 | 보존/확인 |
|---|---|---|
| 전문 서비스 | 핵심 결과→결과물→문의가 먼저. 요청/서비스 설명은 네이티브 펼침에서 읽음 |3개 서비스·결과물은 기본 노출. 맥락을 열어도 선택 변경과 값/열림 상태를 유지. 가상 예시 표시 |
| 포트폴리오 | 첫 화면의 전체 구도→목록의 탐색 세부→모달의 전체/세부/확대 | 실제 제공된 두 파일을 구분. 모바일 주 작업의 비중/크롭을 늘리고 짧은 매체 캡션으로 연결 |
| 행사 | 프로그램 개수 강조 대신 실제 토크/워크숍의 주제·방법으로 참여 판단 | 제공된 e1/e5 제목·설명만 사용. 누르면 해당 날짜/정확한 세션을 열고 summary에 초점 |
| 모션 | 상태 변경 때 남은 부모 진입을 취소하고 결과만 연결 | 실제 값은 즉시 반영. 빠른 키보드 선택·감소 설정에서 중첩 이동/투명도 누적 방지 |

## 에셋의 역할

- NEST 대표: 기존 `nest.svg`의 전체 웹 콘셉트. 좁은 폭에서는 주 작업의 비중과 실제 크롭을 조정한다.
- NEST 다음 정보: 기존 `nest-detail.svg`의 질문→짧은 소개→저장→서가 복귀 흐름. 전체 이미지의 대형 반복을 대신한다. 제공 원본에 있는 내용이며 가짜 세부를 생성하지 않았다.
- RAY: 기존 전체 편집 이미지로 매체 범위를 보조한다. 상세/확대는 같은 작업에 연결된다.
- 서비스: 제공 범위는 공통 데이터의3개 결과물이다. 전후 문장/흐름은 설명용 가상 예시이며 고객 성과가 아니다.
- 행사: 제공된 프로그램 제목·설명·날짜를 편집 근거로 사용한다. 새로운 참여 효과/혜택을 약속하지 않는다. 키비주얼은 이전 자체 개념 SVG를 유지한다.

필수 범위/결과물을 접지 않았다. 보조 맥락을 줄이기 위해 숨김/펼침을 무조건 사용하는 규칙으로 일반화하지 않는다. 프로그램 미리 보기는 목록을 복제하려는 목적이 아니라 관심에서 특정 세션까지 이어지는 탐색이다.

## 실행과 검증

`node scripts/build-relevance.mjs` → `node scripts/serve.mjs --port=4331` → `/relevance/index.html`.

`QA_VARIANT=relevance`로 `scripts/qa.mjs`, `scripts/branches.mjs`를 실행한다. PowerShell에서는 `$env:QA_VARIANT='relevance'`를 사용한다. 추가 검사: `scripts/relevance-checks.mjs`, `scripts/relevance-motion-checks.mjs`, `scripts/relevance-flow-checks.mjs`, `scripts/relevance-evidence-checks.mjs`. 서버는 `BASE_URL`, Chrome은 `CHROME_PATH`로 지정한다.

닫힌/열린 맥락·서비스 변경·확대·회전 표식, 서로 다른 작품 원본·상세/복귀, 양일 프로그램 이동·열림·초점을 확인한다. 기본 기능·모바일·카드/아이콘 정렬·두 글자 확대 방식·모션·키보드도 분리해 기록한다.

B/새 개선본·직전/새 개선본·3종 보기와 함께 이동/동시 스크롤을 유지한다. 모달 내부는 독립 조작이다. 로컬 데모로 실제 예약/전송을 하지 않으며 GitHub Pages에 배포하지 않았다.
