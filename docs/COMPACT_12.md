# B·Craft11 재검토와 전문 서비스 축소안

[브라우저 비교](../compact/index.html) · [검사 요약](../reports/compact-12/README.md)

## 검토 범위와 판단

B와 Craft11을1440/390px에서 새로 캡처하고 실제 콘텐츠·자료·선택 동작을 확인했다. Compact12는 전문 서비스만 조정한 별도 후속안이다. 다른6개 카테고리는 Craft11과 HTML이 동일하다. 기존 Craft11과 그 이전 결과를 수정하지 않았다. 미적 판단은 화면 검토에 따른 해석이며 기능 검사 수나 짧은 길이가 미적 우위를 입증하지 않는다.

## 전문 서비스

| 항목 | 실제 개선 | 남은 부족함과 원인 |
|---|---|---|
| 예시의 구체성 | B의 서비스 범위 설명보다 메시지 초안·4단계 책 탐색·서점 콘텐츠 구조를 직접 보여줘 선택 차이를 이해하기 쉽다. | 서점이라는 맥락은 구체적이지만 누구의 어떤 선택 문제인지 근거가 없다. 문장도 아직 보편적이다. 실제 조사/성과를 발명하지 말고 가상 과제의 대상·제약·판단 이유를 짧게 명시할 필요가 있다. |
| 상단 배경 경계 | 소개와 선택이 한 바탕으로 이어져 문단 바로 밑에서 배경이 끊기던 현상이 사라졌다. | 넓은 같은 색 바탕만으로 소개와 선택의 역할을 구분하면 단조로울 수 있다. 색을 더 나누기보다 제목 크기·내부 간격·결과 위계로 경계를 유지하는 편이 적절하다. |
| 읽기 위치 | 결과 시작·CTA·다음 섹션 위치와 스크롤을2px 미만으로 유지한다. 확대와 열린 맥락에서도 검사했다. | 가장 긴 결과를 위해 예약한 공간이 짧은 문장형 결과에 남는다. 단순히 전부 같은 높이로 고정하는 것이 해결은 아니다. |
| 크기 | Craft11 우측 패널은 약684px로 첫 화면을 넘었다. Compact12는 결과/제공 범위를 PC에서 나란히 두고 흐름을 번호 목록으로 압축해477px로 줄였다. | 320px와200% 확대에서 첫 화면에 모든 내용을 넣을 수는 없다. 자연스럽게 늘어나게 두며 잘림/내부 스크롤로 숨기지 않는다. |

PC1440×900에서 패널 하단은 약999→740px, 문의 버튼 하단은898→641px다.1440×768과1280×800에서도 결과 패널 전체를 첫 화면 안에서 확인했다. 모바일390px 패널은705→622px, 전체 문서는2464→2378px다. 모바일 선택 뒤 빈 공간이 모두 없어진 것은 아니며 순서형/구조형 결과와의 크기 차이에 따른 최소 여백은 남는다.

B는 첫 화면의 서비스 문서가 소개와 잘 묶이고 위계가 단순하다. 자체 화면은 예시를 바로 조작할 수 있고 문의까지의 흐름이 짧다는 장점이 있으나, 시각적 개성과 정보 명료성 모두 B보다 낫다고 단정할 단계는 아니다.

## 포트폴리오

| 항목 | 실제 개선 | 남은 부족함과 다음 기준 |
|---|---|---|
| 작품 자료 | NEST가 단순한 색면 중심의 B 자료에서 주제 탐색·책 소개·내 서가라는 실제 화면 구조로 발전했다. 대표와 상세가 같은 작업을 이어 설명한다. | 여전히 가상 콘셉트다. 화면을 채운 것과 완성도 높은 실제 작업 증명은 다르다. RAY/FIELD는 단순 표지·로고 표현에 머물러 NEST와 자료 밀도가 다르다. |
| 크기·크롭 | PC에서는 NEST를 크게 보여주고 상세 화면을 별도로 제공해 반복 이미지를 줄였다. | 모바일에서도 두 작품을 병렬로 유지하므로 대표 UI의 작은 글씨는 확대 전 읽기 어렵다. 모바일에서는 대표 한 장을 크게 보여주거나 핵심 조작을 크롭하고 전체/세부 확대를 명확히 연결하는 편이 좋다. |
| 조판·탐색 | 작품 설명과 실제 상세 자료가 연결되고 모달 전체/세부·오류/재시도가 같은 버전을 사용한다. | B의 카드 단위는 모바일에서 구분이 즉각적이다. 자체 화면의 선·여백만으로 나뉜 일부 구간은 작업 단위의 응집력이 약하다. 사진을 추가하기보다 작품별 매체/산출물 구성을 먼저 완성해야 한다. |

390px 전체 길이는 B3435px, Craft11은3508px다. 작품 자료를 늘린 대신 탐색 길이는73px 길다. 모바일 대표 자료의 가독성과 단위별 위계가 우선이며 모션을 더 넣는 것은 이 문제를 해결하지 않는다.

## 행사

중복 소개를 덜어 Craft11 모바일은 직전2803→2732px로71px 짧아졌다. 관심 문구→실제 프로그램명→정확한 날짜/세션 열기의 연결은 B보다 구체적이다. 포스터와 본문의 따뜻한 배경도 역할을 나누며 이어진다.

다만 B2546px보다186px 길다. 상단의 두 프로그램 미리 보기와 아래 일정이 같은 프로그램명을 다시 보여주고, 큰 날짜 버튼·세션 행·신청 패널이 각각 넓은 여백을 갖는다. 관심 미리 보기가 탐색을 도와주는 이득과 반복 길이의 비용을 함께 봐야 한다. 소개 문단을 제거하면서 '누가 만나는 행사인가'라는 맥락은 약해졌다. 제공된 프로그램 설명 안에서 활동/관심을 짧게 연결하고, 미리 보기와 전체 일정의 역할을 더 구분하는 편이 좋다. 새 연사·장소·혜택·성과를 발명하지 않는다.

## 모션의 자연스러움

B의 기본 섹션 진입은22px·850ms, 자체 화면은 전문 서비스6/8px·420/520ms, 작품 대표12px·880ms, 작품 카드10px·700ms, 행사 대표14px·800ms, 신청 묶음8px·560ms다. 감속 곡선은 같은 cubic-bezier(.22,1,.36,1)이다.

B는 큰 섹션의 움직임이 통일되어 장면이 한 번에 붙는 느낌이 강하다. 자체 화면은 목적별로 움직임을 구분해 서비스 선택은 빠르고 감상은 느리게 한다. 전문 서비스는 B보다 정적으로 느껴질 수 있으나 값 변경 지연·빠른 재선택 잔상·초점 이동을 줄이는 데 맞는 선택이다. 작품의 작은 글자나 예약 여백을 움직임으로 보완해서는 안 된다.

실제 Chrome에서 PC/모바일의 진입과 감소 설정을 비교했다. 자체 화면의 초점 진입 중단·재진입 반복 금지·즉시 상태 갱신도 검사했다. 시간/이동량 검사만으로 체감 부드러움이나 실기기 프레임 성능을 입증하지는 않는다.

## 실행·보존·제한

```sh
node scripts/serve.mjs --port=4331
node scripts/build-compact.mjs
node scripts/check.mjs
```

`BASE_URL=http://127.0.0.1:4331`, `QA_VARIANT=compact`, `CHROME_PATH`를 로컬 Chrome 경로로 설정한 뒤 `node scripts/qa.mjs`, `compact-checks.mjs`, `compact-stability-checks.mjs`, `compact-role-checks.mjs`, `compact-motion-checks.mjs`, `compact-size-checks.mjs`, `compact-b-motion-checks.mjs`를 `scripts/`에서 실행한다. Windows는 `$env:QA_VARIANT='compact'` 형식이다. 기능 검사의 `artifacts/qa.json`은 실행 직후 `reports/compact-12/browser-checks.json`으로 복사하고 `node scripts/report-compact.mjs`를 실행한다.

SaaS 포함6개 카테고리는 바이트 동일하고 기존 Craft11 실행 자료와 이전 단계의 해시 보존을 확인한다. 함께 이동·동시 스크롤을 유지한다. 독립 최초 생성 실험이 아닌 같은 작성자의 후속 개선이며 외부 전송/실제 예약이 없는 로컬 데모다. 이번 변경은 GitHub Pages에 배포하지 않았다.
