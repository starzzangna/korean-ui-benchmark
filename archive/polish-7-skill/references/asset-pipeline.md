# 문서 밖에 필요한 자료와 준비 방법

## 제공하는 것과 프로젝트에서 받아야 하는 것

| 종류 | 이 패키지의 지원 | 실제 프로젝트에서 결정할 것 |
|---|---|---|
| 한영 UI 글꼴 | `assets/fonts/`의 Pretendard Variable v1.3.9 원본·OFL·CSS | 기존 브랜드 서체 우선. 약 2.06MB이므로 필요한 파일만 복사. 사용 글리프 서브셋은 별도 제작·검사·라이선스/이름 조건 확인 |
| 기본 UI 아이콘 | `assets/icons.svg` 자체 작성 8종, CC0 | 기존 아이콘 체계 우선. 브랜드 로고·특수 업종 아이콘은 별도 제공/권리 확인 |
| 컨트롤 | `assets/controls.css` 선택 적용 | 팔레트·폭·글꼴은 기존 토큰에 연결. 화면 레이아웃 테마가 아님 |
| 액션 | `assets/interactions.css`·`interactions.js` 선택 적용 | hover/press·사진·상세·아래 영역 등장. 기존 모션과 중복하지 않고 터치·키보드·모션 감소 유지 |
| 사진·제품·작업물 | ASSETS 템플릿·목록/미리보기 검사 도구 | 실제 제품·공간·과정·작품 파일, 촬영 동의/출처·권리. 범용 스톡 묶음은 제공하지 않음 |
| 키비주얼 | 카테고리별 편집 기준 | 실제 행사 포스터/영상, 자체 조판·그래픽. 로고·고유 아트는 무단 복사하지 않음 |
| 신뢰 자료 | 사실과 참고 표시 방식 | 실제 경력·가격·주소·시간·약관·산출물. 임의 고객 로고·후기·매출·잔여석 제외 |
| 검사 | 로컬 에셋 검사+브라우저 DOM/선택지 검사 | 앱별 API·상태 전이·예약/결제의 실제 연동 검사 |

무료 파일도 권리·용도·용량 확인이 필요하다. Apple 시스템 폰트를 파일로 복사해 배포하지 않는다. Pretendard는 한영 혼용을 지원하므로 영문마다 별도 폰트를 추가할 필요는 없다. 시각적 이유가 있을 때만 영문 display 파일을 추가한다.

## 최소 준비 흐름

1. 실제 파일을 열고 대표·목록·세부·과정의 역할을 배정한다. 프로젝트 루트에 `assets/ASSETS.json`을 템플릿으로 만든다. 파일 경로는 manifest 위치 기준이다.
2. 출처 URL, 저작자, 이용 조건, 실제/참고 여부, 예상 용도를 기록한다. 외부 서비스의 이용 조건이 불명확하면 배포용으로 확정하지 않는다. 다운로드·라이선스 확인은 사람이 읽을 수 있는 기록으로 남긴다. 도구는 법적 권리를 판정하지 않는다.
3. `node <skill>/scripts/prepare-assets.mjs <project>/assets/ASSETS.json --out <project>/qa/assets`를 실행한다. 파일 누락·해시·빈 메타데이터를 점검하고 `contact-sheet.html`을 만든다. 브라우저로 열어 사진을 나란히 보고 톤·연속성·제품 식별·크롭을 결정한다. 검사는 파일을 수정하거나 원격 파일을 다운로드하지 않는다.
4. 대표 이미지의 원본 해상도와 표시 크기를 실제 브라우저에서 비교한다. CSS 비율만 맞아도 해상도가 모자라면 다른 파일/크기로 바꾼다. 이미지에 width/height 또는 aspect-ratio를 주고, 첫 화면 핵심 이미지까지 lazy 처리하지 않는다. 아래 이미지는 필요하면 lazy·async로 로드한다.
5. 모바일·데스크톱 크롭을 각각 보고 `object-position`/별도 소스를 기록한다. 작품·도표처럼 전체를 읽어야 하면 contain·상세 원본을 제공한다. 사진 로딩 실패·재시도·대체 설명을 확인한다.

외부 검색/생성 도구가 있으면 프로젝트 목적에 맞을 때 사용 가능하다. 필수가 아니며 별도 비용·키가 필요한 도구를 자동 전제로 삼지 않는다. 생성한 사진/렌더를 실제 매장·실제 고객 성과의 증거로 쓰지 않는다. 부족한 자료가 품질을 제한하면 필요한 촬영 목록을 결과에 남긴다.

## 아이콘과 컨트롤 사용

필요한 symbol만 기존 아이콘 컴포넌트로 옮기거나 같은 출처의 sprite를 로컬 제공한다. 아이콘 외형을 새 체계와 섞지 않는다. `icons.svg`의 `kui-arrow-right`, `kui-chevron-down`, `kui-search`, `kui-close`, `kui-plus`, `kui-check`, `kui-expand`, `kui-arrow-left`를 제공한다. sprite를 외부 use로 참조할 때는 로컬 HTTP로 제공한다. file://에서는 브라우저 제한이 있을 수 있다.

```html
<button class="kui-control" type="button">
  <span>작업 자세히 보기</span>
  <svg aria-hidden="true" viewBox="0 0 24 24"><use href="./assets/icons.svg#kui-arrow-right"/></svg>
</button>
```

버튼 문구가 이름을 제공하면 아이콘은 `aria-hidden`으로 둔다. 아이콘 전용 버튼에는 실제 행동의 `aria-label`이 필요하다. CSS는 `.kui-*` 범위에만 적용하며 Tailwind 설치·CDN을 요구하지 않는다. 기존 컴포넌트에 이미 같은 역할이 있으면 참고만 한다.

## 역할·모바일 크롭 메타데이터

ASSETS.template.json v2는 피사체(subject), 촬영군(shootGroup), 구간별 역할과 새 정보(usedIn), 모바일 초점/안전 영역/대안(mobileEdit)을 제공한다. 해당하는 자료에만 기입한다. prepare-assets.mjs는 기존 v1도 지원하며 새 필드를 기입했다면 빈 구조를 오류로 기록한다. contact-sheet에는 역할과 크롭 근거를 표시한다. 빈 템플릿은 실제 에셋이 확보된 것으로 집계하지 않는다. 내용·권리·피사체 적합성은 사람이 별도로 확인한다.


[에셋/크롭 실행 예제](../assets/editorial/index.html#brand)는 같은 참고 사진의 넓은/가까운 크롭과 캡션을 비교한다. 예제 ASSETS.json은 실제 파일 경로·출처·역할·모바일 보존 피사체를 제공한다. 프로젝트에 필요한 촬영 목록은 [편집 결정](editorial-decisions.md)의 조건별 자료 역할로 정한다.

## 촬영군과 표현량 검토

대표/목록/세부가 확보됐다는 개수 확인 뒤 실제 사진군을 함께 본다. 색온도·광원 방향·그림자의 농도·배경 복잡도·촬영 거리 중 불일치가 브랜드 인상을 깨는지 판단한다. 서로 다른 품목의 색을 억지로 같게 보정하거나 원본 사실을 바꾸지 않는다. 의도한 다양성은 유지한다.

사진이 어울리지 않으면 후보는 같은 촬영군 선택, 배치/크롭 조정, 필요한 원본 요청 순으로 비교할 수 있다. 추가 자료 목록은 `대상·사용 구간·필요한 정보·모바일 보존 부위·허용 출처`로 특정한다. 예: 브랜드는 조명의 빛과 소재가 함께 보이는 사용 장면/식별 컷, 식당은 실제 대표 접시와 메뉴 연결 사진, 전문 서비스는 제목·핵심 판단을 읽을 수 있는 원본 문서. 없는 사진을 장식 이미지로 채웠다고 해결로 보고하지 않는다.

ASSETS.template.json의 선택적인 visualGroupReview에 촬영군 비교와 조치를 적을 수 있다. 자동 도구는 실제 색온도나 촬영 일치성을 인증하지 않는다. [편집 실행 예제](../assets/decisions/USAGE.md)의 자료 역할과 새 정보 표를 참고한다.

## 프레임 정렬 다음에 피사체를 검토한다

동시에 보이는 사진의 contact sheet를 만들거나 나란히 띄워 빛/색온도/노출·거리·배경·피사체 면적·시선 방향을 비교한다. 같은 비율의 상자라는 이유로 촬영군이 통일됐다고 기록하지 않는다. 품목이 다른 사진은 물건의 실제 윤곽과 주변 여백이 비교 가능한지 보고 크롭/위치/배치를 조정한다. 작은 원본을 억지 확대하거나 제품의 색·형태를 바꿔 일치를 꾸미지 않는다.

대표/비교/세부의 역할마다 새 정보를 적는다. 같은 원본을 재사용하면 사용 장면→품목 식별처럼 역할 차이를 명시한다. 브랜드는 사용/소재, 매장은 공간/과정, 식당은 음식/실제 메뉴, 작품은 전체/실제 세부, 서비스는 읽는 산출물, 행사는 포스터/일정 중 현재 자료에 맞는 것만 고른다. 고정 장수 할당량이 아니다. 자료 부족은 필요한 대상·촬영 거리·빛·비율·권리/사실 확인을 작업 요청으로 남긴다. 참고 이미지는 실제 제품/장소의 증거로 전환하지 않는다.

ASSETS의 subjectReview는 실제 비교한 폭·남길 윤곽·여백 차이·조치/부족 원본을 담는다. 도구의 자동 점수가 아니라 실제 사진 판단이다.
