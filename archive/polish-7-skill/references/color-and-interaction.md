# 브랜드별 색과 촉각적인 액션

구성의 크기 대비·조판·사진의 면적과 동작 피드백을 화면 목적에 맞춰 연결한다. 색은 기존 브랜드·실제 자료·가독성으로 결정한다. 같은 구조의 색상 변경과 콘텐츠에 맞는 구성 변경을 구분한다.

## 팔레트를 정하는 근거

1. 기존 브랜드와 사용자 지정색을 먼저 따른다. 없으면 실제 사진·제품 패키지·작업물·행사의 메시지에서 후보를 찾는다. 녹색·크림색·검정을 자동 선택하지 않는다.
2. 바탕/본문/보조문구/행동/선택/오류의 역할을 나눈다. 대표 사진의 색과 버튼이 같아야 하는 것은 아니다. 색이 충분한 사진은 중립 바탕, 정보가 많은 앱은 읽기 면을 우선할 수 있다.
3. 실제 콘텐츠로 밝은 면과 어두운 면 중 무엇이 맞는지 결정한다. ‘프리미엄이므로 다크’는 근거가 아니다. 두 후보는 바탕의 온도·명도·강조 면적까지 비교하며 색 이름만 바꾸지 않는다.
4. 본문/버튼/포커스/오류 대비를 실제 조합으로 검증한다. 브랜드색이 연하면 바탕/그래픽으로 쓰고 작은 글자·버튼 글자는 더 진한 역할색을 둔다. 상태는 문구·아이콘도 사용한다.
5. 여러 사이트를 만드는 일반 작업에서는 나란히 보고 바탕·명도·강조 비율이 전부 같아졌는지 확인한다. 고유한 사진·내용이 같은 방향을 정당화한다면 유지한다. 최초 독립 비교에서는 다른 작성자의 시안을 보여주지 않고 제출 후에만 반복성을 평가한다.

| 상황 | 검토할 수 있는 방향 | 고정하지 않을 것 |
|---|---|---|
| SaaS | 차가운 밝은 업무 면·청색/잉크 행동색, 또는 기존 제품의 다크 UI | 모든 SaaS를 녹색 상태 카드로 구성 |
| 생활 브랜드 | 재료색·사진의 온도, 와인/테라코타/청색 등 브랜드 근거가 있는 강조 | 모든 브랜드를 크림+세이지로 결정 |
| 매장·수업·음식 | 공간과 음식의 색을 살리는 밝은 면, 실제 패키지의 강조색 | 업종명만 보고 갈색·녹색 의무화 |
| 포트폴리오 | 작업물의 색을 보존하는 갤러리 바탕과 작은 탐색 강조 | 작품 전체에 같은 색 필터 |
| 전문 서비스 | 문서의 대비·정렬과 명확한 역할색, 필요하면 진한 브랜드 면 | 의미 없는 다크 목업을 신뢰 근거로 사용 |
| 행사 | 포스터의 잉크/종이 관계와 큰 색면, 날짜·행동의 대비 | 행사마다 같은 노랑·연두·궤도 도형 |

## 섹션 사이의 배색 연결

### 바탕까지 선택하고 구현에서 확인하기

공통 CSS의 바탕을 흰색·베이지 등 한 색으로 고정한 채 accent만 바꾸면 다른 브랜드도 같은 계열로 보인다. 초기 바탕은 중립색으로 두고 프로젝트별로 `paper / ink / muted / soft / line / accent`를 함께 확정한다. 확정된 브랜드 규칙이 있으면 이를 우선하고, 사진의 색이 충분하면 흰색·회색처럼 색을 덜 쓰는 선택도 인정한다. 브랜드 근거가 약하면 중립 밝은 면과 제한된 행동색부터 검토한다.

선택 이유에는 무엇을 먼저 읽게 하는지, 사진·실제 자료와 어떤 관계인지, 바탕의 온도/명도와 강조 면적을 적는다. 여러 페이지를 만든다면 전체 축소본에서 지배적인 바탕까지 같은지 비교한다. 다양성을 위해 무작위 색을 뽑거나 카테고리에 색 하나를 영구 배정하지 않는다. 바탕을 바꿨으면 녹색/갈색으로 하드코딩한 안내·선택·문서·모달이 남아 있는지도 확인한다. 업무 앱은 간결한 목록과 상태 위계를 유지하며 팔레트 변경을 소개·요약 카드 추가의 근거로 삼지 않는다.

검토에서는 문서에 쓴 토큰과 body·주요 구간의 computed 색을 대조하고 본문/보조문구/버튼 대비를 실제 조합으로 확인한다. 장식선의 낮은 채도와 입력·초점 경계의 식별은 따로 판단한다.

DESIGN.md에 구간별 바탕·본문·행동색을 나란히 적고 전 페이지를 한 화면의 축소본으로 본다. 소개→내용→신청에서 같은 브랜드의 면으로 이어지는지 확인한다. 입력 영역을 강조하려는 이유만으로 앞에서 쓰지 않은 고채도 색을 넓은 면에 추가하지 않는다. 새로운 색이 필요하면 브랜드·콘텐츠 근거와 다른 구간에서의 사용 위치를 설명한다. 색 개수를 임의로 고정하는 대신 색의 역할과 재등장을 관리한다.

강한 포스터의 다음 구간은 중립적인 읽기 면으로 쉬게 하고, 신청 영역은 기존 잉크색·종이색·강조색의 조합으로 전환할 수 있다. 한 구간의 보기 좋은 조합도 앞뒤와 무관하면 다시 선택한다. 실제 폼의 경계·오류·초점 대비는 넓은 바탕 면과 별도로 검수한다.


페이지 바탕·대표 장면·내용을 읽는 면·선택/완료 면의 역할을 구분한다. 흰색을 비어 있는 안전값으로 자동 상속하지 않고 실제 자료의 소재·빛·확정된 브랜드색으로 선택한다. 파스텔이나 낮은 채도는 넓은 바탕에 쓸 수 있으나 본문·오류·포커스의 식별은 유지한다. 개인 브랜드색이 확정되어 있으면 그 색을 근거로 사용하며 사람의 퍼스널 컬러를 추정해 사실처럼 만들지 않는다.

섹션 목적이 바뀌는 지점은 내용·간격·명도/온도 변화 중 적절한 조합으로 전달한다. 모든 섹션에 다른 색을 할당하지 않는다. 작품/사진의 원색을 보존할 읽기 면과 넓은 분위기 면을 구분하고, 실제 렌더링된 body·대표·목록·신청의 바탕을 함께 확인한다. 업무 앱의 승인된 읽기 면은 소개 사이트의 배경 개선 때문에 변경하지 않는다.

## 장면과 조작을 분리

사진·포스터·작업의 등장과 프레임 자세는 [scene-motion.md](scene-motion.md)의 장면 기준을 적용한다. 이 문서의 짧은 컨트롤 반응이 대표 장면을 정적으로 만들라는 뜻은 아니다. SCENE_MOTION과 CONTROL_MOTION을 따로 확정한다.

- 메뉴·필터·정렬·업무 행·합계는 즉시 내용과 상태를 갱신한다. 행마다 들림과 순차 등장을 붙이지 않는다.
- 대표 CTA는 이동 방향과 누를 수 있는 대상을 알려준다. 일반 저장·폼 확인은 더 짧은 누름/결과 반응을 선택한다. 클릭 처리는 애니메이션 완료를 기다리지 않는다.
- 상품·작업 카드는 작은 이미지 확대 또는 프레임 이동을 선택할 수 있다. 감상용 확대는 명시적인 상세 뷰어에서 이동·맞춤까지 제공한다.
- 상세/확인은 새 맥락을 짧게 알리고 초점·Escape·복귀를 유지한다. 오류는 해당 입력·문구와 연결한다. 장식 반응으로 실제 저장·신청 결과를 대신하지 않는다.
- 실제 요청의 로딩/중복 차단/실패/입력 보존·재시도와 동기 데모의 범위를 구분한다.

신규 표현 중심 페이지의 장면과 컨트롤을 함께 구성하려면 assets/motion의 선택 역할을 복사하거나 기존 프로젝트 구현을 사용한다. 기존 assets/interactions.css/js는 짧은 컨트롤 반응용 대안이다. 같은 요소에 두 패키지를 중복 연결하지 않는다. legacy data-kui-feedback=state/press/cta/card/dialog와 data-kui-reveal=editorial은 기존 구현의 범위이며, 그 작은 수치가 모든 사이트의 상한은 아니다.

DESIGN에는 대상→사용자가 알아야 할 변화→방식/시간→선택 이유를 적는다. 터치와 키보드에서 같은 동작에 도달하고 모션 감소에서는 즉시 상태를 읽을 수 있게 한다. 전 요소 자동 등록·기본 무한 부유·자동 탭 전환·스크롤 가로채기는 추가하지 않는다. 성능 검사·기능 성공·시각적 완성도는 별도로 검토한다.


## 장식선과 조작 경계를 나눈다

색 역할에 `separator`와 `control-border`를 분리한다. 목록/섹션 장식선이 화면에서 먼저 보이면 채도와 명도 대비를 함께 낮추고 실제 사진·텍스트 위계를 다시 본다. 저채도 색도 매우 어두우면 강한 선으로 보이므로 채도만 제거하지 않는다. 사진색에서 유래한 유색 선을 모든 경계에 자동 배포하지 않는다.

장식선은 정보 전달이 색·선 하나에 의존하지 않을 때 중립적인 약한 선을 선택할 수 있다. 입력창 식별에 필요한 경계·선택·오류·포커스는 실제 인접색 대비를 따로 검토한다. 바탕 위 장식선과 입력 테두리를 같은 opacity/공통 border 토큰으로 일괄 흐리게 하지 않는다. hover·선택·초점과 기본 상태를 각각 확인한다.
