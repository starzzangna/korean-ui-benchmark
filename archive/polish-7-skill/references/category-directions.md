# 카테고리별 구성과 시각 방향

업종 하나에 모양 하나를 고정하지 않는다. 사용자가 원하는 인상과 실제 자료를 우선하고, 아래 후보 중 내용·에셋·주요 행동에 맞는 방향을 고른다. 후보는 설계의 출발점이며 현재 자료로 구현할 수 있는 것만 선택한다.

## 선택 과정

1. 사용자가 해야 할 일과 제공된 사실을 적는다. 예: 네 제품의 가격 비교, 두 수업의 시간 선택. 주소·후기·소재·실적 등이 없으면 만들어 채우지 않는다.
2. 실제 에셋을 확인한다. 소유 사진, 사용 가능한 참고 사진, 제품 화면, 일러스트, 텍스트 중 무엇이 있는지 구분한다. 소형 프로젝트의 사진 사용에 유료 API나 이미지 생성 구독을 전제로 하지 않는다.
3. 카테고리 안에서 자료로 가능한 구성 후보 두세 개를 비교하고 하나를 선택한다. 가능한 안이 하나라면 이유를 적고 진행한다. 사용자가 이미 방향을 지정했다면 그 선택을 구체화한다. 후보를 무작위로 섞거나 매 섹션마다 다른 스타일을 덧붙이지 않는다.
4. 선택한 방향을 첫 화면·섹션 순서·타이포·사진 비율·색상 역할·핵심 컴포넌트에 함께 적용한다. 같은 구조에 색상과 제목만 바꾼 결과는 다른 방향으로 세지 않는다.

## 카테고리와 서로 다른 후보

## DESIGN.md에 남길 결정

```yaml
SITE_CATEGORY: brand-home
ART_DIRECTION: photographic-catalog
ASSET_MODE: licensed-reference-photography
DESIGN_VARIANCE: 5
SCENE_MOTION: auto
CONTROL_MOTION: auto
VISUAL_DENSITY: 5
```

설정 뒤에는 실제 결정도 쓴다: 첫 화면에서 보여줄 대상, 섹션 순서와 이유, 제목/본문 관계, 주요·보조 사진의 화면 비율과 크롭 위치, 중립색/강조색의 쓰임, 자료 출처, 모바일 읽기 순서. `ART_DIRECTION` 이름만 붙여 놓고 이전 템플릿을 그대로 구현하지 않는다.

## 사진을 사용할 때

사용자 소유의 실제 제품·장소 사진을 우선한다. 공개 사진을 추가한다면 원문 페이지의 사용 조건·작가·출처를 확인하고, 허용되는 파일을 로컬에 저장해 런타임의 임의 이미지 서비스 의존을 줄인다. 사진의 주제·광원·구도·비율을 직접 확인하고 내용과 맞게 크롭한다. 본문 위에 사진을 깔면 대비를 검증한다.

참고 사진은 실제 상품·매장·팀 사진과 구분해 표시한다. 제조사·재질·소유권·제휴를 추측하지 않는다. 가상의 상품 사진이면 사용자에게 참고 이미지임을 알리고 실제 판매 사진처럼 오인시키지 않는다. 사진이 없다는 이유로 모든 페이지에 같은 SVG 정물을 자동 생성하지 않는다. 실제 UI·상세 텍스트·형태 예시 등 과업에 맞는 대안도 가능하다.

## 반복과 차별화 검토

여러 사이트를 나란히 보고 다음을 비교한다.

- 첫 화면: 사진 전체 면 / 제품 그리드 / 작업 목록 / 일정표 / 조판 중 무엇이 중심인가?
- 조판: 제목의 크기뿐 아니라 서체 역할·굵기·줄 길이·정렬이 내용에 맞게 달라졌는가?
- 탐색: 제품·예약·문의·자료 검색이 실제 우선순위에 맞게 배치됐는가?
- 이미지: 실제 내용과 연결되는가, 단순히 분위기를 채우는 같은 정물을 반복하는가?
- 섹션: ‘작은 영문 라벨→감성 제목→사진→똑같은 카드’가 내용과 무관하게 반복되는가?

근거 없이 크림 배경·명조·아치·작은 영문 색인·갈색 사진을 묶어 ‘프리미엄’의 기본값으로 삼지 않는다. 어울리는 프로젝트에서는 쓸 수 있지만, 제거만 해서 내용이 빈약해지는 것도 피한다. 실물 사진을 추가했다고 자동으로 좋은 디자인이 됐다고 보고하지 않는다.

## 적용 범위

주제·보유 에셋·사용자 행동으로 방향을 고르고 실제 화면에서 검토한다. 색·서체·출력 스택은 프로젝트 조건으로 결정한다. 가상 실적·후기를 사실처럼 만들지 않고, 필요한 부속 도구는 실제 제공·실행 여부를 확인한다.
