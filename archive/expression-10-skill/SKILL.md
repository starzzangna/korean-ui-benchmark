# 한국어 UI 디자인

콘텐츠를 식별하고 다음 행동을 수행하기 쉬운 한국어 화면을 설계한다. 색·구도·자료·모션은 페이지 목적과 실제 에셋으로 결정한다. 특정 브랜드의 외형, 공통 테마, 효과 개수를 품질 기준으로 삼지 않는다.

## 범위와 우선순위

- 현재 사용자 요청과 기존 프로젝트의 브랜드·스택·기능을 우선한다. 새 소형 사이트는 정적 HTML/CSS/JS로 구현할 수 있으며 Tailwind나 외부 서비스를 필수로 설치하지 않는다.
- 요구사항·디자인 선택·검증 가능한 결과를 구분한다. 기존 프로젝트를 수정할 때는 [프로젝트 기준](references/project-constraints.md)으로 유지할 기능·자료·관계와 변경 범위를 확인한다.
- 제공되지 않은 제품 정보·주소·후기·성과를 사실처럼 만들지 않는다. 사진·글꼴·아이콘의 출처와 이용 조건은 실제 사용 에셋에 대해 기록한다. 연동 없는 입력은 가까운 위치에 처리 범위를 표시한다.

## 설계에서 구현까지

1. **과업과 정체성:** 방문자가 무엇을 판단하거나 수행해야 하는지 정하고, 이 브랜드에서만 보여줄 수 있는 내용·자료를 찾는다. [편집 선택](references/editorial-decisions.md)의 제작 브리프로 `방문 상황 → 첫 판단 → 근거 자료 → 다음 행동`을 한 문장으로 연결한다. 한국적인 인상을 특정 팔레트·장식으로 고정하지 않는다. 자연스러운 한국어, 실제 상품·방문·의뢰 맥락과 브랜드의 표현을 설계한다.
2. **구성 선택:** GNB·배너·본문을 따로 꾸미기 전에 [상단과 색면 관계](references/header-and-surfaces.md)로 반복 탐색·대표 장면·구간 경계의 연결을 정한다. 전체 같은 바탕이나 배너만 다른 구성도 조건에 맞으면 선택한다.  대표 대상·문구·행동의 관계가 다른 후보를 검토한다. 자료나 요청이 한 방향을 정하면 불필요한 시안을 추가하지 않는다. 설명이 없는 색상·비율 변경을 새 구성으로 간주하지 않는다. 문구·자료·행동의 동시 이해와 자료 감상 중 무엇이 중요한지로 병치/전면/적층을 선택한다. 대표 대상의 식별 면적을 전폭·전체 높이와 혼동하지 않으며, 특정 구도를 피하기 위한 후보나 할당량을 만들지 않는다.
3. **구간 연결:** 첫 화면은 대상과 목적, 중단은 비교·이해, 하단은 선택·완료를 맡도록 편집한다. 실제 과업에 필요하지 않은 구간은 생략한다. 반복 설명·큰 로고·장식 패널로 길이를 채우지 않는다. 설명을 줄이는 것과 대표 장면을 줄이는 것은 구분한다. 브랜드 인상이 목적인 페이지는 첫 화면에서 식별 가능한 대표 대상·핵심 문구·다음 행동이 함께 전달되는지 확인하고, 목록의 기능 완성으로 이를 대신하지 않는다. 구체적인 판단은 해당 카테고리 기준을 따른다.
4. **대표 구간부터 구현:** 현재 자료의 주인공·비교 대상·첫 행동이 이어지는 첫 화면과 다음 구간에서 구성을 채택한다. 관계가 불명확하면 내용 관계가 다른 소수의 후보를 비교하고, 채택 이유와 버린 설명/선택을 기록한다. 전체 페이지 완성 뒤 색만 바꾸는 것으로 이 선택을 대신하지 않는다.  [DESIGN.md 템플릿](assets/DESIGN.md)에 선택한 관계와 실제 자료를 기록하고, 첫 화면과 바로 다음 구간을 PC/모바일로 먼저 만든다. 대상의 식별·설명 밀도·다음 행동이 성립하는지 본 뒤 나머지를 확장한다. 자료 부족은 장식으로 메우지 말고 [에셋 제작 요청서](assets/ASSET-BRIEF.md)에 대상·용도·필요 크롭을 남긴다. 부분 스타일 변경은 부모 배경·간격과 최종 컨트롤 변형까지 확인한다.
5. **실화면 대조:** [적용 확인](references/applied-evidence.md)으로 설계한 관계를 최종 DOM·조작·PC/모바일 화면과 대조한다. 표현을 다듬는 검토와 필수 기능의 완료 판정을 나눈다. [완료 게이트](references/delivery-gates.md)에 따라 누락·행동 가림·내부 잘림은 수정 후 영향 상태를 다시 검사한다. 동결 비교를 요청받았으면 원본 결과와 후속 수정을 분리한다.

## 공통 설계 기준

- **새 제작과 수정:** 기존 화면의 승인된 구도를 보존하는 조건은 해당 수정 작업에만 적용한다. 새 제작에서는 기능·사실·명시한 제약을 유지하고 정보 묶음과 대표 장면은 다시 판단한다. 재사용 예제는 필요한 관계/동작의 참고이며 완성 레이아웃의 정답이 아니다. 기능 공통화가 히어로·구간 순서·설명량까지 고정하지 않게 한다.
- **색:** 브랜드·사진·콘텐츠로 정하고 바탕/본문/보조/행동/선택/오류의 역할을 일관되게 연결한다. 바탕의 온도·명도·보조 면과 강조 면적까지 결정하고 실제 CSS 토큰에 반영한다. 공통 템플릿에 크림색을 숨은 기본값으로 두거나 버튼색만 바꿔 다양성을 대신하지 않는다. 업종만으로 녹색·미색·다크 모드를 고정하지 않는다.
- **색면과 구간:** 페이지 바탕·대표 장면·내용 읽기·선택/완료 면을 현재 자료에 맞게 정한다. 흰색이나 공통 미색을 자동 상속하지 않는다. 사진·소재·확정된 브랜드/개인색을 근거로 낮은 채도의 바탕도 검토하고 실제 구간의 명도·본문 대비·주목도를 확인한다. 이미 승인된 업무 앱은 이 표현 변경에서 분리한다.
- **자료:** 대표·목록·상세가 각각 전체/판단/세부 중 새 정보를 맡는지 확인한다. 같은 이미지를 연속해 크게 반복하는 경우에는 실제 감상 목적과 새 설명이 있는지 검토한다.  사진 상자뿐 아니라 피사체 크기·빛·크롭·캡션·다음 행동을 맞춘다. 작업·상품 상세는 선택한 자료와 같은 대상을 보여준다. 참고 이미지와 실제 제품/장소/고객 자료를 구분한다.
- **감상과 편집:** 문장·순서·비교·구조처럼 내용의 실제 형태를 표현으로 옮긴다. 모든 결과를 같은 인용문 카드, 모든 작품을 같은 캡션 패널로 만들지 않는다.  감상이 중요한 상품·음식·작품은 목록 밀도보다 먼저 실제 대상의 감상 크기를 정한다. 대표/목록/상세의 반복 자료는 전체·세부·쓰임 중 새 정보를 맡아야 한다. 번호·작은 라벨·얇은 선·정돈된 행을 업종 공통 스타일로 고정하지 않는다. 업무 앱에는 감상용 장면을 추가하지 않는다.
- **색인과 결과:** 특정 상품·분야·서비스를 고르는 색인은 해당 항목 상세·필터 결과·선택된 자료까지 이어지게 한다. 모든 항목이 같은 섹션으로만 이동하면 단순 구간 링크로 명명한다. 각 선택의 값·보이는 결과·초점/복귀를 실제 조작으로 대조한다.
- **정보 밀도:** 첫 행동까지의 길이와 과업 전체의 탐색 길이를 분리해 확인한다. 첫 CTA를 앞당긴 뒤 카드 여백으로 전체 화면이 늘어나는지 PC/모바일에서 다시 본다.  목록에는 비교에 필요한 이름·상태·가격·분야를 남기고 긴 판단 근거는 접근 가능한 상세로 옮긴다. 동등 비교 카드의 폭·이미지·캡션·행동 축을 맞추며 의도한 비대칭은 강조 목적과 읽는 순서를 설명한다.
- **한국어:** lang=ko·UTF-8·viewport를 설정한다. 기본 서체는 한글·영문·숫자 모두 Pretendard로 한다. 실제 파일을 제공하고 입력·선택·버튼도 상속한다. 별도 서체는 사용자 요청이나 확정된 브랜드 규칙이 있을 때 선택하고 이유를 기록한다. 실제 로드된 글꼴로 줄바꿈·굵기·행간을 확인한다.
- **조작:** 보이는 label·키보드 초점·오류 연결·복구·Escape·대화상자 초점 복귀를 구현한다. 선택 컨트롤의 필수 값/문구/개수는 구현에서 추출하지 않은 요구 계약과 실제 파싱 DOM을 대조하고 각 필수 선택값이 연결된 결과까지 도달하는지 확인한다. 대표 흐름 하나나 JS 구문 통과로 누락 검사를 대신하지 않는다.
- **정렬:** 아이콘과 문구의 내부 중앙/첫 줄, 그 묶음과 컨테이너의 가로 배치를 각각 결정한다. 글꼴 로드 후 짧은/긴 문구·오류·확대 상태에서 확인한다. 광학 중심과 상자 중심은 별도 판단이다. 나란한 select·검색·버튼은 실제 조작 높이와 상하 기준선, 라벨/필드 간격을 대조하고 장식선과 입력 경계의 색 역할을 분리한다. 셀렉트 표시를 통일할 때는 네이티브 기능을 유지하고 화살표 크기·우측 여백·문구 안전 영역을 공통 계약으로 검증한다.
- **모션:** 대표 자료 하나에만 제한하지 않고 구간의 읽는 단위에도 진입 모션을 검토한다. 사진·제목·설명·행동을 묶어 움직이며 배경 면과 조작 중인 입력은 안정적으로 둔다. 대상·계기·즉시 바뀌는 정보·장식의 끝 상태를 정한다. 장면 등장, 조작 피드백, 상태 표식을 구분한다. 빠른 왕복·중단·터치·키보드·모션 감소에서도 핵심 정보와 기능을 유지한다. 예제의 색·시간·전체 레이아웃을 일괄 적용하지 않는다.

## 설정과 검증

설정이 필요하면 [시작값](references/presets.md)을 바탕으로 SITE_CATEGORY/PAGE_PURPOSE, ART_DIRECTION/ASSET_MODE, SCENE_MOTION, CONTROL_MOTION, VISUAL_DENSITY, FONT_POLICY를 결정한다. DESIGN_VARIANCE나 MOTION_INTENSITY 같은 숫자 입력은 실제 구도·대상·거리·시간으로 번역한다. 숫자는 품질 점수가 아니며 완성 사이트에 설정 화면을 자동 추가하지 않는다.

320/390/768/1440px과 필요한 중간 폭에서 실제 콘텐츠를 확인한다. 글자만2배·글자/행간2배·브라우저 메뉴 확대는 다른 검사로 기록한다. 제목·가격·선택값·회전 표식·동적 확인창의 내부 손실을 문서 가로 넘침과 분리하고 overflow:hidden으로 감추지 않는다.

본문 대비4.5:1, 큰 글자·중요 UI 경계3:1을 검토하고 색 외 문구/상태를 제공한다. 조작 영역은44px 정도부터 검토하되 실제 과업·대상 장치에 맞춘다. 기능 성공·좌표 차이·효과 수를 시각적 선호나 전체 접근성 인증으로 바꾸지 않는다.

필수 선택지·연결 결과·닫기/완료 행동은 문서 작성이나 화면 검토 횟수로 완료시키지 않는다. 최종 HTML/컴포넌트 편집 뒤 새로 로드한 DOM에서 독립 요구 계약을 실행한다. 실패·미실행이 있으면 완료 게이트를 열지 않고 수정하거나 제한을 명시한다. 사용자가 동결 비교를 요청한 경우에는 결함 있는 원본도 보존하고 후속 수정을 별도로 검증한다.

정적 HTML/JS는 실제 브라우저와 구문을, 기존 앱은 변경에 맞는 타입/lint/테스트/빌드를 확인한다. 변경 내용·실제 검증·남은 제한을 한국어로 구분하고 실행하지 않은 검사를 통과로 기록하지 않는다.
