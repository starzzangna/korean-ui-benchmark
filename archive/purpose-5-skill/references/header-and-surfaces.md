# GNB·대표 장면·본문의 관계 선택

상단은 메뉴 개수와 방문 과업으로 설계한다. 페이지마다 다르게 보이게 하려는 목적만으로 탐색 위치를 바꾸지 않는다. 방문자가 반복해서 쓰는 이동과 첫 방문에서 판단할 내용이 같은 묶음인지 먼저 판단한다.

| 조건 | 검토할 관계 | 제외할 조건 |
|---|---|---|
| 반복 업무·저장·계정 이동 | 대표 장면과 독립된 기능 GNB | 소개 배너가 기능 접근을 밀어낼 때 |
| 안정된 상품 탐색·변하는 캠페인 | 같은 GNB/본문, 배너만 구별 | 캠페인마다 탐색 위치까지 바뀔 때 |
| 하나의 사진이 방문 판단을 담당 | 사진과 연속된 GNB 또는 사진 위 GNB | 문구 안전 영역·대비가 부족하면 중첩 제외 |
| 일회성 행사·전시 | 로고·날짜·행동을 함께 편집한 포스터형 상단 | 행사명을 GNB와 제목에서 연속해 크게 반복할 때 |
| 작업 감상이 먼저인 스튜디오 | 작은 마스트헤드, 큰 작업 | 축소된 탐색이 의뢰·분야 이동을 숨길 때 |
| 자료의 색/질감 자체가 정체성 | 페이지 전체 같은 바탕 | 구간 경계를 색 외 간격·제목·선으로도 읽지 못할 때 |

같은 바탕, 배너만 다른 바탕, 상단과 본문의 연속, 기능별 분리 중 콘텐츠에 맞는 관계를 채택한다. 색 있는 상단 → 밝은 목록 → 진한 신청을 공통 공식으로 만들지 않는다. 메뉴 행동·초점·접근성은 공유할 수 있지만 헤더 HTML·높이·로고/메뉴의 줄 수까지 무조건 공통화하지 않는다.

DESIGN.md에는 선택한 관계/배제한 관계와 이유, 실제 selector·CSS 역할색을 기록한다. 320/390/768/1024/1440px에서 GNB 줄바꿈·로고/메뉴 충돌·첫 행동·다음 구간 진입을 본다. 글자만200%와 글자/행간200%에서 헤더·사진·제목의 높이가 내용에 따라 늘어나야 한다. 사진 위 메뉴는 실제 크롭별 대비를 검토하고 불확실하면 사진 밖 연속 색면을 선택한다.

입장은 대표 자료의 묶음을 조용히 안내한다. 전체 상단·모든 섹션에 같은 Y 이동을 적용하지 않는다. 서비스 선택·필터·확대·날짜 변경은 결과를 즉시 갱신한 뒤 필요한 대상만 피드백한다. 메뉴 위치가 움직이는 효과와 모션 감소의 정보 손실을 피한다.
