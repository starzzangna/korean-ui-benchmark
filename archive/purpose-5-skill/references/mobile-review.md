# 모바일 내부 조판과 상태 검토

문서 scrollWidth가 정상이어도 내부 글자·캡션·선택값이 잘릴 수 있다. 320/390/768/1440px를 시작 표본으로 보고 실제 레이아웃이 전환되는 폭도 확인한다. 서로 다른 폭의 합격 수를 미적 점수로 합산하지 않는다.

## 실제 내용으로 보는 항목

| 대상 | 확인할 상태 | 문제일 때 편집할 것 |
|---|---|---|
| 한글 제목·단계 | 한 글자만 고립, 과도한 줄 수, 안쪽 열의 최소 폭 | 의미 단위 문구/줄바꿈, 가로 단계→세로 단계. 글자 축소·강제 nowrap으로 숨기지 않음 |
| 날짜·유형·금액 | 줄이 바뀌어도 서로 다른 정보가 붙지 않는가 | 의미별 span/list와 gap. 금액·날짜는 단위를 보존하되 컨테이너보다 길면 줄 배치 허용 |
| 회전/겹친 프레임 | 정지·등장 중간·hover·복귀의 바깥 경계 | 실제 그리드/여백과 한 열 전환. transform은 문서의 자리 크기를 바꾸지 않음 |
| 대표/보조 사진 | 피사체 식별, 캡션/CTA 연결, 모바일 불필요한 반복 | object-position/별도 소스/비율, 보조를 후속 구간으로 이동 |
| 나란한 카드 | 긴 제목·다른 설명·홀수 마지막·필터1개/복구 | 기존 동등 카드 폭/이미지/캡션/하단 행동 계약 유지. 내용 잘림으로 높이를 맞추지 않음 |
| 아이콘·복합 문구 | 한 줄 중앙 또는 여러 줄 첫 줄/그룹 중앙 | 실제 문구 wrapper의 상자 기준 선택. 서로 다른 기준의 측정값을 혼합하지 않음 |
| native select | 긴 선택값·단위·화살표 공간·레이블 | 폭/패딩/줄 구조와 별도 선택 요약. 선택값을 짧게 바꿀 때 의미 보존 |
| 모바일 탐색 | 헤더·보조 탐색·설명이 목록을 과도하게 밀지 않는가 | 중복 정보 축소와 재배치. 핵심 조작/안내를 임의 제거하지 않음 |

## 모션과 확대의 확인 순서

1. 폰트·이미지 로드 후 실제 크기의 첫 화면·중단·마무리를 본다. 정렬은 상자 측정과 시각 판단을 함께 기록한다.
2. 글자200%에서 문서 넘침 외에 내부 잘림·고립 글자·가격 충돌·고정 높이 손실을 본다. computed 글꼴/행간 주입 검사는 브라우저 메뉴 확대와 구분한다.
3. 선택/필터/설명 펼침을 왕복한다. 포인터를 빠르게 출입하고 등장 도중 상세를 열어도 내용·초점·끝 상태가 맞아야 한다.
4. 터치·키보드에서 hover 없이 같은 정보/행동에 도달한다. OS 모션 감소 초기 상태와 실행 중 변경, JS 비활성 시 기본 내용을 확인한다.

자동 검사는 후보를 찾는 보조 수단이다. 한 글자 고립·사진 적합성·광학적 정렬·부드러움은 실화면으로 판단한다. 기준을 통과하지 못하면 DESIGN.md에 문제/조치/남은 한계를 남긴다. 문서 전체 overflow:hidden·고정 높이·본문 축소로 실패를 감추지 않는다. 최초 제작 비교의 동결 결과는 수정하지 않고 별도 개선본에서 해결한다.

이미지 width/height 속성은 로딩 자리를 잡는 원본 정보다. CSS에서 폭만 바꾸고 속성의 높이가 남으면 aspect-ratio를 적어도 세로로 길어질 수 있다. 유동 이미지의 height:auto 또는 프레임 안의 width/height:100%와 object-fit을 구분하고 실제 렌더링 비율을 확인한다.

## 내부 검토에서 놓치기 쉬운 실제 실패

- 모바일에서 br을 숨길 때 `아침부터<br>작은`은 `아침부터작은`이 된다. 공백을 포함한 의미 단위 span이나 일반 띄어쓰기를 기본 HTML에 두고 폭별 실문장을 읽는다. 한 글자 고립 후보 검사는 이 붙는 단어를 찾지 못한다.
- native select는 선택 문구가 여러 줄로 표시된다고 가정하지 않는다. option은 의미를 보존한 짧은 이름, 전체 조건/단위/금액은 연결된 외부 요약으로 제공한다. 가장 긴 실제 선택을 조작한 뒤320/390/768·글자200%에서 확인한다. 레이블·요약을 ellipsis로 숨기지 않는다.
- 포스터의 큰 영문을 숨겼을 때도 한국어 행사명·일시·참가 조건·행동이 남는지 본다. 작은 날짜만 확대 검사에서 문서 밖으로 나가면 실패다. 큰 타이포는 반응형 크기/줄 배치를 바꾼다.
- 동등 비교의2열 구성에서는 마지막 홀수 작품을 임의 전폭으로 늘리지 않는다. 2+1의 마지막 카드와 다음 구간을 같은 화면에서 보며, 부자연스러운 공백은 섹션 간격/자료 순서로 조정한다. 필터1개→0개→전체 복구에서도 폭·안내·다음 행동을 유지한다.
- 기본/초점/hover 이동 중/복귀의 상자를 따로 본다. 중심 정렬 측정 통과가 작은 조작 영역·광학적 위치·잘림 통과를 뜻하지 않는다.

[확대 대응 실행 예제](../assets/decisions/index.html#event)의 긴 참가 조건은 select 밖 요약으로도 읽힌다. 브라우저200% 확대, 글자만 확대, computed 글꼴/행간 주입은 서로 다른 검토로 기록한다. 실행한 방식만 보고하고 데스크톱 Chrome 결과를 실기기/Safari 인증으로 표현하지 않는다.

## 확대 방식과 상태를 분리해 기록한다

기본320/390/768/1440, 글자만2배, 기존 computed 글자+행간2배, 실제 브라우저 메뉴 확대는 서로 다르다. 자동 주입은 원래 계산값을 먼저 저장한 뒤 적용하며 원본 소스/CSS를 바꾸지 않는다. 각 방식마다 문서 가로 넘침과 내부 잘림·가격 충돌·안내 줄 겹침·select 선택값·초점을 별도로 확인한다. 기본 폭 통과를 확대 통과로 옮겨 쓰지 않는다.

오류/가장 긴 선택/펼친 설명/대화상자에서도 확인한다. 깨지면 fixed height/nowrap/최소 너비를 검토해 줄·열·큰 포스터의 크기를 재편집한다. 본문 축소·overflow:hidden으로 손실을 숨기지 않는다. [카테고리 예제](../assets/category-motion/index.html)는 글자/행간 확대를 화면에서 왕복하며 같은 상태를 비교한다. 실제 메뉴 확대/실기기/Safari는 별도 수동 검사이며 미실행이면 그렇게 기록한다.


회전된 + 문자나 자식 SVG는 부모 rect 안에 있어도 화면 밖으로 그려질 수 있다. 열림·닫힘·복귀와 두 확대 방식에서 문자 Range와 필수 표식의 실제 경계를 함께 본다. [적용 근거](applied-evidence.md)와 visualBounds 계약으로 지정한 범위를 측정하고 pseudo/잉크·그림자는 수동 확인한다. 의도된 이미지 팬 영역과 일정 표식의 바깥 넘침을 같은 것으로 처리하지 않는다.

## 선택지와 모달의 내부 접근

좁은 화면에서 필수 선택지가 실제 옵션으로 남아 있는지 확인하고 선택값과 완료 결과를 대조한다. 긴 값을 화면에 보완 표시한 것과 실제 option 누락은 다른 문제다.

라운드 모달은 본문 영역만 이동하면서 레일이 상하 모서리를 덮지 않아야 한다. 글자만2배·글자/행간2배에서 하단 행동까지 실제 스크롤·클릭하고, 확대 이미지 팬 직후 닫기·재진입·키보드 복귀를 확인한다. 이미지의 의도된 내부 스크롤과 필수 본문 손실을 구분한다. 실기기 미실행은 브라우저 에뮬레이션 결과로 대신 인증하지 않는다. [모달 스크롤](dialog-scroll.md)을 참조한다.

## 필터와 재생성 이후의 검토

기본 화면 외에 필터1개/0개/복구와 새 결과가 생긴 상태를 본다. 같은 항목의 크기가 달라졌다면 의도된 강조인지 그리드의 빈 열 제거 때문인지 구분한다. 자동 높이 구역이 다음 구역을 밀어내는지 실제 클릭으로 확인한다.

모달 닫기는 전체 상자와 SVG/문자의 그림을 외곽 안에서 본다. 재진입 뒤 새 summary/오류 노드에도 같은 확대가 적용됐는지 확인한다. 확대 스타일 재적용 자체의 스크롤 초기화는 제품 동작의 성공으로 세지 않는다. [완료 게이트](delivery-gates.md)의 상태별 근거를 남긴다.
