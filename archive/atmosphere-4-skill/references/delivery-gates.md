# 표현 검토와 기능 완료의 게이트

표현은 여러 선택이 가능하지만 필수 옵션·현재 선택 결과·닫기·완료 행동에는 대체 가능한 실패가 없다. 검토 사이클이나 토큰 상한에 닿았다는 사실을 정상 동작의 근거로 쓰지 않는다. 시간이 부족하면 실패/미실행과 남은 조치를 밝힌다. 사용자가 동결 비교를 요청했을 때만 원본을 유지하고 별도 보완본을 만든다.

## 구현 초기에 확보할 관계

1. 요구에서 필드별 `selector / 상태 / value / 표시 문구 / 기대 결과`를 적는다. 구현된 options에서 기대 목록을 역생성하지 않는다. placeholder·disabled·중복·첫/마지막 값을 구분한다.
2. 단가·설명·선택 항목은 하나의 데이터 레코드에서 렌더링하고, 기대 계약은 별도로 유지한다. 데이터가 있는 앱에서는 options도 그 레코드로 생성한다. 작은 정적 select는 정상 시작/닫기 태그로 작성하고 파싱된 DOM을 검사한다.
3. 필터1개/0개/복구, 장문, 동적 모달 재생성을 첫 대표 화면에 포함해 본다. 겉모양이 완성된 뒤 처음 검사하지 않는다.

## 최종 편집 뒤 통과할 항목

| 게이트 | 실제 근거 | 통과로 대신할 수 없는 것 |
|---|---|---|
| 요구 → 파싱 DOM | 필수 값/문구/개수·중복 대조 | HTML 로드 성공, JS 구문 성공, 소스에 문자열 존재 |
| 각 필수 값 → 결과 | 분야별 초안, 날짜/시간/인원 확인, 금액/필터 결과 | 대표 값 하나의 완료, selectOption 값 변경만 성공 |
| 그룹/반복 목록 | 필터1개와 복구의 카드 폭·행동 축, 실제 첫 줄과 안내 묶음 위치 | 기본4폭의 문서 가로 넘침0 |
| 열린 상태와 확대 | 390/768에서 제목·닫기·본문·마지막 행동, 생성된 결과에도 확대 유지 | 닫힌 모달 검사, 배경 문서의 폭, 버튼 일부 좌표가 화면 안 |
| 실제 조작 | native 팝업 상태를 기록한 방향키/Enter/Escape/Tab, 닫기 후 초점 | 프로그램 값 설정, 키보드 순서가 잘못된 하네스의 실패/성공 |

선택지가 있으면 `audit-page.mjs --require-contract --contract <요구계약> --exercise-selects` 또는 동등한 검사를 실행한다. 이 도구는 DOM/값 선택까지만 검사한다. 결과 연결·제출·실제 키보드·모달은 프로젝트 동작 검사로 보완한다. 실행할 브라우저가 없으면 미실행이며 완료가 아니다.

선행 옵션 누락으로 여러 흐름이 막히면 원인 하나와 영향받은 검사 수를 구분한다. 누락을 고친 뒤에는 그 값의 결과·오류 복구·재진입까지 다시 실행한다. 스타일만 바꿔도 카드 열·모달 헤더·폰트에 영향이 있으면 해당 상태를 다시 확인한다.

## 확대 검사 자체의 유효성

글자만 확대와 고정된 기존 행간의 스트레스, 글자/행간 동시 확대, 실제 메뉴 확대를 구분한다. 새 결과/모달 노드를 생성한 뒤 기존 inline 확대가 사라졌는지 확인한다. 다시 확대하는 동작이 스크롤을0으로 만드는 등 검사에 간섭하면 기존/새 노드에 지속되는 테스트 CSS를 사용하고 방법을 기록한다. 어느 방법도 다른 OS·실기기 인증으로 바꾸지 않는다.

자체 작성 테스트의 사례 배열이 비었거나 필요한 폭/상태가 빠졌으면 통과시키지 않는다. 검사를 보정할 때는 기존 결과와 이유를 남기며 비교군 전체에 같은 기준을 적용한다.

작성자 보고와 중앙 계측이 다르면 폭·문구·폰트·selector·확대 주입 순서를 먼저 맞춘다. 검사기가 원래 행간을 px로 강제 고정한 스트레스만으로 단위 없는 행간 CSS의 오류를 단정하지 않는다. 정상 사용자 확대와 구분하고 검사에 맞추기 위한 임의 margin/중복 배율/!important 보정을 하지 않는다.
