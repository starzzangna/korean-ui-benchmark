# 자체 디자인 스킬의 목표와 수렴 원인

## 목표

한국어 사용자와 실제 브랜드의 내용을 해석해, AI가 기본 조건만 받았을 때보다 내용에 맞는 구도·사진 편집·조판·행동을 일관되게 제안하는 제작 스킬을 만든다. 특정 비교군과 다른 색을 쓰거나 장식을 늘리는 것을 목표로 하지 않는다. 기능 완성은 전제이며 디자이너의 편집 판단을 별도로 검토한다.

한국적이라는 표현을 단일 스타일로 정의하지 않는다. 자연스러운 한국어, 실제 상품·식사·방문·의뢰의 판단 맥락, 브랜드가 가진 내용과 자료가 화면에서 읽히는 것을 목표로 한다. 특정 서체·미색·모서리 반경을 적용한 것만으로 이 목표를 달성했다고 보지 않는다.

## 현재 결과가 비슷한 직접 원인

| 대상 | 구현에서 확인한 사실 | 해석 |
|---|---|---|
| SaaS 자체/no skill | [SaaS 렌더러](../src/saas-layout.mjs)의 두 조건이 같은 heading → overview → taskList 블록을 조합 | 자체 조건의 차이가 주로 스타일에 남음. 새로운 업무 정보 설계의 효과를 보여주기 어려운 비교 |
| 식당 자체/B | [대표 장면 렌더러](../src/category-scenes.mjs)의 두 조건 모두 같은 사진 → 같은 소개 블록을 사용. 최종 화면도 같은 사진 위 제목·행동 구도 | 색·글자 굵기를 제외하면 같은 장면으로 보이는 것이 자연스러움 |
| 전문 서비스 자체/B | 같은 렌더러에서 소개 → 같은 documentArt를 조합. [자료/본문 렌더러](../src/render.mjs)의 콘셉트 문서와 서비스 본문도 공통 | 우측 문서의 색·깊이 표현이 달라도 내용과 판단 순서가 같음 |

이것을 스킬 자체의 능력 차이로만 해석하면 안 된다. 전체 HTML/구간 구성을 공유한 구현 방식이 독립적인 편집 선택을 제한했다. 한 작성자가 전체 비교군을 제작했으므로 다른 안의 구성과 기존 피드백의 영향도 배제할 수 없다. 기존 비교는 결과 관찰 자료이며 스킬의 우월성을 입증하는 통제 실험은 아니다.

## 지침과 자료 측면의 원인

1. **개별 수정 요청의 일반화:** 사진 중심 식당, 우측 산출물, 승인한 앱 구도를 보존하는 요청이 반복되면서 재사용 지침의 중심이 됐다. 기존 화면 수정에는 적절하지만 새 제작의 기본형으로 가져오면 같은 결과가 반복된다.
2. **규정의 구체성 차이:** 정렬·옵션·확대 검사는 실행 가능한 반면, 브랜드의 첫 판단과 실제 자료를 편집하는 지시는 상대적으로 추상적이었다. 기능 검사 통과로 미적 완성도를 대신할 수 없다.
3. **자료의 제한:** 사진 세 장과 공통 개념 그래픽, 같은 소개 문장으로 여러 조건을 제작했다. 동일 자료도 편집할 수 있지만 실제 메뉴 사진·읽을 만한 산출물·브랜드 고유 내용이 없으면 정체성을 만들 여지가 줄어든다.
4. **검토 시점:** 전체 페이지를 만든 뒤 색·간격을 고치는 방식은 이미 고정된 정보 구조를 바꾸기 어렵다. 대표 구간과 다음 구간을 먼저 검토해야 한다.

## 이번 지침 수정

- 스킬의 시작점을 과업/정체성 브리프로 구체화했다. 방문 상황 → 첫 판단 → 근거 자료 → 다음 행동을 정하고 실제 구간에서 확인한다.
- 새 제작과 기존 수정의 보존 범위를 구분했다. 기능·사실은 유지하되 이전 구도를 자동 요구로 가져오지 않는다.
- 식당은 실제 식사 판단, 전문 서비스는 의뢰 상황·범위·증거, SaaS는 처리 단위와 정보 위계로 구성을 고르게 했다. 특정 사진 위 제목/우측 종이/상태 카드 구도를 업종 기본형으로 고정하지 않는다.
- [에셋 제작 요청서](../skills/korean-ui-design/assets/ASSET-BRIEF.md)에 대상·판단·촬영/문서 조건·크롭·사실성·권리·확보 전 대안을 남기게 했다. 라이선스가 있는 파일의 존재와 내용 적합성을 별도로 판단한다.
- 첫 화면과 다음 구간을 실제 자료로 먼저 구현하고 PC/모바일에서 검토한 뒤 확장한다. 현재 정렬·선택지·모달·키보드·확대·모션 감소 기준은 유지한다.

## 카테고리별 다음 제작에서 볼 것

| 카테고리 | 편집의 주요 판단 | 필요한 자료의 예 |
|---|---|---|
| SaaS | 비교/순차 처리/단계 이동 중 주 과업, 열 위계, 즉시 조작과 상세의 구별 | 실제 업무 필드와 긴 값·빈/오류 상태. 감성 사진 불필요 |
| 브랜드 | 사용 맥락과 상품 식별의 비중, 제품 선택 차이 | 제품 전체·소재·사용 장면 중 필요한 원본과 실제 규격 |
| 로컬 | 과정/공간의 인상에서 수업 차이와 일정 선택으로 연결 | 해당 수업의 과정·결과물, 제공된 방문 정보 |
| 식당 | 식사 인상/메뉴 비교/방문 조건 중 첫 판단 | 실제 메뉴와 대응하는 사진·가격·설명. 참고 상차림은 구분 |
| 포트폴리오 | 대표작의 감상 크기와 인덱스, 상세로 옮길 설명 | 작품 원본/세부와 실제 역할·범위 |
| 전문 서비스 | 의뢰 상황에서 범위와 산출물 판단으로 연결 | 읽히는 익명화 자료, 제공된 사례·관점·의뢰 조건 |
| 행사 | 참여 이유와 프로그램/일시의 읽는 순서, 중단 밀도 | 키비주얼 원문·실제 프로그램·참가 조건 |

이는 에셋 최소 개수나 레이아웃 할당량이 아니다. 없는 사실을 채워 넣지 않고 현재 자료로 가능한 범위를 선택한다. 모션은 대표 대상과 상태 변화의 연결을 돕게 하며 효과 수를 평가하지 않는다.

## 현재 내용으로 구체화할 수 있는 설계 예

- **아침정원:** 음식 사진의 인상을 보고 메뉴 이름·가격으로 내려가는 흐름과, 메뉴 비교를 먼저 읽고 상차림을 보조로 보는 흐름을 실제 콘텐츠로 검토할 수 있다. 제공 사진을 감자 수프 등 개별 메뉴의 실물로 표시하면 안 된다. 음식별 시각적 차이가 필요하면 실제 메뉴 사진이 추가로 필요하다.
- **정돈실:** 브랜드 진단·웹 서비스 기획·콘텐츠 정리는 각각 메시지·사용자 과업·읽는 순서라는 다른 판단을 제공한다. 이 차이를 의뢰 상황과 결과물로 먼저 읽히게 하는 구성을 검토할 수 있다. 같은 추상 문서를 모든 서비스의 대표 자료로 쓰는 것보다 내용이 구체적이다. 실제 사례가 없으면 개념 안내로 표시한다.
- **태스크링:** 좌측 탐색과 상단 대기·진행·완료 카드가 명시 요구라면 유지한다. 그 안에서도 업무명·상태·담당자·기한·완료 행동의 위계와 선택/상세 동작을 설계할 여지가 있다. 이를 색 차이만으로 해결하지 않으며, 차이를 만들기 위해 불필요한 요약/예정 업무를 다시 추가하지 않는다.

이 예는 다음 시안의 검토 방향이며 구현되거나 사용자 선호가 확인된 결과가 아니다.

## 다음 비교의 공정한 조건

비교 방식 두 가지를 분리한다.

- **지침 효과 비교:** 같은 사실·기능·에셋 풀·제작 예산을 제공하고, 각 조건의 정보 묶음·대표 장면·구간 편집을 독립적으로 결정한다. 상태 처리와 접근성 조작은 공유할 수 있지만 완성 히어로/페이지 레이아웃은 공통 렌더러로 고정하지 않는다.
- **전체 제작 방식 비교:** 에셋 선택/제작과 도구 사용까지 조건에 포함한다. 시간·비용·자료 차이를 기록하고 지침만의 효과라고 설명하지 않는다.

모든 조건에 같은 수정 기회와 요구를 제공한다. 최초 결과를 동결하고 사용자 피드백을 반영한 개선본은 별도로 둔다. 기존 비교를 본 작성자의 새 결과와 다른 맥락의 독립 생성을 같은 증거로 취급하지 않는다.

기능·모바일·정렬·확대·키보드·모션 검사는 필수 게이트다. 시각적 평가는 별도로 브랜드 식별, 정보 위계, 사진 적합성, 문단 밀도, 구간 연결, 행동의 자연스러움을 같은 PC/모바일 조건에서 본다. 조건명을 가린 선호와 이유를 기록하고, 새 브랜드/과업에서도 반복 확인한다. 다른 안과 다른 레이아웃을 만들었다는 사실만으로 우수 판정을 하지 않는다.

## 보존과 검증 범위

이번 변경은 스킬·가이드·템플릿에 한정한다. 기존 비교 화면·스크린샷·동결 기록을 수정하지 않는다. 지침을 개선했다는 사실과 실제 새 화면이 더 낫다는 결과는 구분한다. 새 생성과 사용자 검토 전에는 비교군을 능가했다고 주장하지 않는다.
