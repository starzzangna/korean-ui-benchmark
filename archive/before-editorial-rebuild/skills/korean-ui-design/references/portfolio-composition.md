# 포트폴리오의 목적과 작품 중심 구도

포트폴리오에서는 소개 문장·작업 이미지·탐색 중 무엇이 방문자의 첫 판단을 돕는지 먼저 정한다. 같은 제목과 같은 이미지도 면적·관계·등장 순서가 달라지면 인상이 달라진다. 기능과 모션 수만으로 이 결정을 대신하지 않는다.

## 나란히 비교하는 작업 카드의 정렬 계약

구현 전에 목록의 목적을 `동등 비교 / 의도한 비대칭`으로 정한다. 대표 장면의 겹침·기울임과 목록의 정렬은 별개다. 동등 비교로 선택한 행은 카드 외곽과 이미지 영역, 캡션·설명 읽기 축, 하단 행동을 맞춘다. 비대칭은 강조할 작업과 읽는 순서에 대한 근거가 있을 때 사용하고, 예전 CSS가 남아 좁아진 카드를 의도한 비대칭으로 해석하지 않는다.

- **폭과 배치:** 부모는 `repeat(2, minmax(0, 1fr))` 같은 명시적 열을 사용한다. 동등 비교 카드에는 `width:100%`, `min-width:0`, 같은 내부 여백을 적용한다. 항목별 개별 클래스의 백분율 너비·max-width·margin-left:auto·padding-top·grid-column을 실제 computed style로 점검한다. 부모 열만 같게 바꿔도 자식의 `width:76%`는 남는다. 카드 전체에 일괄 리셋하지 말고 해당 비교 행의 범위에서 해제한다.
- **이미지 영역:** 같은 행에서 비교할 때는 이미지 컨테이너 비율·안쪽 여백을 통일한다. 작품 원본 비율은 유지하며 조판·워드마크의 모서리를 자르는 cover 대신 contain을 우선 검토한다. 다른 비율의 원본은 컨테이너 안 여백으로 수용한다. 확대 뷰어는 썸네일 비율을 강제하지 않는다.
- **설명과 행동:** 캡션·제목·설명·관찰 정보·버튼을 같은 순서로 구성한다. 부모 stretch와 카드 내부 Grid/Flex를 함께 사용해 하단 행동을 정렬한다. 버튼만 absolute로 고정하거나 설명을 잘라 높이를 맞추지 않는다. 문장 길이가 다르면 필요한 경우 행을 공유하는 Grid/subgrid로 정보별 기준선을 맞춘다. 고정 높이·빈 문단·임의 spacer로 특정 문구에만 맞추지 않는다.
- **필터와 모바일:** 필터 전·필터 한 개·전체 복구에서 숨긴 카드가 레이아웃 공간을 차지하지 않는지 확인한다. 한 열에서는 인위적인 동일 높이를 풀고 자연스러운 내용 높이와 명시적인 카드 간격을 둔다. 두 열에서 한 열로 바뀌는 중간 폭도 검사한다.
- **Tailwind 사용 시:** 부모의 `grid-cols-2 items-stretch`만으로 완료하지 않는다. 카드의 `w-full min-w-0`와 내부 세로 흐름, 해당 이미지의 aspect/object-fit, 하단 행동의 배치를 함께 확인한다. 기존 클래스나 일반 CSS가 적용한 너비·위치가 우선하는지도 검사한다. 원래 스택에 Tailwind가 없으면 설치하지 않는다.

### 최초 제작 검수

폰트와 실제 이미지가 로드된 뒤 PC·중간 폭·모바일에서 작업 목록 자체를 확인한다. 페이지 상단 캡처나 가로 넘침 검사만으로 끝내지 않는다. 지연 로드 이미지는 먼저 화면에 진입시킨 다음 로딩을 확인한다.

동등 비교 행은 카드 좌우 폭, 외곽 상·하단, 이미지 영역, 캡션·설명 제목·행동의 y 좌표 중 DESIGN.md에서 맞추기로 한 기준을 비교한다. 정지 상태에서 같은 상자 기준의 차이 약1 CSS px 이내를 실측 목표로 삼고 실제 글리프·여백은 화면으로도 확인한다. hover·등장 중의 transform 값을 정지 레이아웃 결함으로 판정하지 말고 종료·복귀 후 다시 측정한다. 기울어진 대표 장면에는 이 정렬 목표를 강제하지 않는다.

한 카드의 설명을 더 긴 한국어 문장으로 바꿔 보아 잘림·버튼 겹침·가로 넘침이 없는지 확인하고, 테스트 문구는 저장하지 않는다. 의도적으로 기준선을 달리했다면 어떤 과업을 돕는지 남긴다. 기능 검사에서는 필터·이미지 상세·확대·키보드·초점 복귀가 유지되는지 따로 확인한다.

## 목적 선택

스튜디오 인상을 먼저 원하면 대표 작업의 앞뒤·크롭·색 관계로 소개 장면을 구성하고, 중단에서 그 작업을 볼 이유를 제공한다. 제목과 분야만 반복한 썸네일 목록으로 끝내지 않는다. 제공된 작업 설명·목표·전체/세부 이미지에서 `작업 의도 / 핵심 판단 / 관찰할 세부`를 짧게 편집한다. 자료가 부족하면 확인된 의도만 쓰고 가짜 고객·성과·수정 전후를 만들어 사례 연구처럼 포장하지 않는다.

한 대표 작업을 조금 깊게 소개한 뒤 다른 작업의 비교·필터·전체/세부 탐색으로 연결할 수 있다. 대표 장면의 합성·겹침 이미지와 상세 원본의 전체 보기는 역할을 구분한다. 모바일에서 핵심 글자와 작품 모서리를 잃지 않고 직접 상세로 들어갈 수 있어야 한다.

| 목적 | 적합한 요청 | 첫 화면과 다음 정보 |
|---|---|---|
| studio · 스튜디오 소개형 | 작품을 통해 분위기·분야·역량을 보여주고 싶음 | 식별 가능한 대표 작업과 짧은 소개를 함께 편집 → 실제 작업 목록/상세 |
| gallery · 작품 감상형 | 한 작업의 이미지·세부를 크게 감상 | 짧은 소개와 큰 작품 → 캡션·전체/세부 탐색 |
| archive · 빠른 탐색형 | 작업이 많고 분야·연도·유형별로 찾아야 함 | 분류·이름·메타데이터와 썸네일 → 해당 상세 |

사용자가 스튜디오 인상을 선호한다고 밝혔으면 studio를 우선 검토한다. 모든 포트폴리오를 같은 콜라주로 만들지는 않는다. ‘깔끔함’만 주어진 경우 자료와 방문자의 과업으로 판단하고 이유를 DESIGN.md에 남긴다.

한 작품의 몰입과 여러 작업의 비교는 다른 목적이다. 감상형은 한 작업의 면적·원본/의도된 크롭·다음 작품의 진입을, 탐색형은 작업 간 구별·분류·캡션의 가까움을 우선한다. 밝은/어두운 면이나 첫 이미지의 y 좌표만으로 우열을 판정하지 않는다. 사용자가 두 방식을 비교하고 싶다면 실제 갤러리 보기 전환을 제공할 수 있지만 모든 완성 사이트에 설정 UI를 강제하지 않는다. 제품 브랜드의 촬영 통일감과 달리 포트폴리오의 서로 다른 작업 표현은 보여줄 자산이다.

## 작품을 먼저 편집하기

studio의 후보는 큰 한 작업+보조 작업, 서로 다른 두 작업의 전후 관계, 화면 한쪽을 채운 대표 작업과 짧은 색인 등으로 비교할 수 있다. 자료의 성격과 모바일 재구성이 달라야 별개 후보다. 작품 이미지에 글자가 있다는 이유만으로 대표 작품을 뒤로 보내지 말고, 소개의 크기·분리 공간·작품 배율을 함께 조정해 본다.

먼저 대표 작업을 식별 가능한 크기로 놓고 제목·설명·CTA의 면적을 조정한다. 스튜디오 소개형의 제목은 데스크톱 약56~76px 같은 범위에서 시작할 수 있으나 글자 수·폭·작품에 맞춰 바꾼다. 크기는 의무값이 아니며 제목 중심 포스터가 목적이라면 다른 선택이 가능하다. 작은 글자가 보이는 썸네일을 무조건 읽게 만들지 않는다.

두 작업을 겹칠 때는 주인공/보조, 색·재료·분야의 관계가 보여야 한다. 앞 작업이 뒤 작업의 핵심을 가리지 않게 하고, 이미지 주위 프레임·얇은 선·그림자는 실제 분리와 깊이를 돕는 만큼만 쓴다. 배경과 행동색은 작업의 색을 보존하며 연결한다. 어두운 면·연두색·궤도·기울기를 세트로 고정하지 않는다.

## 구도와 연결한 움직임

정지 화면에서 구도가 성립한 뒤 [scene-motion.md](scene-motion.md)의 장면 역할을 연결한다. 앞뒤 레이어는 바깥 등장 wrapper와 안쪽 프레임을 나누고 필요하면 짧게 시차를 둔다. 프레임 자세를 정돈하는 hover는 선택 사항이다. translate만 아무 이미지에 붙인 것으로 대표 장면의 편집을 완료하지 않는다.

대표 작품을 누르면 실제 작업 상세에 도달한다. hero의 대표 작업과 필터된 목록의 범위가 다를 때는 선택한 작업을 안전하게 열고 현재 범위/필터 변경을 알린다. 목록의 필터·이전/다음은 그 목록의 범위를 존중한다. 두 개의 이미지 버튼이 겹쳐 조작을 가로막지 않게 한다. 키보드 초점·모바일 tap·닫은 뒤 원래 위치 복귀를 유지한다.

## 모바일과 확대

데스크톱의 크기와 회전을 그대로 축소하지 않는다. 작은 화면에서는 제목·작품·행동이 함께 읽히도록 작품의 비율과 겹침을 다시 배치한다. 작업 캡션과 날짜/분야는 잘리지 않아야 한다. 320·390·768·1440px에서 실제 경계를 확인한다. CSS scale은 레이아웃 너비를 줄여주는 도구가 아니다.

글자 확대에서는 제목·메타데이터·CTA를 재배치하고 고정 높이를 풀 수 있어야 한다. 문서 overflow:hidden으로 글자 손실을 감추지 않는다. 작품 내부의 의도된 이미지 크롭과 본문/초점의 잘림은 구분한다. 모션 감소에서는 레이어 관계와 탐색이 정지 상태로도 유지된다.

## 실제 화면 비평

- 첫 화면만 보고 무엇을 만드는 스튜디오인지 실제 작업으로 알 수 있는가?
- 제목과 작품의 크기 관계가 이번 목적에 맞는가? 큰 제목만 남고 작품이 화면 아래로 밀렸는가?
- 앞뒤·작품 간 대비가 자료에서 나오며 불필요한 장식을 빼도 구도가 남는가?
- 대표 행동은 명확하고 작품을 눌렀을 때 기대한 상세가 열리는가?
- 모바일에서 대표 장면이 새로 편집됐고 상세·확대·초점·모션 감소가 동작하는가?

관찰한 화면과 선택 이유를 기록한다. 특정 구도·색상·기울기를 썼다는 이유만으로 우수하다고 판정하지 않는다.


[실제 적용 확인](applied-evidence.md)에 작품 감상 크기와 설명 위치의 최종 화면을 남긴다. 나란히 카드 축을 맞춘 다음 실제 원본을 보며 열 수를 결정한다. 작은3열에 설명을 더해 작품이 읽히지 않는 문제를 대신하지 않는다. 반복 관찰은 상세에 두고 작품/원본 탐색은 유지한다.
