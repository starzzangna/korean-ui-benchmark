# DESIGN.md — 프로젝트 설계 기준

현재 조건→선택한 관계/구현→실제 검증을 기록한다. 해당하는 항목만 남기고 빈 표·안내 문장은 제거한다. 예제의 색·수치·문구를 프로젝트 기본값으로 복사하지 않는다. 문서 링크는 복사한 위치에 맞춰 조정한다.

## 목적과 요구

- 제작 유형: 새 제작 / 기존 화면 수정. 현재 보존할 명시적 요구와 이전 프로젝트에서 가져오지 않을 구도를 구분한다.
- 제작 브리프: `방문 상황 → 첫 판단 → 이 브랜드의 근거 자료 → 다음 행동`을 한 문장으로 적는다.
- 표현의 원리: 이 내용을 읽게 할 사진 거리·정보 묶음·조판·구간 리듬은 무엇인가? 추상 형용사나 팔레트 이름만 적지 않는다.
- 대상 사용자·주요 과업·먼저 전달할 내용
- 제공된 사실/자료·기능·스택·연동/데모 범위
- 현재 프로젝트에서 유지할 기능·브랜드 규칙과 변경할 범위
- 선택한 구성과 이유, 다른 구도를 제외한 조건
- 첫 섹션에서 동시에 읽을 문구·자료·행동과 감상이 먼저 필요한 자료
- 좌우 병치/장면 우선/적층을 선택한 콘텐츠 근거, 폭과 높이가 필요한 이유
- PC에서 자료 식별·첫 행동·다음 정보의 진입 위치와 모바일 재배치 결과
- 상단 각 열의 실제 정보량/높이, 불필요한 빈 공간과 정보 재배분의 결과

구도 후보를 작성하기 위한 후보나 고정 면적 비율은 추가하지 않는다. 전폭/전체 높이가 필요 없다면 쓰지 않으며, 좌우 병치가 자료 가독성을 해치면 다른 관계를 선택한다.

첫 화면과 바로 다음 구간을 실제 자료로 먼저 구현한다. PC/모바일에서 대상 식별·읽는 순서·다음 행동을 확인하고 채택/재편집 이유를 남긴다. 다른 안과 비슷해도 내용에 가장 적합하면 채택할 수 있다. 색·굵기만 다른 안은 구조가 같은 것으로 기록한다.

식당 등 사진으로 먼저 판단하는 페이지는 문구 안전 영역과 대표 대상의 식별이 확보될 때 사진 위 제목·행동 배치를 선택할 수 있다. 모바일에서 둘을 함께 확보하기 어려우면 사진과 텍스트를 적층한다. 사진에서 메뉴·예약으로 이어지는 배색, 음식 크롭, 문구 대비, 글자 확대 후 높이 증가를 기록한다.

| 구간 | 주인공·읽는 순서 | 새로 얻는 정보 | 관련 행동/결과 | 모바일 재배치 |
|---|---|---|---|---|

사진/작품은 프레임 크기와 실제 피사체 크기를 따로 확인한다. 대표/목록/상세에서 같은 자료를 쓰면 새로 보여줄 전체·세부·쓰임을 적는다. 색인은 표시한 항목과 실제 열린 대상/필터/선택값이 일치하는지 기록한다. 중복된 색인·필터·메뉴 예고는 각각 다른 판단을 돕는 경우에만 유지한다.

업무 앱의 보조 요약·소개 페이지의 긴 장식 구간은 실제 판단에 필요한지 설명한다. 반복 설명과 빈 공간을 채우기 위한 요소는 줄인다.

## 색·조판·자료

바탕의 온도·명도와 보조 면·강조 면적을 함께 선택하고 브랜드/사진/주요 과업의 근거를 적는다. 공통 크림 바탕에 버튼색만 바꾸지 않는다. 브랜드 근거가 없으면 중립 바탕을 먼저 검토하고, 확정한 역할색을 실제 CSS 토큰·구간·모달에 대조한다. 여러 사이트의 색 차이를 위해 업종별 고정색이나 임의 팔레트를 강제하지 않는다.

기본 서체는 한글·영문·숫자 모두 Pretendard이며 제목·본문·버튼·input·select·textarea에 일관되게 적용한다. 실제 폰트 파일과 라이선스를 제공하고 로딩 후 적용을 확인한다. 별도 서체는 사용자 요청이나 확정된 브랜드 규칙이 있을 때만 적용 범위와 이유를 기록한다.

소개형 페이지의 첫 섹션 대표 제목은 Pretendard 700에서 시작해 본문·보조 제목과 굵기 차이를 만든다. 실제 선택한 굵기와 예외 이유를 기록하고 모바일 줄바꿈·200% 글자 확대에서 잘림과 겹침이 없는지 확인한다. 업무 앱 제목은 화면 밀도에 맞춰 별도로 판단한다.

| 역할 | 실제 선택·값 | 내용/브랜드에 맞는 이유 |
|---|---|---|
| 페이지 바탕·대표·목록·선택/완료 면 | | |
| 본문·보조·행동·선택·오류 | | |
| 한글·라틴·숫자 서체/굵기·로딩/제공 방식 | | |
| 제목·본문·메타의 위계·행간·줄바꿈 | | |
| 컨테이너·간격·프레임/반경 | | |

| 실제 에셋 | 식별할 대상/용도 | 출처·권리·해상도 | PC/모바일 크롭·안전 영역 | 연결된 정보/행동 |
|---|---|---|---|---|

실제 제품/매장/작업 자료와 분위기 참고·개념 그래픽을 구분한다. 대표/목록/상세에서 같은 자료를 재사용하면 새 정보와 이유를 적는다. 부족한 자료·필요한 촬영·표현하지 않을 사실도 기록한다.

부족한 자료가 구도를 좌우하면 [에셋 요청서](ASSET-BRIEF.md)를 작성한다. 필요한 장면·연결 행동·촬영/문서 조건·PC/모바일 크롭·권리·확보 전 대안을 남긴다. 확보하지 않은 자료를 확보한 것으로 쓰지 않는다.

## 정보 묶음과 정렬

목록의 목적을 `동등 비교 / 의도한 비대칭`으로 정한다. 동등 비교는 카드 폭·이미지 영역·캡션·제목·행동 중 맞출 축을 적고, 비대칭은 강조 대상과 읽는 순서를 설명한다. 열 수/비율은 실제 자료와 화면 폭으로 결정한다.

| 대상·폭 | 카드/행·정보/행동 기준선 | 한 열·긴 문구·필터 후 배치 | 실제 화면 근거 |
|---|---|---|---|

| 요소 | anchor/group/icon/text selector | PC·모바일 가로 배치 | 세로 중앙/첫 줄 | 기본·두 확대 결과 |
|---|---|---|---|---|

내부 아이콘/문구와 묶음 전체 위치를 따로 확인한다. 상자 수치와 실제 글리프/선의 광학 판단을 구분한다. 고정 높이·잘림으로 정렬을 위장하지 않는다.

## 장면·조작·상태 동작

| 대상·계기 | 즉시 바뀔 정보/행동 | 장식 거리·자세·시간·끝 상태 | 중단/왕복·터치·키보드·모션 감소 |
|---|---|---|---|

SCENE_MOTION과 CONTROL_MOTION은 서로 다른 역할이다. 정적 구성이면 이유를 적는다. 등장/회전/이미지 확대 레이어를 나누고 기능을 장식 종료까지 지연하지 않는다. 사용하는 구현 파일·외부 의존성·폰트/에셋 용량을 기록한다.

## 조작과 복구

| 주요 흐름 | 입력/선택 | 로딩·빈 결과·오류·수정·재시도 | 완료 결과·키보드/초점 |
|---|---|---|---|

native select의 필수 옵션은 요구 자료의 값/문구/개수와 실제 파싱 DOM을 대조한다. 작품/상품 상세는 선택한 대상·필터 범위·전체/세부·확대/맞춤·닫기 복귀 중 필요한 기능을 확인한다. 입력과 동적 결과는 안전한 문자로 표시한다.

## 모바일과 확대

| 화면·폭·상태 | 원래 글자 / 글자만2배 / 글자+행간2배 / 메뉴 확대 | 문서 넘침 | 내부 잘림·고립 글자·선택값·회전/초점 | 수정·미충족·미실행 |
|---|---|---|---|---|

320/390/768/1440과 필요한 중간 폭에서 최종 폰트·이미지를 로드하고 실제 화면을 본다. 고정 행간 스트레스와 일반 글자 확대, 의도된 이미지 이동과 필수 내용 잘림을 구분한다. 회전은 초기/열림/닫힘/복귀 및 필요한 중간 상태를 본다. viewport 가로와 부모 양축 등 경계가 다른 계약을 같은 점수로 비교하지 않는다.

## 실제 적용과 전달

| 기대 관계 | 최종 DOM·자료·상태 | PC/모바일 화면·실제 조작 근거 | 통과/미충족/대체/미실행·이유 |
|---|---|---|---|

[적용 확인](../references/applied-evidence.md)·[모바일 검토](../references/mobile-review.md)에서 해당 관계만 선택한다. 지침을 읽거나 클래스가 존재한다는 사실로 완료를 판정하지 않는다. 기능·가로 넘침·광학 정렬·시각적 선호는 다른 축이다.

실행 명령·대상·결과·남은 제한을 기록한다. 일반 제작은 수정 후 다시 검사하며, 동결 비교를 요청받은 경우 원본과 후속 개선을 분리한다.


## 나란한 폼과 경계 역할이 있을 때

- 같은 행 selector와 공유 크기 토큰(font/line-height/border-box/padding/min-height 또는 확대 가능한 높이), label→입력/필드 간 간격, 모바일 재배치
- 실제 폰트 로드 후 조작 상자의 높이·top/bottom 차이, 오류·긴 값·글자 확대 결과
- separator와 control-border의 실제 값·인접 바탕·선택/오류/초점 대비, 사진/본문보다 먼저 보이지 않는 장식선의 강도

위 항목은 해당 폼/경계가 있을 때 작성하며 서로 다른 역할의 CTA·한 열 입력을 일괄 같은 크기로 만들지 않는다.


셀렉트가 있다면 실제 select selector, 화살표 wrapper/크기/우측 여백/문구 안전 영역, 고대비 대체 표시와 disabled/오류 상태를 기록한다. 기본·모바일·두 글자 확대의 측정값과 실제 키보드 선택/change 결과를 구분한다.

## 선택지·상세 모달이 있을 때의 완료 계약

| 필드의 역할·selector·상태 | 요구 자료에서 정한 필수 값/문구·개수 | 파싱 DOM의 사용 가능 항목·누락/중복 | 필수 값별 연결 결과·오류 복구 | 실제 키보드·근거 |
|---|---|---|---|---|

선택지 계약을 구현 options에서 자동 생성하지 않는다. 요구→DOM→각 값의 결과를 대조하고 미선택 오류 후 완료를 확인한다. 비슷한 라벨의 필터와 신청/문의 필드를 구분한다. 대표 한 분기나 JS 구문 검사로 전체 완료를 대신하지 않는다.

| 모달 외곽·본문·이미지 이동 영역 | 높이 제한·라운드·레일/손잡이·고대비 | 짧은/긴 내용·PC/모바일·두 확대 | 최하단 실제 행동·키보드·닫기/재진입·초점 복귀 | 화면/조작 근거·미실행 |
|---|---|---|---|---|

외곽 클리핑은 내부가 실제로 스크롤될 때 적용한다. overflow:hidden으로 필수 내용을 숨기지 않는다. [모달 구현 기준](../references/dialog-scroll.md)과 [실행 예제](dialog.html)를 필요한 부분에 적용하고 기존 Dialog 컴포넌트·브랜드 토큰을 우선한다.

## 편집 후 완료 게이트

| 구간 | 먼저 읽을 대상 하나 | 덜어낸 반복 설명/장식과 이유 | PC/모바일 실제 판단 |
|---|---|---|---|

| 필수 요구·상태 | 최종 파일 검증 시점/명령 | 기대 사례 수·실행 수 | DOM/각 결과/키보드·확대 | 실패 원인·재검사·미실행 |
|---|---|---|---|---|

필수 선택지·가려진 행동·닫기/완료 실패를 표현 검토 횟수로 종료하지 않는다. 요구 계약은 구현에서 역생성하지 않고 최종 편집 뒤 파싱 DOM과 각 값의 결과를 대조한다. 필터1개·동적 모달 재생성·첫 줄 행간/긴 제목 확대도 대상에 포함한다. [완료 게이트](../references/delivery-gates.md)를 따른다. 동결 비교는 원본과 후속 수정/검증을 분리한다.

## 표현 변경의 영향 범위가 있을 때

| 변경 대상 | 부모 배경/gap/자식 면·최종 버튼 변형 | 중간 폭의 정보/행동 묶음·공통 열 | 유지 대상과 실제 대조 |
|---|---|---|---|

첫 화면의 자료·행동은 폭과 높이를 함께 기록한다. 목록 비교는 필터/열림 상태를 맞춘다. 색·한 속성만 바뀌었다는 이유로 기존 padding/반응형 규칙의 적합성을 가정하지 않는다.

인접 섹션을 조정했다면 장면의 끝→다음 제목의 실제 간격, 구간 전환을 알리는 수단과 이유를 기록한다. 개념 문서가 있다면 메타·제목·단계·판단의 읽는 순서와 프레임/표식의 역할을 기록하고, 실제 자료와 개념 표현을 구분한다.

구간 경계를 수정할 때는 분리할 두 묶음과 경계 위치(앞/뒤/내부)를 명시한다. 사진 캡션·다음 행동 안내·일정처럼 역할이 다른 내용을 구분하고, 묶음 아래 경계선으로 묶음 위쪽 혼동을 해결했다고 판정하지 않는다.
