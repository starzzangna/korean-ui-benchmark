# 시각 방향을 실제 화면에서 검토하기

## 구현 전에 남길 짧은 결정

콘텐츠가 중심이 되는 한 문장으로 시작한다. ‘프리미엄하고 깔끔한 식당’ 대신 ‘제공된 음식 사진의 접시 배열과 네 메뉴의 가격 비교를 중심으로 읽는다’처럼 주제의 구체물을 쓴다. 자료가 없으면 확인되지 않은 사실로 채우지 않는다.

구성 후보는 색·자간만 다른 버전이 아니라 첫 화면의 대상·탐색 방식·내용 순서가 다른 안으로 비교한다. 선택한 안에 대해 다음 다섯 항목을 실제 값으로 확정한다.

1. 첫 화면의 주인공과 핵심 행동: 사진, 메뉴, 작업물, 일정, 업무 목록 등.
2. 대표 제목·본문·숫자의 역할과 실제 제공할 서체·굵기.
3. 바탕·본문·강조의 역할과 넓은 면의 사용 이유. 카테고리별 고정색으로 결정하지 않는다.
4. 섹션별 새로운 정보와 구성: 매 섹션을 같은 카드로 만들거나 다르게 보이려고 매번 모양을 바꾸지 않는다.
5. 모바일에서 유지할 우선순위와 줄어들거나 사라질 보조 요소.

업무 앱에는 이 소개 페이지 구성을 강제하지 않는다. 검색·대기열·목록·다음 행동이 먼저다. 단일 컴포넌트 수정에도 전체 랜딩 재설계 절차를 강제하지 않는다.

표현 중심 페이지는 [구도](hero-composition.md)와 [표현의 연결](visual-coherence.md)을 함께 검토한다. 가능했던 분할 외 후보가 실제 다른 읽기 순서를 갖는지, 선택한 사진/작품과 문자 면적이 맞는지, 프레임·그림자·버튼의 언어가 이어지는지 본다. 정지 화면과 주인공의 반응을 원래 크기에서 확인한다. CTA의 작은 이동만 검사하고 대표 사진/작품의 선택 반응을 완료 처리하지 않는다. 관련 이미지나 반응이 없는 과업에는 적용하지 않는다.

## 내용이 빈약해지지 않는 장식 검토

장식을 없앤 자리에 같은 제목과 큰 빈 공간만 남기지 않는다. 확보한 작업·가격·일정·제품 화면·설명 중 방문자가 필요한 정보를 가져온다. 실자료가 부족하면 더 짧은 페이지도 적합하다. ‘고급’ 인상을 위해 허위 실적·후기·로고·숫자로 채우지 않는다.

섹션을 한 화면씩 보면서 무엇을 새롭게 알게 되는지 확인한다. 같은 말을 반복하는 소개, 읽을 정보 없는 과도한 여백, 첫 과업을 밀어내는 거대한 도식·포스터를 재검토한다. 의도적인 여백·브랜드 포스터는 가능하되 실제 탐색과 읽기 순서를 설명할 수 있어야 한다.

## 검사와 비평을 분리

브랜드 소개에서는 [대표 장면](brand-scene.md)의 검토 기준으로 정돈·대표성·사진 통일감·다음 과업을 따로 본다. 감상형과 탐색형처럼 목적이 다른 선택을 하나의 승패로 합산하지 않는다. 같은 확대율/감속 곡선이어도 움직이는 대상의 프레임·크롭·앞뒤 관계가 다르면 인상이 달라진다. 조판과 장면을 보지 않고 모션 수치만 조정해 해결하려 하지 않는다.

모션의 표시 효과를 검토할 때는 효과의 존재뿐 아니라 **사용자가 보는 표시 배율**을 확인한다. iframe/캔버스를 20%로 축소하면 2px translate는 화면상 약 0.4px다. computed transform 통과만으로 체감 품질을 완료 처리하지 않는다. 원래 크기에서 hover/클릭/스크롤 전후 화면 좌표, 실제 모션 감소·hover 지원, 전환 시간과 위치를 확인한다. 비교용 축소 프레임에는 단독/실제 크기 보기와 효과 위치 안내를 제공하고, 축소를 보상하려고 제품 자체 효과를 과장하지 않는다.

| 축 | 확인할 근거 | 결과 해석 |
|---|---|---|
| 기능·기본 UI | 흐름, 오류 복구, option, 조작 높이, overflow, 이름, 초점, 실제 사용 서체 | 재현 가능한 오류와 통과 범위를 기록 |
| 정보 발견 | 같은 과업을 수행한 사람의 정답·막힌 지점, 화면 내 배치 | 문서 y 좌표만으로 이해 속도를 대체하지 않음 |
| 시각적 완성도 | 대표성, 조판, 위계, 내용의 충분함, 사진 크롭, 화면 간 일관성 | 관찰·평가자·조건 인지 여부를 기록 |
| 표현 다양성 | 제목·사진·탐색·섹션 구성의 실제 차이 | 색만 다른 화면을 별도 방향의 성과로 세지 않음 |

여러 사이트를 만들 때 이미 비슷한 명조·아치·별표·종이 도식·크림/녹색 조합을 반복했다면 콘텐츠에 맞는 다른 구성을 검토한다. 특정 색·서체를 전면 금지하는 새 고정 스타일로 바꾸지는 않는다. 독립 실험 작성자에게는 이전 결과를 보여주지 않고, 반복성 검토는 제출 후 평가 단계에서 한다.

## 화면 검토 순서

간결함만 확인하지 않는다. 브랜드·매장·전문 서비스는 ‘대상은 명확하지만 누구의 사이트인지 기억할 장면이 없는가’를 함께 본다. 사진 거리의 변화, 실제 산출물, 주제에 맞는 조판 중 자료로 가능한 해결을 선택한다. 목록을 무조건 아래로 밀거나 포스터·모션을 의무 추가하는 뜻은 아니다. [art-direction-and-assets.md](art-direction-and-assets.md)에서 해당 업종의 표현과 자료 요건을 함께 확인한다.

일반 제작에서는 다음 출고 기준을 실제 화면으로 확인한다. 각 항목에 관찰한 화면과 이유를 적고 `확인 / 수정 필요 / 확인 불가`를 구분한다. AI가 임의 점수를 합산해 품질을 인증하는 절차가 아니다.

| 기준 | 확인 질문 | 수정이 필요한 예 |
|---|---|---|
| 주제 적합성 | 이름을 가려도 무엇을 제공하는지 콘텐츠로 알 수 있는가? | 카페·법률·SaaS에 같은 추상 도형과 감성 문구 |
| 정보 위계 | 가격·일시·작업·다음 행동 등 핵심 과업에 바로 접근하는가? | 큰 소개·포스터가 실제 정보를 여러 화면 아래로 밀어냄 |
| 조판 | 실제 서체로 제목·본문·숫자의 위계와 자연스러운 한글 줄바꿈이 보이는가? | 모든 제목을 초대형으로 처리, 영문 장식만 먼저 읽힘 |
| 에셋 편집 | 사진·작업물·UI가 실제 내용을 설명하며 필요한 세부를 볼 수 있는가? | 잘린 제품, 읽을 수 없는 UI, 작은 이미지에 hover만 제공 |
| 일관성과 개성 | 한 프로젝트 안의 규칙이 일관되고 콘텐츠에서 나온 특징이 있는가? | 모든 영역을 카드로 분해하거나 구역마다 다른 스타일을 추가 |
| 모바일과 동작 | 좁은 화면에도 우선순위·크롭·선택·복구·초점이 유지되는가? | 데스크톱 두 열을 그대로 쌓아 중복 이미지·빈 공간이 늘어남 |

`수정 필요`인 근거를 모아 영향이 큰 문제 세 개 이내부터 고친다. 먼저 정보·구도·사진 크롭을 해결하고, 그다음 글자·간격·선·상태를 다듬는다. 문제를 해결하지 않은 채 그림자·hover·모션만 추가하지 않는다. 도구 없이 본문만 검토했다면 브라우저 검수를 완료했다고 말하지 않는다.

- 서체 로딩을 확인한 실제 배포 결과를 390·768·1440px에서 본다. 제목 크기와 줄 수, 본문 대비, 콘텐츠의 충분함, 사진·도식의 역할, 다음 행동 순으로 살핀다. 자동 검사 숫자만 보고 화면을 건너뛰지 않는다.
- 기능 검사·실제 폰트·overflow 검사를 통과해도 미적 품질이 입증되지는 않는다. 점수를 만든다면 축·평가자·근거를 공개하고 스스로 준 점수를 사용자 선호처럼 보고하지 않는다.
- 최종 편집 후 필수값 기대 계약과 실제 DOM을 새로 대조한다. 콘솔 오류가 없어도 잘못된 HTML의 브라우저 복구로 option이 사라질 수 있다. 실행 명령이 같아도 수정 전 파일을 본 결과는 최종 제출의 증거가 아니다. [browser-audit.md](browser-audit.md)의 도구를 선택적으로 사용한다.
- 일반 제작·개선에서는 관찰한 상위 문제 세 개 이내를 정해 수정하고 같은 너비에서 다시 본다. 추가 개선은 새 실패나 미해결 문제가 있을 때 진행한다. 별도 이미지·애니메이션 서비스를 필수로 만들지 않는다.
- 최초 제작 비교에서는 제출 전 자체 검토의 허용 범위를 양쪽에 동일하게 사전 지정한다. 제출 동결 후에는 화면의 문제도 결과로 보존한다. 수정본이 필요하면 별도 폴더·평가로 분리한다.

화면 목적에 맞는 정보·조판·사진·동작을 근거로 검토한다. 사용하지 않은 도구를 실행했다고 보고하지 않는다. 모션 수·자간·특정 색의 사용 유무만으로 품질을 판정하지 않는다.

## 장면과 조작의 분리 검토

상단·중단·하단을 각각 `유지 / 수정 / 확인 불가`로 기록한다. 사용자에게 좋다는 평가를 받은 구간은 기능·가독성 문제가 없으면 유지하고 다른 구간을 보완한다. 한 화면의 선호를 페이지 전체의 승패로 확대하지 않는다.

- 상단: 주제·대표 자료·핵심 행동이 연결되는가? 제목·로고가 콘텐츠를 과도하게 밀어내지 않는가?
- 중단: 항목의 시작과 끝, 서로 다른 점, 현재 선택, 다음 행동을 구별할 수 있는가? 수업·메뉴·프로그램은 실제 비교 과업으로 검토한다.
- 포트폴리오 중단: 제목·분야 외에 제공된 작업 의도·핵심 판단·볼 세부가 있는가? 가짜 성과 없이 관찰 동기를 줄 수 있는가?
- 하단: 신청·문의가 앞의 내용에서 이어지는가? 새 정보 없는 대형 로고·반복 문구가 한 화면을 차지하지 않는가?
- 전체: 넓은 배경색을 나란히 봤을 때 같은 브랜드인가? 특정 구간에만 등장하는 고채도 색의 근거가 있는가?

390·1440px에서 전체 페이지와 각 구간의 실제 크기를 함께 본다. 전체 축소본은 배색·면적·리듬, 실제 크기는 글자·항목 구분·아이콘·선택 상태·조작을 검토한다. 구간의 문제가 남아 있으면 작은 hover나 큰 제목을 더하기 전에 내용과 구성을 조정한다.

스튜디오 소개형 포트폴리오에서는 작업이 첫 화면의 주인공인지, 제목 크기와 여백이 작품을 뒤로 밀지는 않았는지 먼저 본다. 프레임·깊이·작품의 색 관계가 정지 화면에서도 성립해야 한다. [portfolio-composition.md](portfolio-composition.md)의 목적별 질문을 선택하고, 구도 문제를 작은 hover나 새 배경색만으로 해결했다고 보고하지 않는다.

대표 사진·작업·포스터의 구도와 진입 리듬이 콘텐츠를 설명하는지 실제 크기로 본다. SCENE_MOTION을 calm으로 정했다면 대표 장면에서 그 움직임이 실제로 보이는지 확인하고 작은 CTA hover만으로 완료 처리하지 않는다. 정적인 선택은 자료·브랜드·사용자의 조건으로 설명한다. 동시에 필터·시간표·폼은 즉시 조작되고 전체가 흔들리지 않는지 본다.

320/390/768/1440과 200% 글자 확대에서 제목·날짜·버튼·회전 프레임의 경계를 확인한다. 태블릿에서 CSS scale로 시각 크기만 줄이고 문서 스크롤 너비를 놓치지 않는다. 콘텐츠의 잘림을 문서 overflow:hidden으로 감추지 않는다. 모션 감소 초기/실시간 변경·JS 차단·터치·키보드의 핵심 동작을 검토한다. 검사기의 종료0과 세부 항목의 전부 통과는 구분한다.

## 기능이 정상이어도 남는 시각 비평

각각 실제 화면과 이유를 남긴다: 주인공/보조의 시선 순서, 대표→중단→마무리의 새 정보, 사진 재사용의 의미, 모바일에서 남은 피사체, 선택과 결과의 관계. ‘정렬됨’과 ‘이 브랜드로 기억됨’을 별도 판단한다. 모든 항목을 임의 숫자로 합산해 스킬 승리로 보고하지 않는다.

회귀 검사는 프로젝트의 명시한 요구를 기준으로 한다. 관련 자료·정보 축·탐색/확대·키보드 경로가 장식 변경으로 사라지지 않았는지 확인한다. 영향받은 첫 장면·목록·완료 상태를 PC/모바일에서 대조하며 한 화면의 새 효과로 전체 사이트가 개선됐다고 판정하지 않는다.


[모바일 내부 조판](mobile-review.md)을 적용해 문서 넘침 정상과 내부 정상 표시를 구분한다. 의미 단위 메타정보, 내부 단계의 한 글자 고립, 회전 프레임/구분선 경계는 자동 통과 수와 별도 기록한다. [편집 결정](editorial-decisions.md)의 선택 근거가 실제 화면에 남았는지도 확인한다.


최종 화면의 지침 적용 여부는 [기대 관계→위치/상태→화면 근거→판단](applied-evidence.md)으로 확인한다. 사진/행동의 대상 불일치, 과정/수업 관계 누락, 작품 감상 크기 부족, 반복 설명은 정렬 검사 통과와 별개다. 일반 제작에서는 미충족을 수정·재검사하며 비교 동결본은 원본 실패/보류를 남긴다.

## 선택 누락과 모달 스크롤 확인

필수 선택값을 구현에서 역산하지 말고 요구 목록과 최종 브라우저 DOM으로 대조한다. 필수 값마다 연결된 결과까지 도달하고, 미선택 오류를 고친 후 완료할 수 있어야 한다. 대표 흐름·스크립트 구문 통과만으로 기본 기능 완료를 판정하지 않는다.

라운드 모달은 외곽 모서리뿐 아니라 레일·손잡이·교차 모서리와 본문 최하단 접근을 직접 본다. 스크롤이 필요한 긴 내용·확대 상태에서 본문을 이동하고 닫기와 마지막 행동이 실제 조작 가능한지 확인한다. [구현 기준](dialog-scroll.md)의 외곽 클리핑과 내용 숨김을 구분한다.
