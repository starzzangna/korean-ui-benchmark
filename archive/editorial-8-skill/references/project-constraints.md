# 프로젝트 요구와 유지 범위

기존 화면을 수정하거나 여러 구현으로 같은 요청을 전달할 때 사용한다. 현재 사용자 요청이 이전 결정과 충돌하면 현재 요청을 우선한다. 요구사항과 선택 가능한 표현을 구분한다.

## 구현 가능한 기준으로 적기

| 요청 | 유지할 관계 | 선택 가능한 표현 | 확인 방법 |
|---|---|---|---|
| 상품을 비교하기 쉬워야 함 | 사진·이름·가격·선택이 같은 상품에 연결 | 열 수·이미지 비율·정보 위치 | 긴 이름/가격·모바일·상세 왕복 |
| 작품이 중심이어야 함 | 식별 가능한 작업 자료와 실제 상세 진입 | 대표/보조 병치·큰 한 작품·목록 | 표시 크기·전체/세부·필터 범위·초점 복귀 |
| 일정 신청이 쉬워야 함 | 날짜·유형·금액·신청 결과의 일치 | 포스터·시간표·목록의 면적 | 날짜 전환·합계·오류 수정·확인 |
| 차분한 표현 | 읽기/입력 중 지속 움직임과 경쟁 장식 억제 | 배색·서체·프레임·단회 등장 | 실제 크기·터치·모션 감소 |

각 관계의 적용 화면·상태와 변경 가능한 부분을 DESIGN.md에 적는다. 색명·고정 열 수·특정 비율은 해당 프로젝트의 명시적 요구일 때만 유지 조건이 된다. 예시의 수치를 새 프로젝트에 자동 전달하지 않는다.

## 변경과 회귀 검토

기능·콘텐츠·표현 중 바뀐 항목을 구분한다. 자료·과업·접근성에 따른 변경 이유를 적고 관련 PC/모바일 화면을 대조한다. 원본 확대·선택값·키보드 경로 등 기존 기능이 장식 변경으로 사라지지 않게 한다. 관련 없는 부분 수정에 전체 재설계 절차를 요구하지 않는다.

독립 비교를 요청받았다면 공통 사실·기능·에셋 권한·유지 조건을 모든 조건에 같은 입력으로 전달한다. 제출 시점·추가 수정·검사기 보정을 구분하고 동결 결과는 별도로 보존한다. 비교 실험을 일반 사이트 제작의 필수 절차로 만들지 않는다.
