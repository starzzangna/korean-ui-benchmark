# 팔레트와 정보 계층의 실제 화면 검토

## 프로젝트별 색상

기존 브랜드가 있으면 우선한다. 새 프로젝트라면 주요색·중립 배경·본문·보조 글자·상태색을 나누고 주제와 핵심 행동에 맞는 이유를 DESIGN.md에 기록한다. 여러 샘플을 한 번에 만들면 주요색과 큰 배경 영역을 나란히 검토한다. 통일 요청이 없는데 모두 같은 팔레트라면 선택을 재검토한다. 녹색·보라색 등 특정 색 자체를 금지하지 않는다.

비교 도구의 바탕과 테두리는 무채색을 권장한다. 평가 대상 밖의 장식이 색상 인상을 과하게 좌우하지 않도록 한다. 상태는 주요색을 바꿔도 텍스트·형태로 식별할 수 있어야 한다.

## SaaS 현황과 요약 카드

사용자가 비교할 단위를 먼저 정한다. 상태별 숫자를 빠르게 비교해야 하면 분리된 카드와 일정한 간격이 유용하다. 연속 지표라면 통합 띠도 가능하므로 모든 화면에 같은 카드 구성을 강제하지 않는다.

- 카드 안의 상태명 → 수치 → 비율 순서를 일관되게 두고, 건수와 비율은 같은 데이터에서 계산한다. 분모가 0일 때도 유효한 값으로 처리한다.
- 진행 막대는 보조 표현이다. 비율을 이해해야 하는 과업이면 숫자도 제공한다. 카드 전체가 버튼이면 상태명·수치가 접근성 이름에 포함돼야 한다.
- 밀도를 높이려고 보조 글자를 과하게 작게 하거나 컨트롤 영역을 줄이지 않는다. 카드 간 여백, 숫자의 강조, 검색과 테이블의 구분을 별도로 검토한다.

## 인라인 요소의 크기와 진행 막대

span에 height만 지정하면 의도한 높이로 렌더링되지 않을 수 있다. 트랙과 채움의 표시 형식을 명시하고, 실제 채움 높이·폭·부모 경계 안의 배치를 확인한다.

```html
<span class="block h-[3px] overflow-hidden rounded-full bg-slate-200" aria-hidden="true">
  <span class="block h-full w-1/3 bg-blue-700"></span>
</span>
```

위 1/3은 정적 예시다. 실제 업무 비율은 데이터로 계산하며 같은 카드에 읽을 수 있는 수치·비율을 제공한다. CSS만 사용해도 동일하게 `display:block`, 트랙의 명시적인 높이와 채움의 `height:100%`를 설정한다.

실제 브라우저에서 다음을 확인한다.

1. 트랙과 채움의 `getBoundingClientRect()` 높이가 의도와 맞고, 채움이 트랙을 벗어나지 않는다. 잘려서 얇아 보이는 것과 정상 높이는 구분한다.
2. 초기 상태뿐 아니라 0개·여러 항목 추가·필터 변경에도 숫자와 비율이 일치한다.
3. 모바일과 데스크톱에서 카드 순서와 그룹 구분이 유지된다. 주요 컨트롤의 아이콘·텍스트 정렬은 별도로 측정한다.

## 비교 결과 해석

컨트롤 높이·기능 성공·가로 넘침·시각적 명료성은 다른 평가 축이다. 일부 자동 검사 통과를 디자인 전체의 우월성으로 보고하지 않는다. 최초 비교가 동결됐으면 입력과 산출물을 보존하고 후속 개선본·검사 결과를 별도 폴더에 둔다. 사후 수정 결과를 최초 제작 MD 효과로 합산하지 않는다.
