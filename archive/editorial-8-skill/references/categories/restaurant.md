# 식당 · 음식·메뉴·방문 조건

## 전면 사진과 따뜻한 읽기 면

음식 사진이 첫 판단을 맡고 안전한 문구 영역이 확보되면 화면 폭을 활용하는 전면 장면을 적극 검토한다. 전폭을 100vh 고정 높이로 해석하지 않고 실제 제목·설명·메뉴 행동과 글자 확대를 수용한다. 필요한 문자 영역의 명암을 조절하면서 음식의 색과 빛을 보존한다. 모바일에서 접시·글자 대비를 함께 확보하기 어려우면 문구를 분리한다.

사진에서 메뉴와 예약까지 바탕의 온도·행동색을 연결한다. 음식·브랜드에서 유래한 낮은 채도의 읽기 면과 선택 면을 쓸 수 있으며 색 개수나 베이지 계열을 업종 기본값으로 고정하지 않는다.

## 음식이 주인공이 되는 크롭과 중복 없는 메뉴 진입

사진 상자가 커도 식탁·도구만 크게 남으면 음식 감상에 실패한 것이다. 접시의 위치·크기·질감과 문구 안전 영역을 원본에서 정하고 PC/모바일의 실제 크롭으로 확인한다. 사진 위 문구와 분리형 소개 중 음식과 읽기를 함께 보존하는 구도를 선택한다. 피사체를 놓치지 않게 `object-position`만 조정할지 별도 원본이 필요한지 기록한다.

첫 장면의 메뉴 예고와 바로 다음 전체 메뉴가 같은 이름/가격을 반복하면 예고를 줄이거나 다른 판단을 맡긴다. 정돈된 메뉴의 의미 아이콘·이름/가격 축과 예약 구간의 연속성은 보존한다. 실제 메뉴 사진이 없으면 참고 상차림을 특정 요리의 실물처럼 연결하지 않는다.

## 목적과 구성 선택

음식과 식당의 성격·메뉴 진입을 동시에 보여주려면 소개/메뉴 행동과 음식 사진을 병치할 수 있다. 전면 사진은 큰 면적이 음식·공간의 맥락을 잘 전달하고 문구 안전 영역이 확보될 때 선택한다. 기존에 승인된 전면 구도 보존은 해당 수정 작업의 조건이며 새 식당 제작의 기본형은 아니다. 구체적인 선택은 [첫 화면 기준](../hero-composition.md)을 따른다.

음식의 성격을 보여주면 사진 중심, 메뉴/가격 비교가 우선이면 메뉴 보드, 방문 조건과 날짜 선택이 우선이면 예약 중심을 검토한다. 음식 사진과 관련 소개·메뉴 진입을 인접하게 두고 긴 장식 구간이 메뉴를 밀어내지 않게 한다.

새 제작에서는 `어떤 식사를 고르는가 → 무엇으로 판단하는가 → 메뉴/방문으로 어떻게 이어지는가`를 먼저 적는다. 같은 상차림 사진과 소개 문장을 그대로 두고 바탕·버튼·굵기만 바꾸면 새 음식점의 편집이 아니다. 다음 후보는 내용이 뒷받침할 때만 사용한다.

| 실제 판단 조건 | 가능한 대표 구간과 다음 구간 | 필요한 자료 |
|---|---|---|
| 한 접시의 맛·재료를 먼저 보고 싶음 | 접시와 짧은 소개 → 해당 메뉴 이름·가격·다른 선택 | 그 메뉴의 실제 사진. 분위기 사진을 개별 요리 사진으로 간주하지 않음 |
| 식사 구성·가격을 비교하고 싶음 | 읽히는 메뉴 편집과 보조 음식 사진 → 메뉴 선택 | 실제 메뉴명·가격·설명, 제공될 때 구성/규격 |
| 공간에서의 식사를 판단함 | 상차림/공간 장면 → 제공된 방문·예약 조건 | 실제 공간 자료. 주소·운영 시간·좌석은 제공된 사실만 |

대표 장면의 다음에 같은 감성 소개를 반복하지 않는다. 사진이 한 장뿐이면 같은 사진을 여러 구간에 장식으로 재사용하기보다 메뉴의 비교 밀도와 실제 식사 정보를 편집한다. 사진/정보가 부족하면 [에셋 요청서](../../assets/ASSET-BRIEF.md)에 필요한 대상을 남긴다.

### 사진을 한 장면으로 사용하는 상단

대표 음식과 매장 분위기가 첫 판단의 근거이고 충분한 해상도의 사진·문구 안전 영역이 있으면, 넓은 사진 위에 짧은 제목과 메뉴 진입을 함께 배치할 수 있다. 사진 위 문구는 선택지이며 식당의 기본 템플릿이 아니다. 제목은 기본 Pretendard 700에서 검토하고, 사진의 음식은 밝게 유지하면서 문구 뒤에만 필요한 명암을 준다. 배색은 실제 브랜드와 사진으로 정해 메뉴·예약까지 역할을 연결한다. 따뜻한 미색이나 어두운 오버레이를 업종 기본값으로 강제하지 않는다.

모바일 크롭에서 음식과 문구 안전 영역을 동시에 확보할 수 없으면 사진을 위로, 제목·설명·행동을 아래 단색 영역으로 분리한다. 확대 시 텍스트 영역 높이가 늘어나게 하고 고정 높이·줄 수 제한으로 숨기지 않는다. 대표 접시가 잘리지 않는지 320·390·768·1024·1440px와 글자 200%에서 확인한다. 큰 사진은 전체 화면 높이 강제나 메뉴 진입을 밀어내는 이유가 되지 않는다.

## 자료와 설명 밀도

대표 음식·메뉴별 사진·공간 사진의 역할을 구분한다. 얕은 크롭과 깊은 크롭을 실제 접시로 비교하고 모바일에서도 주메뉴의 형태를 식별할 수 있게 한다. 분위기 디저트 사진을 실제 정식·수프의 증거로 쓰지 않는다.

메뉴는 이름·가격·필요한 설명으로 구별한다. 사진이 없고 음식 종류 구분에 도움이 되면 의미 있는 아이콘을 보조로 사용한다. 아이콘·분류 배지·번호를 모두 반복하지 않는다. 색과 모서리 반경은 실제 브랜드/사진에 맞추고 메뉴·예약까지 같은 역할로 연결한다.

## 조작과 모션

[메뉴 예제](../../assets/category-motion/index.html#restaurant)처럼 검색/분류 결과를 즉시 갱신한다. 가격과 메뉴 텍스트의 비교 축은 움직이지 않는다. 사진 감상의 느린 반응과 예약 컨트롤의 즉각 반응을 구분한다.

## 구현과 검토

비교 목록에서는 가격·설명·구분선의 기준을 맞춘다. 긴 메뉴명·큰 가격·작은 폭에서는 가격을 다음 줄로 옮길 수 있다. native 날짜·시간·인원의 필수 옵션을 실제로 선택하고 예약 오류→수정→확인→완료를 검토한다. 버튼 내부 중앙과 안내/동의의 첫 줄, 묶음 전체의 가로 위치를 따로 확인한다.

[편집 결정](../editorial-decisions.md) · [자료 준비](../asset-pipeline.md) · [모바일 검토](../mobile-review.md). 선택한 기준은 [적용 확인](../applied-evidence.md)으로 최종 DOM·조작·PC/모바일 화면과 대조한다. 수치상 통과와 실제 읽기/광학 판단, 미실행을 구분한다.


## 셀렉트 간격의 일관성

선택 컨트롤이 있으면 같은 제품/비교 범위의 화살표 크기·우측 여백·문구 안전 영역을 공통 토큰으로 연결한다. native 기능과 label/검증/값 갱신은 유지한다. [셀렉트 표시 계약](../control-alignment.md#네이티브-선택-기능과-화살표-표시의-공통-계약)에 따라 실제 모바일·글자 확대·키보드와 연결 기능을 확인한다. 셀렉트가 필요 없는 화면에는 새로 추가하지 않는다.

## 음식 다음에 메뉴가 읽히는 밀도

승인된 전면 음식 사진 구도를 수정하는 작업에서는 음식의 식별과 가까운 메뉴 진입을 유지한다. 새 제작의 구도는 자료와 판단 순서로 선택한다. 메뉴가 짧고 사진이 없으면 얇은 구분선의 목록과 작은 의미 아이콘만으로도 충분하다. 이름·가격·한 줄 설명을 카드 배경/번호/배지보다 먼저 읽히게 하고 예약 구간은 같은 색 역할로 이어간다. 디저트 분위기 사진을 개별 요리 실물로 표현하지 않는다.

날짜의 첫 값과 마지막 값, 시간·인원은 요구에서 정한 계약으로 파싱 DOM부터 확인한다. 시작 option을 닫기 태그로 잘못 쓴 경우에도 페이지는 열릴 수 있으므로 소스 문자열/JS 구문으로 검사하지 않는다. 날짜별 실제 예약 확인·수정·완료와 열린 뒤 스크롤 초기화를 [완료 게이트](../delivery-gates.md)로 검사한다.

## 페이지 관계의 구현 확인

첫 식사 사진은 메뉴의 성격을 식별할 수 있어야 한다. 다른 음식의 분위기 사진을 실제 메뉴처럼 연결하지 않는다. 음식은 밝게 남기고 문구 안전 영역에만 필요한 명암을 준다. 가격·아이콘이 정돈된 간결한 메뉴와 예약 완료 흐름은 유지한다.

공통 구현과 검토는 [페이지 관계 기준](../page-relationships.md)을 따른다.

## 표현 변형과 정보 묶음의 최종 검토

승인된 메뉴/예약의 정보 관계는 유지하면서 사진/버튼 변형을 수정할 때 부모 배경·최종 내부 여백·상태·중간 폭까지 확인한다. 다른 업종의 구도나 밀도 개선을 일괄 적용하지 않는다.

## 상단과 본문의 연결 판단

사진에 메뉴를 겹칠 안전 영역이 없으면 사진과 연속된 어두운 상단을 선택한다. 모바일 사진 전체를 검게 덮기보다 음식이 드러나는 영역과 읽기 영역을 나누고 확대 시 문구 영역이 늘어나게 한다. [공통 선택 기준](../header-and-surfaces.md)을 실제 메뉴 수·자료·방문 과업에 대조한다.

## 탐색 길이와 강조의 편집

전면 사진의 감상과 텍스트의 읽기를 함께 판단한다. 모바일에서 사진/문구 면을 나눴을 때 식탁의 연결이 지나치게 끊기는지 검토한다. 메뉴 이름·설명·가격·표식을 묶어 진입시키고 실제 예약 입력 중에는 화면을 움직이지 않는다.

## 모바일 길이와 경계 재검토

예약 구간의 바탕이 안정적으로 남아야 하는 경우 배경 section이 아닌 내부 소개·폼 묶음에 진입을 적용한다. 음식 사진 크롭과 따뜻한 읽기 면은 이 모션 변경과 분리해 검토한다.

## 첫 판단과 자료의 역할

음식의 감상과 메뉴/예약 접근을 첫 화면에서 함께 평가한다. 같은 전면 사진이라도 첫 메뉴 행동이 늦어지거나 실제 음식 크롭이 사라지면 문구와 안전 영역을 재편집한다.
