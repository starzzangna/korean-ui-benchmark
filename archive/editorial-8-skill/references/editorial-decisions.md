# 구도·자료·동작을 하나의 장면으로 결정한다

표현 중심 사이트에서 지침을 읽었어도 결과가 일반 카드 목록으로 수렴할 때 사용한다. [실행 예제](../assets/editorial/index.html)에는 같은 자료의 크롭 전환, 과정 사진과 선택 목록, 대표/보조 작품, 읽을 수 있는 산출물, 일정 메타데이터를 제공한다. 전체 페이지나 색을 복제하지 않고 해당 관계만 가져온다.

## 구현 전에 비교할 것

먼저 짧은 제작 브리프를 쓴다. `세련된·프리미엄·한국적` 같은 형용사만으로 방향을 확정하지 않는다.

| 결정 | 작업에 사용할 답 |
|---|---|
| 방문 상황과 첫 판단 | 누가 어떤 상황에서 들어오며, 무엇을 알아야 다음 행동을 하는가? |
| 이 브랜드의 근거 | 제공된 상품·방식·작품·문장·자료 중 다른 이름으로 바꾸기 어려운 것은 무엇인가? |
| 대표 장면 | 그 근거를 실제로 보여주는 대상, 읽는 순서, 바로 다음 구간의 새 정보 |
| 표현의 원리 | 예: 소재를 관찰하게 할 사진 거리 / 메뉴를 비교할 가격 축 / 문서의 판단을 읽게 할 조판. CSS 값보다 이유를 먼저 적는다. |
| 자료의 공백 | 현재 자료로 표현 가능한 범위와 추가 촬영/원본/내용이 필요한 부분 |

이 답을 문서에만 두지 않는다. 첫 화면과 바로 다음 구간을 PC/모바일로 먼저 구현해 브랜드 식별과 다음 행동이 읽히는지 확인한 뒤 확장한다. 사진과 문구가 준비되지 않은 빈 상자 시안으로 최종 구도를 승인하지 않는다. 이름·색·글꼴 굵기를 가렸을 때 무엇이 남는지 보는 것은 진단 방법이며, 반드시 낯선 배치를 만들라는 요구가 아니다.

확보한 자료로 성립하는 후보를 비교한다. 예를 들어 `공간 전면 + 소개`와 `과정 사진 옆 수업 목록`은 역할이 다르다. 사진 반경이나 배경색만 바꾼 것은 새 구도 후보가 아니다. 후보 수를 채우기 위해 부적합한 안을 만들 필요는 없다.

## 한국어 화면의 편집

한국적이라는 이유로 미색·둥근 카드·전통 무늬를 자동 적용하지 않는다. 사용자가 알고 싶은 내용을 실제 한국어로 편집한다. 상품이면 규격·가격·선택 차이, 매장이면 제공된 방문/예약 조건, 전문 서비스면 의뢰 상황·범위·결과를 먼저 읽게 한다. 영문 대문자 라벨과 추상적인 감성 문장을 늘리는 것으로 정체성을 대신하지 않는다.

제목은 해당 브랜드가 하는 일을 말하고 문단마다 새로운 내용을 준다. 긴 한국어는 단어 단위 줄바꿈을 검토하되 좁은 폭의 URL·고유명사·숫자에는 탈출 경로를 둔다. 실제 원화·날짜·시간·단위·오류 문구를 넣어 조판한다. 주소·운영 시간·전문 자격·성과는 제공된 사실만 쓴다. Pretendard 기본값은 읽기의 출발점이며 독자적인 편집의 완성 조건이 아니다.

## 재사용의 경계

데이터, 상태 처리, 입력 검증과 접근성 동작은 재사용할 수 있다. 완성 히어로·구간 순서·설명 블록·대표 그래픽을 기본으로 공유하면 새 프로젝트도 같은 장면으로 수렴한다. 반복 패턴을 쓰려면 현재 내용이 그 관계를 필요로 하는지 먼저 확인한다. 레이아웃이 같아도 최선일 수 있으나 색·굵기 변경만으로 새로운 정보 설계를 했다고 기록하지 않는다.

기존 화면을 고치는 작업에서는 승인 범위를 보존한다. 새 제작에서는 이전 프로젝트의 `좋았던 사진 위 제목`, `우측 종이`, `상단 카드`를 자동 요구로 가져오지 않는다. 이미 작성된 문서의 보존 지시도 현재 사용자가 지정한 범위에만 적용한다.

선택 근거에는 다음을 짧게 남긴다.

- 무엇을 먼저 보고 무엇을 다음에 읽는가? 대표 한 작품과 보조 작업의 관계가 정지 화면에서도 보이는가?
- 사진·설명·행동이 같은 대상을 가리키는가? 떨어진 CTA가 어느 사진의 행동인지 추측하게 만들지는 않는가?
- 중단에서 새로운 비교 정보가 생기는가? 과정 사진을 별도 감성 구간으로 떼어 수업과의 관계를 잃지는 않는가?
- 모바일에서는 무엇을 남기고 무엇을 뒤로 옮기는가? PC 두 열을 그대로 쌓았을 때 반복·빈 공간이 생기면 재편집한다.

## 역할별 적용

| 조건 | 선택할 관계 | 피할 결과 | 확인 근거 |
|---|---|---|---|
| 브랜드 사용 장면 | 상품을 식별할 크롭 + 가까운 캡션/상세 | 주변 배경만 넓고 상품은 작음 | 원본·넓은 크롭·가까운 크롭에서 피사체 비교 |
| 로컬 수업 | 손·도구·과정 사진 + 수업 차이/가격/선택 | 카드와 사진이 서로 무관한 요금제형 페이지 | 사진 옆에서 무엇을 배우는지 설명 가능 |
| 사진 우선 식당 | 접시가 읽히는 사진 + 인접 소개/메뉴 진입 | 얕은 사진이 무늬가 되거나 설명/버튼이 멀리 분산 | PC와 모바일에서 음식과 행동의 관계 |
| 스튜디오 포트폴리오 | 대표 하나 또는 주작품/보조의 명확한 대비 | 프레임·바탕·여러 강한 작품이 같은 무게로 경쟁 | 배경/장식 없이도 주작품 식별, 목록 정렬 별도 유지 |
| 전문 서비스 | 구체 요청 + 읽을 수 있는 산출물 한 장 | 작은 상자와 연결선이 내용보다 많음 | 산출물의 제목·핵심 판단을 실제 크기에서 읽음 |
| 행사 | 행사 성격/일시/행동 + 포스터의 위계 | 장식 영문만 기억되고 날짜는 작은 각주 | 모바일에서 행사명·일시·참가 조건을 찾음 |
| 업무 앱 | 제목/검색/상태/목록의 짧은 경로 | 소개 장면·감성 사진·불필요한 보조 패널 | 업무 검색/상태 변경을 지체 없이 수행 |

## 색·프레임·캡션의 무게

사진의 빛·소재와 브랜드색의 관계를 본다. 강한 브랜드색도 가능하지만 로고·제목·큰 배경·버튼을 동시에 강조할 필요는 없다. 작품 자체의 색이 강하면 바탕·그림자는 낮은 위계로 조절한다. 특정 색의 비율을 전역 공식으로 고정하지 않는다.

부드러운 사진 인상이 프로젝트 목적에 맞으면 관련 대표/목록 프레임의 바깥 반경과 선을 연결한다. 가격·캡션·초점 링은 이미지 크롭 레이어 밖에 둔다. 원본 확대는 contain과 별도 탐색을 유지한다. 목록의 정렬을 깨뜨리는 계단 배치로 편집감을 대신하지 않는다. 리듬은 구간의 면적·자료 역할·정보 밀도로 만든다.

## 필요한 에셋을 먼저 특정한다

브랜드는 사용 장면/식별/소재 세부, 로컬은 공간/과정/도구, 식당은 대표 음식/실제 메뉴, 포트폴리오는 대표 전체/관찰할 세부, 전문 서비스는 읽을 수 있는 문서, 행사는 포스터/일정 원본 중 현재 과업에 필요한 것을 선택한다. 모두 확보해야 한다는 할당량은 아니다.

`ASSETS.template.json`의 usedIn/newInformation/mobileEdit에 해당 역할과 남길 피사체를 적는다. 참고 사진·생성 자료는 실제 상품/장소/고객 성과로 쓰지 않는다. 없는 세부를 확대 생성해 실물 증거로 표시하지 않는다. 자료가 부족하면 적합한 구도로 바꾸고 필요한 촬영/원본을 구체적으로 남긴다. 예제의 brewing 사진도 실제 운영 수업의 증거가 아닌 참고 자료다.

## 상태 사이의 모션

사진 등장·버튼 화살표·확인창 등장을 복사하는 것으로 모든 장면을 끝내지 않는다. 해당 화면에서 바뀌는 대상을 고른다.

- 사진/작품 상세: 같은 자료와 캡션의 관계를 유지하고 상세 초점·원본을 즉시 제공한다.
- 수업/서비스 선택: 내용·금액을 즉시 갱신하고 갱신 위치만 짧게 강조한다. 목록 전체를 이동시키지 않는다.
- 시간표 설명: 표식을 회전하되 날짜·시간·가격은 안정적으로 둔다. 처음 열린 항목도 허용하며 열림→닫힘→열림을 확인한다.
- 작품 프레임: 바깥 등장 wrapper와 자세를 바꾸는 안쪽 프레임을 분리한다. 빠른 hover 왕복은 현재 자세에서 이어지고 복귀 후 주변 경계와 겹치지 않아야 한다.

거리·시간·곡선의 실제 값은 대상에 맞게 정한다. 예제는 시작값이며 효과 수는 품질 점수가 아니다. [모바일 검토](mobile-review.md)와 [장면 모션](scene-motion.md)을 함께 적용한다.

## 선택이 실제 화면에서 성립하는지 확인한다

규칙을 늘리기 전에 다음 세 번의 비교로 현재 안을 확인한다. 모든 프로젝트에 별도 실험 UI를 만들라는 뜻은 아니다.

1. **주인공:** 대표 화면에서 제목·사진·작품·일정 중 먼저 남아야 하는 대상을 정한다. 큰 색면/배경/바깥 프레임/보조 라벨을 잠시 덜어낸 안과 본다. 대상을 더 잘 읽게 하면 채택하고, 브랜드의 핵심 표현을 잃으면 유지한다. 면적 비율이나 장식 수를 보편 점수로 만들지 않는다.
2. **구간:** 첫 화면→비교→완료를 이어 본다. 검색줄이 브랜드 소개보다 강하거나, 산출물과 진행 설명이 같은 말을 반복하거나, 홀수 마지막 작품 뒤 여백이 다른 구간보다 과도하면 해당 구간만 다시 편집한다. 정렬된 카드에 비대칭을 추가해 해결하지 않는다.
3. **실제 행동:** 선택한 사진/작품→상세→복귀에서 이름·자료·필터·초점이 이어지는지 확인한다. 장면 등장과 버튼 반응의 존재만으로 연결을 완료한 것으로 세지 않는다.

선택 근거는 `남길 인상 / 덜어낼 후보 / 실제 폭과 상태 / 채택 이유·잔여 한계`로 짧게 기록한다. 명시한 프로젝트 조건을 바꾸는 경우는 별도 근거가 필요하다. [실행 예제](../assets/decisions/index.html)의 사진 우선/소개 병치, 세 작품의 마지막 행, 단순 산출물→상세, 일정/선택 요약은 결과를 비교하는 도구이며 완성 페이지의 배색·숫자·문구를 강제하지 않는다.

## 정렬 측정 뒤의 편집

같은 행 카드의 폭·제목·행동 축이 맞으면 그 결과를 보존한다. 다음 검토는 프레임 안의 여백, 이미지에 중복된 배경, 보조 라벨의 읽는 순서, 마지막 행과 다음 구간 사이의 간격이다. 대표 겹침은 의도한 비대칭으로 따로 측정한다. 같은 수치라도 글리프의 광학적 위치·설명의 길이·이미지 내용이 다르므로 중심 차이만으로 우열을 판정하지 않는다.

## 설명을 어디에서 읽게 할지 결정한다

목록/첫 장면/상세의 역할을 DESIGN.md에 구분한다. 목록은 이름·구별할 정보·판단에 필요한 가격/상태부터, 의도·과정·관찰은 실제 접근 가능한 상세로 옮기는 안을 비교한다. 법적 조건·예약 제약·안전 정보·필수 오류를 미적 밀도를 이유로 숨기지 않는다. 글자 수나 행 수는 보편 상한이 아니다. 같은 설명이 대표/카드/하단에 반복되면 새 정보가 있는 위치만 남긴다.

정렬된 카드가 밋밋하면 비대칭이나 그림자부터 추가하지 않는다. 피사체 크기·본문 밀도·제목 대비·마지막 행과 다음 구간의 간격을 먼저 본다. 브랜드의 선택 관점, 로컬의 배움, 식당의 음식, 작품의 특징, 서비스의 판단, 행사의 참가 이유가 실제 자료로 읽히는지 확인한다. 색을 늘리는 대신 같은 행동색이 사진/조판/다음 구간과 연결되는 근거를 남긴다.


사진/행동 관계나 설명 축약을 선택했다면 [실제 적용 확인](applied-evidence.md)으로 최종 화면을 대조한다. 과정 사진이 다른 구간에 존재하거나 작품이 카드 안에 들어갔다는 사실만으로 관계가 성립했다고 보고하지 않는다. 사진 자체가 같아도 크롭·캡션·행동·주변 면의 선택은 결과를 바꾼다.

## 주인공과 보조를 실제로 덜어내기

첫 화면·비교·선택 구간마다 먼저 읽힐 대상 하나를 정한다. 큰 색면·굵은 제목·번호·배지·테두리·그림자를 동시에 추가하지 않는다. 장식이나 반복 설명을 잠시 제거했을 때 과업/브랜드 식별이 유지되면 더 단순한 쪽을 검토한다. 이 과정은 고정된 미니멀 스타일이나 매번 같은 팔레트를 적용하라는 뜻이 아니다.

사진/작품의 크기, 문장 길이, 배경 대비가 만드는 강약을 먼저 조절하고 간격·반경을 정돈한다. 모션도 같은 주인공을 이어야 한다. 매 섹션의 reveal로 분위기를 만드는 대신 장면 하나의 등장·자료 반응·복귀를 연결한다. 동등 목록의 크기/가격 축과 필수 기능은 이 편집 과정에서 보존한다.

## 첫 화면의 채택과 편집 검토

대표 자료·읽을 문구·첫 행동의 관계를 첫 화면과 다음 구간에서 확인한다. 자료가 방향을 명확히 정하면 후보를 억지로 늘리지 않는다. 결정이 모호하면 예를 들어 자료 감상 중심과 판단/선택 중심의 관계를 비교하고 방문자의 첫 판단에 더 맞는 구성을 고른다. 색/글자 굵기만 다른 후보를 다른 편집으로 세지 않는다.

기능 검증과 분리해 다음을 대조한다: 무엇이 기억되는가, 가장 강한 강조가 판단 근거에 있는가, 같은 선택/설명이 다시 나오는가, 사진·문구·행동이 같은 대상을 가리키는가, 모바일에서도 감상 크기와 실행 순서가 유지되는가. 근거 없이 모든 구간을 줄이거나 극적인 비대칭을 넣지 않는다.

후속 개선의 성과와 스킬의 최초 생성 효과는 구분한다. 생성 성능을 검증할 때는 새 브리프/자료·동일 기능·동일 제작 조건에서 비교하고 결과 순서/이름이 평가를 유도하지 않게 한다. 누적 수정을 받은 한 시안의 우위를 일반적인 생성 성능으로 주장하지 않는다.
