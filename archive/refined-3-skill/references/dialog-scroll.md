# 라운드 모달과 내부 스크롤

작품·상품 상세처럼 긴 내용을 둥근 모달에 표시할 때 사용한다. 기존 Dialog 컴포넌트의 접근성·포털·초점 관리를 우선하고, 스크롤 스타일만 필요한 부분에 적용한다. 모든 팝업에 중첩 스크롤이나 고정 헤더를 추가하지 않는다.

## 외곽과 스크롤 영역의 역할

- 모달 외곽은 border/radius와 `overflow:hidden`으로 모서리를 보존한다. 필수 내용을 숨겨 맞추는 용도가 아니다. 실제 본문에는 `overflow:auto`와 화면에 제한된 가용 높이를 제공해야 한다.
- 열린 모달을 세로 flex/grid로 나누고 헤더와 본문을 분리한다. flex 본문은 `min-height:0; flex:1 1 auto`, grid는 `minmax(0,1fr)`을 사용해 긴 내용이 실제로 스크롤되게 한다. 닫기를 항상 보여야 하는 상세에서는 헤더가 줄어들거나 본문과 함께 사라지지 않도록 한다.
- 닫힌 native dialog에 `display:flex`를 상시 지정하지 않는다. `[open]` 상태에만 적용한다. 모바일은 `dvh`와 양끝 여유로 최대 높이를 정하고 글자 확대 때 실제 내용 접근을 확인한다.
- 레일과 두 스크롤바의 교차 모서리는 투명하게, 손잡이는 식별 가능한 대비와 둥근 모양으로 표시한다. 스크롤바를 `display:none`으로 통째로 숨기거나 모든 페이지에 전역 스타일을 씌우지 않는다. 반경에 필요한 레일 끝 여백을 둔다. 고대비 모드는 시스템 대비 색을 따른다.
- `scrollbar-gutter:stable`은 내용 폭 변화가 불편할 때 선택한다. 예약되는 폭이 이미지/컨트롤을 좁게 만드는지 함께 확인한다. 표준 scrollbar 속성과 WebKit 가상 요소를 혼용할 때 어느 구현이 우선되는지 실제 지원 브라우저에서 확인한다.

## 조작과 내용 보존

바깥 문서, 모달 본문, 확대 이미지 중 어느 영역이 이동하는지 구분한다. 이미지에 실제 확대·이동이 필요할 때만 별도 스크롤 영역을 둔다. 축소/작품 변경 때 이미지 배율과 이동을 초기화하고, 작품 변경 후 제목부터 읽는 흐름이면 본문 위치도 초기화한다.

본문에 키보드 스크롤 진입점이 필요하면 이름이 있는 초점 가능한 영역을 제공한다. 불필요하게 모든 wrapper를 Tab 경로에 추가하지 않는다. 기존 컴포넌트의 포커스 정책과 충돌하지 않게 하며, PageDown/방향키가 의도한 영역을 이동하는지 확인한다. Escape와 명시적 닫기 후 실제 진입 요소로 초점을 돌린다. 배경 스크롤 잠금은 닫기 때 해제한다.

## 확인과 완료 조건

1. 내용이 짧은 상태와 실제로 넘치는 긴 상태를 모두 연다. PC·모바일에서 위/중간/끝으로 스크롤하며 상하 라운드, 투명 레일, 손잡이와 닫기 접근을 직접 본다. 계산된 `border-radius`만으로 모서리 표시 통과를 판정하지 않는다.
2. 글자만2배·글자/행간2배에서 최하단 행동까지 실제 스크롤·클릭한다. 외곽에 넘침이 없더라도 본문이 스크롤되지 않아 내용이 잘리면 실패다. 실제 브라우저 메뉴 확대/실기기와 합성 확대는 따로 기록한다.
3. 이미지 확대→이동→맞춤, 다음 작품, 닫기→재진입과 초기 위치를 확인한다. 키보드 스크롤은 입력 직후 좌표를 단정하지 말고 실제 이동 완료를 기다린다. 기본/모션 감소를 구분하고 터치 팬 직후 첫 닫기 탭도 필요한 장치에서 확인한다.
4. 렌더링 엔진과 OS에 따라 스크롤바 외형이 다르다. Chrome 확인을 Firefox·Safari·실기기 확인으로 확대 보고하지 않는다. 스타일 차이를 제외해도 내용·키보드 접근은 유지해야 한다.

## 제목·닫기와 열린 뒤 초기화

헤더의 긴 제목은 min-width:0인 텍스트 열, 닫기는 줄어들지 않는 조작 열로 나눈다. flex의 기본 min-width:auto가 닫기를 바깥으로 밀 수 있다. 예제 CSS는 minmax(0,1fr) auto를 사용한다. 제목만 줄이고 닫기나 전체 모달을 잘라 문제를 숨기지 않는다.

처음부터 읽어야 하는 상세/확인창은 showModal/마운트 후 본문·필요한 이미지 이동 위치를 초기화한다. 닫힌 display:none 상태에서 scrollTop=0을 쓴 것만으로 재진입이 정상이라고 판단하지 않는다. 닫기 초점을 preventScroll과 연결하고 긴 본문 끝→수정/닫기→재진입을 두 확대에서 실제 검사한다. 읽던 위치 보존이 과업이라면 그 정책을 명시한다.

확대에서 dialog 자체가 의도보다 좁아지면 브라우저 기본 max-width도 확인한다. 예제는 width와 max-width를 같은 viewport 여백 기준으로 명시해 em 기반 기본 제한과 충돌하지 않게 한다. 실제 닫기/본문/하단 행동을 다시 검사한다.
