# 카테고리별로 실제 구도를 결정하기

업종별 구성 선택을 설명하는 예시다. 고정 템플릿이나 무작위 스타일 목록이 아니다. 해당 카테고리만 읽고 자료와 행동에 맞게 변형한다. 색과 폰트를 정하기 전에 선택한다. 기존 브랜드와 사용자가 지정한 자료·구성 조건을 우선한다.

## 선택에 필요한 최소 기록

`구체적인 대상 → 확보한 자료 → 첫 화면 → 다음 정보 → 핵심 행동 → 모바일 변화`를 한두 문장으로 쓴다. 자료가 없는 후보는 제외한다. 후보가 하나만 가능하면 억지로 세 개를 만들지 않는다. 선택 이유는 분위기 형용사보다 실제 자료와 방문 과업으로 설명한다.

## SaaS 업무 화면

- **workbench:** 검색·필터 바로 아래 실제 업무 목록. 넓은 화면은 프로젝트/담당자/기한/상태의 정렬 축을 공유한다. 요약 숫자는 목록을 이해하는 데 필요한 만큼만 둔다. 모바일은 제목·상태·다음 행동 순이며 덜 중요한 열은 상세로 이동한다.
- **operations:** 처리해야 할 작업 대기열이 중심. 진행 단계와 담당자 전환을 드러내고 누락·지연 상태에서 다음 행동을 연결한다. 모바일은 다열 칸반을 억지로 압축하지 않고 상태 선택과 목록으로 재구성할 수 있다.
- **analysis:** 기간·비교 기준과 주요 발견을 차트보다 먼저 확정한다. 축·단위·분모가 있는 차트와 원본 목록을 연결한다. 지표 카드 숫자만 바꾼 가짜 대시보드를 만들지 않는다.

구별되는 특징: 공유 정렬 축과 정보의 밀도. 감성 히어로·커다란 소개문을 업무 영역 앞에 붙이지 않는다.

## SaaS 소개 사이트

- **product-demo:** 실제 한 과업을 수행하는 UI가 주인공. 설명→입력/처리/결과의 연결을 보이고 기능 소개에서도 같은 제품 맥락을 유지한다. 모바일에서는 작은 전체 대시보드 대신 읽을 수 있는 핵심 장면을 쓴다.
- **technical:** 문서·연동·규격을 찾는 사용자를 위한 짧은 소개와 코드/입출력 예. 설치·문서·가격이 실제 목적지로 이어진다.
- **outcome-story:** 제공된 사례의 전후 과정→사용 장면→적용 조건. 검증된 사례가 없으면 이 방향을 제외하고 제품 흐름을 쓴다.

구별되는 특징: 판매하는 제품의 실제 작동. 프로젝트와 무관한 복제 대시보드로 화면을 채우지 않는다.

## 브랜드·패션·뷰티

- **photographic-catalog / product-detail:** 제품 사진과 이름·가격·선택 기준을 가까이 둔다. 넓은 화면은 큰 제품 한 장과 다른 제품 크기 사이의 대비, 이후 일정한 목록 리듬. 모바일에서도 제품 식별과 선택이 감성 소개보다 뒤로 밀리지 않는다.
- **material-journal:** 실제 재료·공정 사진이 있고 구매 전 설명이 중요할 때 선택한다. 전체 모습→소재 근접→사용 장면의 거리 변화를 만든다. 긴 글은 좁은 읽기 폭, 사진은 더 넓은 면으로 분리할 수 있다.
- **collection-index / lookbook / campaign:** 충분한 시리즈가 있을 때 이미지 연속과 품목 연결을 중심으로 한다. 컬렉션 순서와 탐색 위치가 유지돼야 한다. 큰 캠페인 사진이 있어도 제품·분류로 이동하는 경로를 숨기지 않는다.

구별되는 특징: 촬영 대상·크롭·컬렉션의 리듬. 모든 브랜드를 크림색 명조·정물 반쪽 히어로로 번역하지 않는다. 실제 사진이 부족하면 사진 중심 완성 시안이라고 주장하지 않고 확보 가능한 제품 정보 중심의 초안으로 범위를 정한다.

## 카페·매장·로컬 서비스

- **place-first:** 실제 공간·현장 사진이 있고 방문이 주목적. 공간의 넓은 장면과 이름을 결합하고 다음 정보에 위치·영업시간·방문 방법을 둔다. 모바일은 사진 한 장을 유지하고 방문 정보를 가까이 배치한다.
- **menu-first / service-list:** 메뉴·서비스 종류와 가격이 선택의 핵심. 사진과 짧은 설명의 반복, 가격 열의 정렬, 제공 조건을 중심으로 한다. 모든 항목을 큰 버튼 카드로 만들 필요는 없다.
- **class-schedule / appointment / process:** 예약 가능 시간·수업 조건 또는 작업 과정이 실제로 있음. 일정/서비스 선택→조건 확인→문의·신청 순서. 모바일의 폼은 선택 결과를 보존하고 사진 슬라이더가 예약을 가리지 않게 한다.

구별되는 특징: 이 매장을 선택할 실제 이유와 방문/예약의 편의. 카페 사진을 미용실·공방·출장 수리의 공통 배경으로 쓰지 않는다.

## 음식점

- **food-story:** 실제 음식·조리 장면으로 메뉴의 특성을 설명한다. 접시 전체를 보여주는 사진과 재료의 근접 장면을 구분하고 관련 메뉴·가격으로 이어진다.
- **menu-board:** 메뉴 분류·가격·선택 조건이 먼저다. 사진은 대표 항목에 집중해도 된다. 모바일에서 이름과 가격을 같은 항목으로 읽고 품절·예약 제한을 확인할 수 있어야 한다.
- **reservation:** 방문 조건·날짜·인원·좌석이 핵심. 예약 조건과 식당 장면을 같은 맥락에서 보여주고 날짜→인원→확인으로 연결한다. 실제 예약 연동 여부를 표시한다.

구별되는 특징: 음식과 메뉴의 관계. 분위기 사진만 있고 먹을 음식과 가격이 보이지 않는 결과를 재검토한다.

## 커머스

- **catalog:** 분류·필터→일정한 상품 사진·이름·가격→옵션·구매. 탐색 위치를 보존하고 모바일 필터를 닫은 뒤 선택 상태를 표시한다.
- **comparison:** 규격·가격·용도를 같은 축에서 비교. 모바일은 비교 대상/기준을 선택하거나 식별 가능한 표 스크롤을 제공한다.
- **single-product:** 전체 모습→사용 장면→세부·규격→옵션과 구매. 색상 선택은 해당 실제 이미지/설명과 연동한다. 존재하지 않는 옵션을 장식 스와치로 추가하지 않는다.

구별되는 특징: 상품을 식별하고 고르는 일관된 체계. 브랜드 감성과 구매 조건을 분리하지 않는다.

## 포트폴리오

- **image-index:** 짧은 소개 뒤 작업 제목·분야·이미지를 읽는 색인. 서로 다른 비율의 작업도 제목의 시작점과 탐색 리듬은 유지한다. 모바일에서 작업을 보기 전 소개가 여러 화면을 차지하지 않게 한다.
- **case-study:** 대표 작업과 역할·문제·산출물이 중심. 전체 결과→구체적인 결정→상세 이미지→다음 작업으로 이어진다. 확인되지 않은 성과 수치를 만들지 않는다.
- **typographic:** 글·리서치·전략 등 텍스트 결과물이 중심일 때. 제목·발췌·역할·연도로 탐색하며 억지 목업 사진을 만들지 않는다.

구별되는 특징: 작업 자체의 다양한 이미지와 맥락. 이미지형 작업은 클릭→전체/세부→확대·이동→이전/다음→닫기·초점 복귀까지 설계한다. 세부 동작은 [media-and-banners.md](media-and-banners.md)를 따른다.

## 전문 서비스

- **service-guide:** 제공 대상과 결과물→범위·절차·비용 조건→문의. 용역·상담을 요청하기 전에 무엇을 받는지 이해하게 한다.
- **evidence-led:** 공개 가능한 실제 자격·사례·산출물이 있을 때. 증거와 해당 설명을 가까이 두고 고객명·성과 공개 범위를 존중한다.
- **editorial:** 전문 글·문서가 강점일 때 글 목록과 대표 해설을 중심으로 한다. 읽기 폭과 관련 서비스 이동을 함께 설계한다.

구별되는 특징: 검증 가능한 전문성과 이해 가능한 서비스. 스톡 인물 사진·가짜 로고 띠·종이 장식이 근거를 대체하지 않는다.

## 문화·행사

- **poster:** 실제 포스터나 강한 조판으로 행사명·날짜·행동을 한 구도 안에 결합한다. 화면 크기와 무관하게 100vh를 강제하지 않는다. 모바일은 보조 그래픽을 줄이고 날짜·신청을 남긴다.
- **programme:** 참석할 세션 선택이 중요할 때 날짜·시간·출연진의 정렬된 일정이 중심. 첫 화면에서 행사명·기간·참가 조건과 일정 진입을 연결한다.
- **archive:** 종료 행사 기록과 사진·영상·발표 자료가 충분할 때. 참가 신청처럼 보이는 죽은 버튼 대신 기록 탐색을 제공한다.

구별되는 특징: 날짜나 프로그램의 구조와 실제 행사 이미지. ‘소개 왼쪽+중복 대형 포스터 오른쪽’을 자동 기본값으로 쓰지 않는다. [media-and-banners.md](media-and-banners.md)의 배너 규칙을 적용한다.

## 교육·커뮤니티

- **curriculum:** 대상·선수 조건·얻게 될 결과→주차별 내용→일정·신청. 확인되지 않은 취업·수익 성과를 넣지 않는다.
- **resource-library:** 자료 분류·검색·실제 미리보기 중심. 읽은 위치와 필터를 유지하고 빈 결과에서 초기화 경로를 제공한다.
- **cohort:** 실제 참여 일정과 운영 방식→회차별 활동→참여 조건. 모집 상태와 마감일이 제공되지 않았다면 임의 카운트다운을 만들지 않는다.

구별되는 특징: 무엇을 배우고 언제 어떻게 참여하는지. 추상적 혜택 카드가 실제 교육 내용을 대신하지 않게 한다.

## 고른 뒤 확인

브랜드 이름과 색만 다른 업종의 것으로 바꿔도 자연스럽다면 내용·구도를 다시 본다. 이 질문은 자동 합격 판정이 아니다. 같은 탐색 패턴이 합리적인 경우까지 억지로 다르게 만들지 않는다. 첫 화면·이어서 읽을 내용·핵심 행동이 하나의 주제로 연결되는지 직접 확인한다.
