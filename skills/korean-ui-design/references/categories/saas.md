# SaaS · 업무 과업과 정보 계층

## 목적과 구성 선택

업무 앱은 검색·상태·업무 목록을 우선하고 소개용 히어로를 자동 추가하지 않는다. SaaS 홍보 페이지를 만드는 경우에만 설명과 실제 제품 화면을 동시에 판단할 필요, 또는 제품 사용 장면을 먼저 볼 필요로 병치/장면 우선을 선택한다. 구체적인 선택은 [첫 화면 기준](../hero-composition.md)을 따른다.

업무 앱은 탐색·상태 확인·수정·완료를 우선한다. 홍보 랜딩은 제품의 사용 맥락과 도입 판단을 보여준다. 같은 서비스라도 두 화면의 정보 구조를 분리한다. 목록 중심 과업에서는 검색·분류·업무 목록을 먼저 배치한다. 진행 요약·예정 업무·차트는 별도 판단을 돕는 데이터와 과업이 있을 때 추가한다.

## 콘텐츠와 색

사용자가 좌측 메뉴와 상단 상태 카드형을 명시하면 `워크스페이스 탐색 → 제목/새 업무 → 대기·진행·완료 → 검색/상태 필터 → 업무 목록`을 구성 계약으로 기록한다. 상태 카드와 메뉴는 실제 필터에 연결하고, 숫자는 전체 업무 기준으로 수정·추가 시 갱신한다. 모바일에서는 접을 수 있는 탐색과 읽을 수 있는 상태 카드/행으로 재배치한다. 상태 카드의 명시적 요구를 진행 요약 문장·다가오는 업무를 추가하라는 의미로 확대하지 않는다. 승인된 흰 메뉴·보라색은 해당 프로젝트 조건이며 모든 SaaS의 기본색으로 일반화하지 않는다.

간결한 업무 목록이 승인된 화면은 검색·상태·담당자·기한의 비교 구성을 유지한다. 바탕은 브랜드·운영 맥락에 따라 중립 흰색이나 차분한 청회색 등을 검토하되, 공통 소개 템플릿의 크림 바탕을 그대로 상속하지 않는다. 배색을 바꾸기 위해 진행 요약·다가오는 업무·감성 문구를 추가하지 않는다. 행동색과 상태색의 역할을 분리하고 실제 업무 면의 대비를 확인한다.

사용자가 이전 승인본을 지정하면 최신 템플릿을 추정해 적용하지 말고 해당 화면의 상단바·바탕/행동색·검색과 상태 필터의 폭·행의 비교 열·모바일 재배치를 실제 자료에서 확인한다. 검색은 긴 업무명 입력에 충분한 폭을, 짧은 상태 선택은 제한된 폭을 갖게 할 수 있다. 전체 업무 수와 상태별 건수는 한 곳에 모으고 필터 결과 수는 필터가 적용됐을 때만 보여 중복 집계를 줄인다. 아이콘과 안내 묶음은 PC에서 중앙, 모바일에서는 긴 문구 첫 줄을 기준으로 정렬한다.

업무명·상태·담당자·기한 등 실제 판단에 필요한 열을 정한다. 보조 정보는 목록의 읽는 순서를 끊지 않게 배치한다. 브랜드 행동색과 대기/진행/완료/오류의 의미를 분리하고 보조 회색·상태 표식의 대비를 확인한다. 특정 보라색이나 밀도를 모든 앱에 적용하지 않는다.

## 조작과 모션

필터·저장·완료는 실제 데이터와 결과 수를 즉시 갱신한다. [상태 예제](../../assets/category-motion/index.html#saas)는 바뀐 표식의 제한된 강조를 보여준다. 행 전체나 열을 움직여 비교 축을 흔들지 않는다. 상세 진입과 상태 변경을 별도 행동으로 제공한다.

## 구현과 검토

긴 업무명·빈 결과·새 항목·저장 오류·재시도를 확인한다. 좁은 폭에서는 중요 열의 순서를 유지하며 메타데이터를 다음 줄로 옮길 수 있다. 안내의 가로 배치는 컨테이너/본문 축에 맞추고, 한 줄 중앙과 여러 줄 첫 줄 정렬을 구분한다. 기본 내부 정렬만으로 묶음 전체의 위치를 통과시키지 않는다.

[편집 결정](../editorial-decisions.md) · [자료 준비](../asset-pipeline.md) · [모바일 검토](../mobile-review.md). 선택한 기준은 [적용 확인](../applied-evidence.md)으로 최종 DOM·조작·PC/모바일 화면과 대조한다. 수치상 통과와 실제 읽기/광학 판단, 미실행을 구분한다.


## 셀렉트 간격의 일관성

선택 컨트롤이 있으면 같은 제품/비교 범위의 화살표 크기·우측 여백·문구 안전 영역을 공통 토큰으로 연결한다. native 기능과 label/검증/값 갱신은 유지한다. [셀렉트 표시 계약](../control-alignment.md#네이티브-선택-기능과-화살표-표시의-공통-계약)에 따라 실제 모바일·글자 확대·키보드와 연결 기능을 확인한다. 셀렉트가 필요 없는 화면에는 새로 추가하지 않는다.

## 표현의 무게와 완료 확인

목록·검색·상태·새 업무의 위계를 먼저 유지한다. 탐색 항목이 실제로 많을 때만 사이드바/구역 표식을 더하고, 안내·진행 요약·다가오는 업무를 화면 채우기용으로 넣지 않는다. 상태색은 업무명보다 먼저 읽히지 않게 한다.

상태/담당자 요구 계약을 상세·추가 폼별로 나누고 각 값의 저장→재열기와 추가→목록 반영을 실행한다. PC 안내 묶음의 가로 중앙과 모바일/확대 첫 줄은 별도 검사다. 고정 margin-top 보정보다 실제 행간을 따르는 아이콘 상자를 사용한다. [완료 게이트](../delivery-gates.md)를 따른다.

## 페이지 관계의 구현 확인

단순 업무 목록이 주 과업이면 제목·도구막대·하단에 같은 기본 집계를 반복하지 않는다. 필터 결과나 전체 대비 표시 수가 필요한 상태만 남긴다. 완료·추가·검색·초기화 후 집계는 실제 상태와 일치해야 한다. 기존의 간결한 목록을 홍보용 요약 패널로 대체하지 않는다.

공통 구현과 검토는 [페이지 관계 기준](../page-relationships.md)을 따른다.

## 표현 변형과 정보 묶음의 최종 검토

기능과 정보 밀도가 승인된 업무 화면은 다른 카테고리의 소개/장면 개선 때문에 다시 꾸미지 않는다. 유지 범위를 지정하고 변경을 격리한다.
